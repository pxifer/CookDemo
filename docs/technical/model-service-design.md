## 1. 结论、需求依据与决定边界

本设计继承 [PRD](../PRD.md)、[需求基线](requirements-baseline.md)、[数据知识架构](data-knowledge-design.md)、[检索架构](rag-design.md)和[技术决策日志](decision-log.md)。不修改 PRD，不购买服务，不编写正式业务代码，不将研究结论写成已通过的功能验收。

已确认方向：

1. 图片以视觉大模型识别候选，标准食材库归一，再由用户核对；专用检测或混合视觉在有样本依据后再评估。
2. 以已核验境内处理的托管 API 为主，首版一家主供应商；通过统一适配接口保留替换能力，备用供应商须通过同等测试才能启用。
3. 优先平台免费模型；限量免费额度同时设置用户及平台总上限；无合适免费能力时由用户主动自带 Key，不自动使用平台付费余额。
4. 免费服务繁忙时短时排队；超时提供重试、自带 Key 或人工录入，不以固定示例冒充识别成功。
5. 登录用户可主动将 Key 加密保存到账户，支持删除和更换；游客可以临时使用，登录后才可选择保存。
6. 自带 Key 仅支持通过能力、境内处理及条款核验的供应商名单，不开放任意兼容地址。
7. 平台免费请求最多自动补救一次；用户 Key 请求由用户点击重试。认证失败、额度耗尽和数据准入失败不自动重试。
8. 免费 Embedding／Reranking 服务不满足正式使用条件时，先用结构化与关键词路径，保留阶段 2 实验，不为此默认增加平台算力支出。

平台免费不表示供应商无限量、永久零价或固定 SLA；也不表示网站托管、密钥管理、数据库和存储没有成本。费用策略是本阶段新增约束，未取消真实识别、有限菜谱集合、单菜变体、账户同步和受审核条件控制的健康能力。

模型只负责识别、提取或相关性任务。不能确认疾病、审批健康适用、生成集合外新菜、自动移除限制、接受补买或保存默认；营养继续按标准配方计算，不交给生成模型补数。

## 2. 识别路线与部署方式比较

### 2.1 图片识别

| 方案 | 能力与响应路径 | 成本与维护 | 适用条件及决定 |
| --- | --- | --- | --- |
| 视觉大模型＋标准库＋用户核对 | 同时处理散装食材、包装文字和补充说明；单模型调用链较短，实际延迟待测 | 外部 API 或自部署运行成本；可能漏认、误认，需要字段及语义检查 | **采用为首轮路线**，先建立真实照片基线 |
| 专用检测／分类模型 | 固定类别、目标定位可针对性优化，可能降低适配场景的计算量 | 需要标注、类别维护及上线测试；不直接完成混合中文理解 | 类别与样本成熟、存在明确漏认问题后评估 |
| 专用视觉＋视觉大模型 | 检测、OCR 与语义互补 | 多模型时延、调用、错误合并及运维增加；更复杂不等于更准确 | 首版不预先建设，须证明收益 |

视觉输出为待确认候选。遮挡、切碎或包装内部成分不能臆测；不能通过照片证明不含过敏原、食物安全或实际克重。可见数量与标签重量也须保留出处及待确认状态，不自动证明可用库存充足。

### 2.2 单供应商、多供应商与自部署

| 方案 | 收益 | 代价、替换风险与决定 |
| --- | --- | --- |
| 一家托管主供应商＋统一适配 | 减少初期运维；统一任务接口便于未来替换 | 仍依赖一家可用性；免费和故障出口需完整。**采用**，并不提前确定具体型号已经获准上线 |
| 两家托管服务同时可用 | 经验证后可故障切换，减少单家依赖 | 双份能力、数据条款、格式和限流测试；重复请求可能增加等待和费用。暂不要求双活 |
| 开源模型境内自部署 | 掌握模型版本和计算链路，无外部按次 API 账单 | 承担设备或云算力、内存、扩容及维护成本；响应时间取决于硬件和负载。保留研究，不作为免费不足时的默认投入 |

自部署视觉可研究 Apache-2.0 许可的 [Qwen3-VL-2B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct)及 [4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct)。开放权重许可不等于托管 API 使用许可，也不等于零运行成本；未测硬件前不承诺显存、速度或吞吐。

| 任务 | 模型职责 | 不交给模型的职责 | 当前候选与启用状态 |
| --- | --- | --- | --- |

| 营养与健康 | 模型输出不能成为营养事实或专业审核凭据 | 标准投料计算、已审风险规则、证据定位及支持状态由数据与规则模块完成 | 继承 D1 与 D2-05 |

| Reranking | 对已召回候选计算相关性 | 不找回漏召回，不批准健康结果 | 保留 bge-reranker-v2-m3 对照；首版默认不依赖它 |

按任务分配模型，不要求所有任务同一型号，也不要求每个任务都使用不同供应商。混合文字输入优先一次提取多个类别，避免每个字段分别调用；结构化清单和人工修改不重复送模型。换菜、翻页、人数及口味修改走规则和检索，不重新识别图片。

图片与已有文字分别进入确认流程并按 PRD 合并；不为统一格式默认再调用一个文字模型重写视觉输出。确需语义补救时必须计入一次自动补救预算。

## 5. 统一网关与路由设计

网关是后端逻辑边界，首版可在同一后端进程内实现，不要求先拆独立微服务或引入复杂代理平台。

| 逻辑组件 | 职责 |
| --- | --- |
| 任务接口 | 区分图片提取、文字提取、Embedding 和 Reranking；前端不直接决定任意模型 ID、URL 或 SDK 参数 |
| 供应商与型号登记 | 保存具体型号、能力、区域、版本、价格类型、免费到期／配额、条款与数据核验状态 |
| 凭证管理 | 解析平台凭证或当前用户凭证引用，检查所属权、有效状态和允许任务 |
| 配额与队列 | 用户／游客限流、平台总额度、账户并发、队列及调用预算，分开核算免费和用户调用 |
| 供应商适配器 | 按型号能力映射输入、输出格式、思考与图片参数；关闭与网关冲突的 SDK 隐式重试 |
| 输出校验 | JSON／字段、来源、语义和状态校验；把可核对候选交给确认流程 |
| 运行记录 | 记录版本、耗时、用量、错误和路由路径，排除密钥及原始敏感内容 |

### 5.1 最小内部输入与输出

本阶段定义逻辑契约，不实现或冻结对外 API。

| 接口内容 | 必须表达的语义 |
| --- | --- |
| 请求身份 | 请求标识、用户或游客会话、所属权及任务类型 |
| 输入 | 当前文字或受控图片引用、必要的已确认上下文；历史健康资料不默认附送 |
| 执行策略 | 当前选择平台免费或自带 Key、凭证引用、允许型号、总时限、剩余尝试次数及输出版本；由服务端校验 |
| 结果 | 已校验／部分可核对／需处理／失败，不把模型返回成功等同业务通过 |
| 提取项 | 原始名称、候选标准标识、类别、可选用量与单位、原文／图片来源定位、疑似及待确认状态 |
| 运行信息 | 供应商与实际模型、适配器／提示词／Schema 版本、用量、尝试次数和结束原因 |
| 错误 | 认证、限流、模型拥挤、额度耗尽、超时、截断、解析失败、数据不准入等稳定类型，以及是否可由用户重试 |

原始 Key 不出现在模型请求正文或任务日志中，仅由网关用于供应商鉴权。模型不得生成凭证引用、供应商地址或执行工具指令。

### 5.2 路由顺序与费用边界

1. 检查当前任务与数据类型是否获准；未核验敏感处理条件的型号不接收真实敏感请求。
2. 检查用户主动选择的费用模式。保存 Key 不等于已选择用它付费，平台免费失败不静默切换到用户 Key。
3. 平台路线只进入具体免费白名单，核实价格类型、额度期限及平台／用户余额后预留本次预算；排队不占供应商并发槽。
4. 免费可用时调用。备用仅在完成同等核验且符合当前费用策略后使用，不因主服务故障临时接入新供应商。
5. 无免费能力或免费等待超限时，返回用户可选出口；用户主动选自带 Key 才发起该路线。
6. 自带 Key 检查用户、供应商、任务和模型权限，仅用于该用户请求，不进入平台共享池。

平台不自动付费是明确路由政策。若供应商缺少可核验的免费权限隔离、用完即停或等效硬限制，仅靠本地价格表不能完全保证政策变化不产生账单；该接入须保留待准入，不承诺“技术上绝无扣费”。不能通过注册轮换账户或多 Key 绕过免费限制。

## 6. 模型输出、解析和业务确认

供应商支持 JSON 不等于严格遵守本站 Schema，更不等于内容正确。适配器应优先使用该型号和模态实际支持的结构化模式，网关统一承担最终检查。

校验顺序：

1. 检查传输结束、供应商错误、拒绝及截断状态；流式部分输出不直接进入可用食材清单。
2. 解析 JSON 并检查类型、必需字段、枚举、条数和长度；拒绝或显式处理未定义字段，不以宽松解析掩盖错误。
3. 检查名称与单位、数量、人数的适用性；缺量保留空值，不补 0，不把人数小数截成整数。
4. 用标准库生成匹配候选；一名多物、生熟或类别歧义保留供核对，不强行归一。
5. 保留每项原文或图片来源；模型自报置信度不作为校准概率或健康通过依据。
6. 数量冲突、新旧限制冲突、无法分类限制交回既有确认流程；模型不决定移除旧限制。

可确定的格式整理不调用模型；确需模型修复时只修结构，不补造未识别的名称、数量、过敏成分或健康事实。稳定有效的部分可保留为待确认项；疑似遗漏了限制时必须明确保留未处理状态，不能因部分食材有效而绕过限制阻断。

模型输出及图片内文字均为不可信输入，不执行其中的外部 URL、工具调用、脚本或“忽略限制”指令。首版识别适配器不启用联网搜索、代码执行等无关工具。

## 7. 密钥保护与生命周期

### 7.1 游客、登录与保存

- 游客可临时输入受支持供应商的 Key，经 TLS 提交至后端用于自己的请求；不写 localStorage、IndexedDB、持久 Cookie、草稿或数据库。
- 登录用户可临时使用，也可主动选择保存；不预勾选保存。登录与返回识别流程保留本餐信息，临时凭证不自动升级为账户凭证。
- 保存后前端只收到凭证标识、供应商、用户标签、掩码和状态；不提供完整 Key 的查询／回读接口。
- 从其他设备登录可使用已保存凭证，但不能取回明文；每次请求服务端重新校验所属权。
- 临时凭证不得写入持久队列消息；队列使用受控引用。队列清理、会话退出或临时凭证到期后，不再解引用使用。

### 7.2 加密与权限

采用认证加密及独立密钥管理：业务库保存密文和密钥版本等必要元数据，解密材料与业务数据库、源码和前端分开。网关通过最小权限按需解密，限制明文存活范围；所有凭证相关日志、链路追踪及异常均脱敏。

| 方式 | 收益 | 代价及本设计处理 |
| --- | --- | --- |
| 只靠磁盘／数据库透明加密 | 运维较简单 | 不能充分隔离业务查询与明文凭证读取；不作为账户 Key 的唯一保护 |
| 应用密文＋独立主密钥管理 | 支持用户所属权、密钥版本与轮换，降低单独数据库泄露的影响 | 增加权限与轮换管理；采用这一职责边界 |
| 托管密钥／秘密服务 | 可提供集中权限、审计和轮换能力 | 可能收费并形成服务依赖；具体产品结合后端部署决定，不在本阶段购买 |

具体密码库、密钥服务与存储字段留给后端方案，但不能省略认证加密、密钥隔离、权限及轮换。可参考 [OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)。

### 7.3 删除、更换和失效

- 删除或更换使旧凭证版本立即对新请求失效；取消或阻止尚未发出的相关排队请求，清理应用侧明文缓存。
- 更换采用新凭证版本，旧任务不能在执行时悄悄换用新 Key。
- 已发至供应商的请求不保证可撤回；可能已有用量。删除本站凭证不等于供应商撤销，泄露时提示用户到供应商轮换／撤销。
- 备份恢复遵守删除／失效记录，不复活已删除凭证；备份留存、恢复权限及物理清除时限在数据生命周期专题收口。
- 单项凭证删除的语义已确定；不据此替用户决定完整账户注销范围。
- 凭证有效性检查优先使用供应商提供的非生成鉴权能力；如只能发起可能计费的测试，须由用户明确触发，不在保存时隐式执行。

## 8. 排队、重试、降级与版本

### 8.1 配额和短时队列

平台同时管理用户／游客调用频率、模型请求量、Token 额度、供应商账户并发和平台总免费余额。有限额度要为已接收的在途请求预留；不能只按调用次数判断是否还有 Token，也不能把控制台延迟统计当实时余额。

游客标识和 IP 等只能辅助公平限流，不视为可靠身份；平台总上限必须独立存在。认证、隐私和日志限制同样适用于限流数据。配额不足尽量在上传或发起模型前反馈；重复点击合并为同一任务，用户可以取消排队。

短队列避免无限等待和无界积压。用户、队列容量、等待时限、输出上限和临时凭证有效期均为上线配置必填项，在实际供应商配额和样本测量后确定；当前不虚填秒数、每日次数或并发保证。排队与执行共用请求总时限，补救不重置总时钟。

### 8.2 尝试预算

| 情形 | 处理 |
| --- | --- |
| 平台免费请求的可恢复网络／供应商故障或格式失败 | 原始调用后最多一次自动补救；重发、格式修复和已获准免费备用共用预算，合计最多两次模型尝试 |
| 用户自带 Key 的任何模型失败 | 不自动重发或调用修复模型，提示可能已产生用量，由用户点击重试 |
| 认证、权限、参数、额度耗尽、数据不准入或内容拒绝 | 不自动重试；返回相应处理路径，不能通过换模型绕过 |
| 模型拥挤／账户限速 | 区分供应商错误，尊重其重试提示；在总时限及预算内处理，不能无限轮询 |

免费重试也会占容量和等待预算；自动补救只允许仍获准且仍免费的路线。应用幂等标识用于避免重复点击，并不意味着供应商保证超时重发只执行一次。

智谱[错误码](https://docs.bigmodel.cn/cn/faq/api-code)区分账户限速 1302、模型拥挤 1305 和额度上限 1308，不能把所有 HTTP 429 都当成同一种可恢复错误。

### 8.3 降级

图片或文字识别失败时保留原输入和已确认部分，支持修改、重试、自带 Key 或人工补录；不使用固定示例伪装成功。免费不可用不自动切收费，也不自动消耗已保存的用户 Key。

没有合格免费 Embedding／Reranking 时使用结构化与关键词路径，明确暂不启用语义增强；既有图片／文字真实识别需求继续保留。向量或重排故障继承 D2 降级；规则无法核验仍停止依赖它的推荐，不能以模型生成替代。

### 8.4 版本与替换

记录供应商、实际型号、接入区域、能力声明、价格／条款核查时间、模型快照或别名、提示词、输出 Schema、适配器和评测版本。可锁定快照时优先固定；别名或供应商自动升级时须检测与回归，不宣传版本永久不变。

图片／文字备用须通过同样样本、输出、地域和费用验证；用户 Key 不会跨供应商复制。Embedding 模型或维度变化按 D2-15 重建独立索引，不能用另一家模型临时编码查询后检索旧向量空间；不用个人 Key 为全站建公共索引。

## 9. 敏感数据、缓存与日志

真实照片及健康／过敏资料仅通过已核验境内处理的链路。核验具体供应商、型号、接入与推理范围、第三方处理、调用日志、保留、训练使用及删除例外；自带 Key 不豁免。

| 数据／行为 | 边界 |
| --- | --- |
| 图片 | 校验格式和实际内容，按需缩放并处理方向、去除非必要 EXIF；不能为省 Token 而静默丢掉关键细节。私有受控传输，避免公开图床和长期外链 |
| 混合文字 | 仅发送本次提取必要内容；不默认附带账户身份、全部历史资料及收藏。包含疾病／过敏表达时仍按敏感请求准入 |
| 结构化确认 | 原文与用户确认状态按 PRD 保留，服务端处理不自动变为本餐云同步或长期保存 |
| 缓存 | 继承 D2-17：公共版本化数据可缓存，个人图片、查询向量及最终结果不持久进入公共缓存或索引 |
| 日志 | 记录随机请求标识、型号／版本、耗时、用量、错误、排队和补救次数，不记录 Key、原图、原始输入或可还原个人健康限制的内容 |
| 诊断 | 优先人工构造及经处理样本；真实敏感诊断另行明确授权、权限和保留，不因排查需要自动开启 |

智谱[隐私政策](https://docs.bigmodel.cn/cn/terms/privacy-policy)有境内存储、目前不跨境及匿名化使用等说明，但不能据此宣称 API 零留存或绝不用于任何训练；具体推理链路、原图及日志时限仍须核实。其协议对医疗等用途有限制，候选模型只用于输入提取，不承担疾病判断；含健康文本的具体使用边界也纳入准入核查。

阿里云[北京地域说明](https://help.aliyun.com/zh/model-studio/beijing-access-information)区分“中国内地”与可涉及其他地域的“中国弹性区”，并说明 2026-10-13 前后上线模型的默认范围差异。北京域名、品牌属地和用户提供的 Key 均不能独立证明全链路境内；按具体版本核验。

未落实短期图片和供应商留存边界前，可用公共或人工构造材料继续设计和测试；不将准入未知直接当作通过，也不因此取消正式真实识别范围。

## 10. 低成本策略、评估与验收场景

能力分级按调用成本而非取消产品要求：普通规则推荐和详情无需生成调用；已准入免费识别限量提供；用户主动选择自带 Key 才使用其额度或余额。首版不引入额外付费会员方案。

成本控制优先减少不必要调用、限制输入／输出、避免重复提交、复用公共版本化表示及关闭未证明收益的重排；不以缓存旧限制或猜测模型输出来省费。不启用无关搜索、Agent 工具或后台生成。

验证采用相同公共照片／标注文本对照候选，覆盖散装、包装、遮挡、相似食材、中文别名、否定、混合数量及限制冲突。分别记录名称／数量／分类准确性、漏项与误报、Schema 合格率、人工修正量、队列和完整结果 P50／P95、错误和实际用量。免费与收费参考分开报告，不由官方榜单替代项目样本。

必须验证的行为：

1. 免费视觉／文本仅生成候选；照片无法确定重量时保持未知，原有限制未被覆盖。
2. JSON 合法但类型、人数或单位非法时不能进入已确认状态；截断内容不能伪装完整结果。
3. 一次免费格式修复后再失败不继续调用；网络重发与格式修复不各获一次预算；SDK 不叠加重试。
4. 用户 Key 超时后不自动补救；手动重试前能理解可能已产生用量。
5. 免费配额预留与并发控制防止多人透支；用完或改价后不自动切平台收费、FlashX／Pro 或用户 Key。
6. 短队列取消、超时、限速和额度耗尽均有不同状态；已确认输入及人工录入出口保留。
7. 游客 Key 不落持久存储；登录不自动保存；账户保存明确主动，其他用户不能引用或回读。
8. 删除／更换旧 Key 后排队任务不能继续使用；恢复备份不复活凭证，删除本站不冒充撤销供应商。
9. 请求携带任意兼容地址、未准入模型或其他用户凭证引用时拒绝；不能通过重定向绕开名单。
10. 模型不可用或版本变化不生成目录外菜谱，不放宽过敏／忌口，不用免费模型替代健康规则。
11. Embedding 备用不混用不同向量空间；没有合格免费增强时结构化及关键词推荐仍可用。
12. 日志、错误、链路追踪与备份不意外暴露明文 Key 或原始健康输入。

本阶段只完成架构、官方资料核查和验证计划，未注册账号、购买服务、实际调用模型、测量吞吐或执行上述未来功能验收。
