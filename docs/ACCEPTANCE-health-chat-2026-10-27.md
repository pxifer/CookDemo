# 登录后个人Key健康AI对话

日期：2026-10-27，Asia/Shanghai。基线`485abd6`；用户要求开放健康模式、登录后填API、开启后显示AI对话框。D19-04记录本轮授权，覆盖原先仅显示未开放说明的入口。

## 已完成与使用

点击“健康模式”→登录/注册→填写DeepSeek API Key→“开启健康模式”。已登录用户直接填写；疾病名称选填。工作台推荐区顶部出现可收起的聊天框，开启时自动定位并聚焦该区域，手机无需越过长食材区寻找。

支持多轮对话、Enter发送/Shift+Enter换行、取消并恢复问题、清空对话、换Key和独立错误反馈。Key使用密码输入框，只留当前页内存，刷新/离开页面/关闭模式/退出/换账号清除；不默认保存到浏览器、账户或数据库。填写、开启和刷新不验证Key或调用模型，只有用户发送消息使用自己的DeepSeek额度。

AI回复纯文本显示，疾病与对话会发送给固定DeepSeek接口；不自动发送图片、完整本餐原文或账户档案。没有接入本站RAG的提示持续可见。菜谱生成与聊天分开，仍执行原食品级过敏/忌口、库存和补买规则，`conversation_only`说明未按疾病RAG筛选，不用模型聊天冒充规则结论。

## 接口与边界

- `POST /api/v1/health/chat`，真实账户+同源CSRF，UUID操作、个人Key、交替的user/assistant消息及疾病名称；禁止客户端system消息、任意URL/型号/工具。服务端固定DeepSeek `deepseek-flash`。
- 17秒应用截止、单次输出1600token/64KiB、15条/16000字符上下文、当前问题最多2000字符；超时/取消/错误不自动重发。Key无效、余额不足、供应商限流/故障、空/截断回复分别反馈，问题保留。
- 新增`deploy/db/health-chat.sql`：`shiwei_ai_chat_operations`和`shiwei_ai_chat_claim`，真实认证JWT及有效会话，账号行锁串行化，只认领一次；每账号滚动每分钟6次、24小时120次。只存身份、操作ID、HMAC指纹、时间，不保存Key/疾病/对话正文。客户端不可更新/删除记录，不能退还或重新武装操作。运行元数据需后续管理员按保留策略清理，不宣称已自动定时删除。
- 本机测试身份的内存去重仅用于显式loopback测试；公网使用上述PG RPC，不用进程Map冒充共享费用账本。没有平台Key、平台模型消费或自动充值。
- 登录回跳正确返回健康设置；刷新不因登录URL遗留而误开账户弹层。取消按钮阻止默认提交并同步恢复问题，避免状态切换导致误重发。
