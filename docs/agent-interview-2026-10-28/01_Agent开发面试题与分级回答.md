# Agent开发面试题与分级回答

面向 Agent 应用开发与 AI 后端岗位的复习手册

资料核查日期 2026年10月28日

这份手册帮助你回答三个核心问题：系统为何这样设计，失败时怎样定位，怎样证明改进有效。复习重点是项目事实、RAG 全链路、Agent 执行可靠性与评测。模型训练岗还需另补训练数学、分布式训练与论文复现，不能仅靠本手册覆盖。

优先级是结合参考题、公开面经和拾味项目风险作出的准备建议，不是全行业题目出现概率。文中口述回答是可改写的答题框架；涉及“我做过”的内容必须以自己的代码、记录和职责为依据。第二份文档提供拾味当前能够证实的经历，第三份提供仍待实施的优化。

## 一 复习顺序与答题方法

| 级别 | 准备要求 | 主要内容 | 练习时间建议 |
| --- | --- | --- | --- |
| P0 必须掌握 | 能画链路 能讲输入输出 能接两轮追问 | 项目贡献 RAG 数据与检索 Agent边界 工具校验 评测 幻觉 幂等 压缩 | 约60% |
| P1 重要加分 | 能说明选型条件 代价 失败处理 | 向量索引 中文检索 持久化 多Agent MCP 性能 存储 安全 | 约30% |
| P2 按岗位扩展 | 能解释原理 知道何时需要 | GraphRAG 微调 本地推理 Harness源码 模型基础 | 约10% |

回答顺序建议为：结论和适用场景 → 自己的实现 → 一个具体失败例子 → 验证方法 → 仍有的限制。普通概念题控制在45至90秒，项目难点展开到2至3分钟。面试官追问参数时，说明参数来自什么实验，而不是把某篇教程的默认值说成最优值。

公开原帖里可以核对到上下文 token 计数、压缩后验证、Skills 加载、单多 Agent 取舍等追问。[字节Agent开发日常实习一面](https://api-cdn.nowcoder.com/feed/main/detail/d2cf5165d1184b59879eff5793b7b453?sourceSSR=subject)。另有原帖关注切块、混合召回与架构选择。[集团信息系统一面](https://www.nowcoder.com/feed/main/detail/00e3488329c041c5a5a357c14ce138b4?sourceSSR=dynamic)。这些是候选人自述，只用于提炼问题，技术答案以官方文档和论文为准；不据此认定某公司的统一考纲。

### Q01 P0 请介绍一个你深度参与的Agent项目

**口述回答**：先用一句话说明用户、痛点和交付。接着画用户输入、状态管理、检索、模型、工具、校验、输出的链路。挑自己实际负责的两个模块，讲清设计与失败案例。最后给出可复现指标，并主动说明哪些已上线、哪些只在本地、哪些仍是方案。

**追问**：为什么需要 Agent？你独立完成什么？没有你会缺哪一块？最难问题的复现输入和对应代码是什么？

**准备材料**：一张架构图、一条完整请求、一段关键代码、一份评测报告和一例失败。拾味不能把本地研究库包装成已上线的自主医疗 Agent。

### Q02 P0 你的项目效果怎么样

**口述回答**：业务效果、模型质量和工程质量分别说。业务看任务完成率与使用反馈；检索看相关证据覆盖和排序；生成看事实支持与引用；工程看错误率、P95、取消和重复执行。所有数字说明数据集、分母、版本、硬件和时间范围。只有编辑回归时就如实说编辑回归，不用“准确率100%”概括整套系统。

**追问**：换一批题还有效吗？是谁标注？是否调过测试集？有没有和不用 RAG 的方案对照？

### Q03 P0 你个人负责什么 团队如何分工

**口述回答**：按模块交代输入、输出、接口和验收责任，区分设计、实现、测试、部署。个人项目说明自己做的决策以及 AI 辅助生成的部分，能解释合并后的实现。不要虚构企业流量、团队人数或专业审核。

**追问**：一段关键代码为什么这样写？设计被否决过吗？你如何验证 AI 生成的实现？

### Q04 P0 为什么需要RAG 直接用长上下文或微调行不行

**口述回答**：资料经常变化、需要引用和权限控制时优先检索；少量短资料可以直接读全文；稳定行为和输出风格可用微调。检索、长上下文和微调可以组合。先测全文基线，确认延迟、成本或定位能力确有问题再建索引；RAG 也有漏召回、解析错误和过期证据风险。[RAG论文](https://arxiv.org/abs/2005.11401)

**追问**：只有7份资料为何还建库？回答：价值还包括版本、条件、撤回、引用与可执行规则治理；不代表现在必须上向量检索。

### Q05 P0 Agent Workflow和普通聊天有什么区别

**口述回答**：聊天主要生成内容；Workflow 用程序预先定义执行路径；自主 Agent 在运行中根据反馈选择下一步工具和步骤。实际系统可以让外层流程固定、内层检索有限自主。选择依据是任务不确定性、风险、成本和可验证性，不能把每次 API 调用都称为自主 Agent。[架构区分](https://www.anthropic.com/research/building-effective-agents)

**追问**：拾味是什么？当前主要是确定性推荐流程和模型建议功能，目标是在受控检索中增加 Agent 能力。

### Q06 P0 项目中最大的技术难点怎么讲

**口述回答**：给出可复现的触发条件和错误后果，讲最初方案、定位证据、修改和验证。比如“把鲜香菇与干香菇归为同一实体会混用成分依据”，应展示实体形态拆分和冲突保留；不要只说“幻觉很严重，所以用了 RAG”。

**追问**：其他方案为何不行？修复有副作用吗？是否覆盖跨请求、取消和版本切换？

## 二 P0级RAG全链路

### Q07 P0 从零搭建RAG的完整流程是什么

**口述回答**：离线先定义任务和评测样本，再登记来源、解析清洗、保留定位、实体对齐、结构切块、关键词索引和可选向量索引，生成版本清单。在线先认证和理解问题，再检索、融合、重排、构造有预算的上下文，生成带证据的结果，最后验证引用、适用条件和输出。更新、撤回、监控贯穿两条链路。[流程综述](https://arxiv.org/abs/2404.10981)

**追问**：哪个环节最先优化？通过失败分层判断，不能固定回答“重排永远收益最高”。

### Q08 P0 PDF Word HTML等不同来源怎么处理

**口述回答**：按格式提取结构，保留标题、段落、表格、页码和脚注。电子 PDF 和扫描 PDF 分流；OCR 结果中的数字、负号、单位及列对齐要抽查。去页眉页脚和重复版本，但不删除有语义的否定和限制。原始文件 hash、解析器版本、定位和清洗后文本一起保存。

**追问**：双栏论文串行、表头跨页、扫描表格怎么办？先做结构复原和人工核对，不能让模型凭常识补丢失字段。

### Q09 P0 Chunk长度怎么确定 为什么不是固定512

**口述回答**：先确定最小可独立理解的证据单元，再按模型 tokenizer 计算长度。块太大容易带入噪声，太小容易失去条件；用结构切块和父子块平衡。对照不同长度、边界和重叠，观察证据覆盖、上下文噪声、延迟及 token；512只是候选参数，不是通用答案。

**追问**：中文字符等于 token 吗？不等于；不同模型 tokenizer 不同。Embedding 支持长输入也不意味着应该把所有文档切成长块。

### Q10 P0 Markdown没有标题怎么切

**口述回答**：先按空行、列表、句子边界组织，再用最大 token 限制递归拆分；超长自然段才比较语义边界。代码块、列表项和表格保持原子结构。若用模型补标题，把它存为检索辅助字段，引用仍指原文，不能让生成标题成为证据事实。

**追问**：句子相似度下降就一定能断开吗？不能，否定、例外和跨句指代也要检查；语义切分要对照简单基线。

### Q11 P0 表格怎么切 条件和例外怎么保留

**口述回答**：按逻辑行或记录组切，给每块带上表头、单位、基准、脚注和来源定位。结论与必要限定共同构成证据单元，无法放在同块时建立显式关联，并在回取上下文时一起取。测试要包含“除外”“不适用”“每100克”和跨页脚注，防止方向或基准丢失。

**追问**：表格超过模型上限？拆记录组并重复受控表头，不能在数值和单位之间截断，也不能只保留结论列。

### Q12 P0 Overlap多大合适

**口述回答**：重叠用于保护边界附近语义，代价是重复索引、检索结果拥挤和上下文浪费。优先结构边界；必要时对自然段边界少量重叠。按原文 span 和父节去重，并比较零重叠与少量重叠。父子回取能减少对大面积重叠的依赖。

**追问**：20%是否合理？要说明 token 长度、文档类型和实测收益，不能只报百分比。

### Q13 P0 父子块为什么有用

**口述回答**：child 较短便于精确定位，parent 提供定义、例外和上下文。召回 child 后按需回取 parent，并在预算内保留相关段落。多个 child 属于同一 parent 时去重。父块不是必须全部塞入，原文与辅助摘要分开保存。

**追问**：parent太大怎么办？抽取命中的证据段和相邻限定，仍保留原文定位；不能用一段未经校验的摘要替换全部证据。

### Q14 P0 Embedding模型怎么选

**口述回答**：先看语言、领域、query 与文档长度、许可证、资源和部署边界，再用本项目冻结集比较 Recall、nDCG、延迟、内存和建库成本。BGE-M3 与 Qwen3-Embedding-0.6B 可以做中文对照，但榜单高不等于本项目最好。文档与查询必须使用兼容的同一编码协议。[BGE模型卡](https://huggingface.co/BAAI/bge-m3)、[Qwen模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)

**追问**：为什么选1024维？是候选模型输出规格和存储实验起点；降维只有在模型支持并通过评测后使用。

### Q15 P0 向量化时有哪些容易忽略的细节

**口述回答**：固定模型 revision、tokenizer、query 指令、池化方式、归一化、截断上限和输出维度。批量任务按内容 hash 去重，失败批次可恢复，检查维度、非有限数、空文本和意外截断。相同维度不代表向量空间兼容；换模型必须重建相应索引。

**追问**：离线有文档向量就能在线检索吗？还需要在线用同一模型生成 query 向量，并验证运行环境能承载。

### Q16 P0 关键词和向量为什么要混合

**口述回答**：关键词擅长专名、型号、精确短语；向量擅长同义改写和语义近似。中文专名、疾病分型、否定句可能对两路都困难，因此还要有结构化实体过滤。混合用于互补，是否值得加入要看困难题增益和成本。[混合检索动机](https://www.anthropic.com/engineering/contextual-retrieval)

**追问**：向量高相似就是正确吗？仅代表相关，不代表结论方向、适用人群或事实可信。

### Q17 P0 BM25是什么 PostgreSQL全文检索就是BM25吗

**口述回答**：BM25结合词频饱和、逆文档频率和长度归一化进行词项相关性排名。PostgreSQL 的 `ts_rank`、`ts_rank_cd` 有自己的排名方法，不能直接叫 BM25。中文还需明确分词、词典和索引配置；只建 GIN 不会自动获得合适的中文召回。[PG全文搜索](https://www.postgresql.org/docs/17/textsearch-controls.html)

**追问**：现有代码用的是什么？拾味目前是应用内实体与关键词加分，数据库 GIN 是准备结构，还没有 SQL 全文或 BM25 性能结果。

### Q18 P0 多路召回怎么融合

**口述回答**：先按稳定 chunk ID 去重，再用 RRF 等基于排名的方法，避免直接相加量纲不同的关键词分和余弦分。公式可写为 `score(d)=Σ w_i/(k0+rank_i(d))`，未出现的通道贡献为0。`k0`、通道权重和各路候选量用开发集调，再固定到测试集。规则必需证据单独保留，不参与被 top-k 挤出。

**追问**：两个通道来自相同文本会被重复奖励吗？融合对象按chunk去重，每通道只计一次；同源重复文档还要做来源归并。

### Q19 P0 Reranker和Embedding有什么区别

**口述回答**：Embedding 可以预计算文档表示，适合大范围候选发现；cross-encoder 把问题和候选一起编码，细致判断相关性，适合较小候选集。重排只能重排已有候选，不能找回根本没召回的证据。加入后要比较质量收益、截断、P95和资源。[重排模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)

**追问**：sigmoid后0.9是不是90%正确率？不是，未经校准的相关性分数不能当事实概率或安全概率。

### Q20 P0 Query改写 多轮指代和HyDE怎么用

**口述回答**：先把“这个”“上次那个”与已确认会话实体绑定，无法确定就澄清。改写只补检索表达，保留原问、否定和硬限制，可同时检索原问与改写。HyDE 用假设文本帮助召回，但生成内容不能作为事实或引用，医疗场景尤其要防止把假设答案写回知识库。

**追问**：改写把“不吃牛奶”改成“牛奶推荐”怎么办？对实体、否定和限制做结构比对，不一致就回原问或询问。

### Q21 P0 召回很多无关内容怎么办

**口述回答**：先看是切片主题混杂、query 歧义还是过宽过滤。然后依次尝试实体约束、标题权重、候选去重、重排和父节局部回取。压缩时保留支持、反对和限制证据，不能只留下容易生成肯定答案的片段。最终上下文按预算选内容，不等于简单增加 top-k。

**追问**：是否可以让LLM挑“最相关”后删原文？可作为候选筛选，但关键限定与引用必须程序复查。

### Q22 P0 检索不到怎么办 怎样拒答

**口述回答**：区分知识未覆盖、解析或实体失败、候选截断、检索故障和证据冲突。无证据时说明缺哪部分，可澄清、返回已知部分或明确转普通模式。技术故障不能包装成“没有相关知识”；没有命中也不能证明某食材安全。

**追问**：阈值设多少？按无答案题和有答案题的误接收、误拒绝曲线校准，不把0.8设成通用门槛。

### Q23 P0 RAG回答错了怎么定位

**口述回答**：按链路检查：原文是否有答案 → 解析定位正确吗 → 切片是否保留条件 → 正确实体和证据进入各路候选了吗 → 融合重排是否删掉 → 上下文是否包含 → 模型是否读对 → 输出校验是否漏过。用“金标准证据直接给模型”和“固定生成器只换检索器”两个对照分离检索与生成错误。

**追问**：反复改 prompt 没效果？先看证据链，源头缺失或条件错配不是措辞优化能解决的。

### Q24 P0 如何减少幻觉和伪造引用

**口述回答**：模型只可引用请求证据包内的 ID；服务端校验 ID、版本、定位和支持关系。把答案拆成事实陈述，检查是否有对应证据；证据不能支持时删改或标明不足。模型生成 URL 不直接展示。结构合法只是第一层，不能代替事实核验。

**追问**：有引用是否说明回答正确？引用可能存在但不支持结论，需要核对句意、人群、剂量和时间。

## 三 P0级Agent设计与执行

### Q25 P0 ReAct与Plan Execute Replan如何选

**口述回答**：ReAct 根据观察交替决定动作，适合下一步依赖即时反馈的探索；Plan Execute 先建立步骤与依赖，适合较长且可拆解任务，执行后按失败或新条件重新规划。前者易循环和成本膨胀，后者易过早计划错误。项目可以外层固定状态机，内部允许少量检索改写。[ReAct论文](https://arxiv.org/abs/2210.03629)

**追问**：如何确认完成？用明确的产物、状态与验收条件，不能根据模型说“完成了”判断。

### Q26 P0 Agent Loop和Harness分别负责什么

**口述回答**：Loop 是读取状态、构造上下文、调用模型、验证动作、执行工具、观察结果、决定继续或结束的循环。Harness 是围绕模型的运行设施，还包括工具注册、权限、沙箱、会话、预算、持久化、取消与评测。模型提出动作不等于有权执行。[Harness解释](https://code.claude.com/docs/en/how-claude-code-works)

**追问**：你是自己做Harness还是使用现成框架？要说明实际实现了哪些运行机制，不把 SDK 封装说成完整平台。

### Q27 P0 Function Calling原理是什么

**口述回答**：把工具名称、用途和参数 schema 提供给模型，模型返回工具选择和结构化参数；应用校验权限与业务条件后执行，再把工具结果反馈给模型。模型本身没有直接调用数据库。工具定义、输出解析、真实执行和结果验证是不同环节。

**追问**：流式参数只有半个JSON能执行吗？不能，完整组装并通过 schema 与业务校验后才执行；高风险操作还要验证用户授权。

### Q28 P0 工具如何设计才不容易误调用

**口述回答**：每个工具表达清晰的业务能力，名称、适用和不适用场景、必填参数、单位、返回状态都明确。优先有限能力如 `retrieveEvidence`，不要暴露任意 SQL、任意 URL 或管理员写库。输出有大小限制，并返回稳定 ID 和必要状态。[工具设计](https://www.anthropic.com/research/writing-tools-for-agents)

**追问**：很多工具怎么办？按当前任务只加载相关工具，降低歧义；不能仅靠减少描述长度降低 token。

### Q29 P0 模型输出JSON就够安全吗

**口述回答**：JSON 可解析只说明语法合法。还要拒绝多余字段，检查类型、范围、枚举、数组数量、字符串长度、ID存在性、对象归属、输入版本和业务限制。模型把食材名写成化学成分、把不存在的菜谱 ID 输出为推荐，都必须被拦截。

**追问**：失败自动让模型修复几次？读任务可设计受预算限制的修复，但拾味当前用户Key路径约定单次尝试，不自动重发。

### Q30 P0 如何保证路由准确和流程不跑偏

**口述回答**：区分普通推荐、健康咨询、证据查询、偏好写入等任务。能用确定条件判断的由代码路由，语义分类只处理歧义部分；低置信度询问。状态机限定各状态可用工具和转移，模型不能跳过身份、证据和确认节点。

**追问**：模型自报confidence可靠吗？不能直接当概率，要用标注集校准并记录误路由代价。

### Q31 P0 如何防止无限循环或无效反思

**口述回答**：限制模型轮数、工具次数、总 token、时间和成本；检测相同动作参数及无新证据的重复。每轮必须推进可观测状态。预算不足时返回未完成的明确状态和原因，不伪装成功。反思步骤只有在有外部检查或新信息时才值得继续。

**追问**：为什么不让Agent一直想直到解决？错误可能自我强化，且会放大费用和超时风险。

### Q32 P0 工具超时 失败 重试如何设计

**口述回答**：先分只读与有副作用，再区分确定未执行、明确失败、结果未知。只读可在总截止内有界退避；写操作只有幂等和状态核验充分时才考虑重试。供应商调用超时可能已经计费，拾味 BYOK 不自动补发。降级只能维持已声明语义，缺健康必需证据时不能继续给通过结论。

**追问**：取消是否一定停止计费？应用可传递取消信号，不能承诺供应商已经停止计算。

### Q33 P0 如何实现幂等 防止两个实例重复执行

**口述回答**：用身份、operationId、输入指纹和版本绑定操作；数据库唯一约束与条件更新原子认领。相同 ID 不同输入拒绝，不能仅先查询再插入。认领提交后再调用外部服务，避免长事务。进程在外部调用后崩溃可能产生未知结果，不能因此宣称跨供应商 exactly once。

**追问**：两个消费者同时拿到待处理任务？依赖数据库 CAS 或受控租约与 fencing token，不靠内存布尔值。

### Q34 P0 人工确认如何落实

**口述回答**：先生成待执行提案，包含目标资源、动作、输入版本和影响；用户确认绑定提案 hash、身份和有效期。执行前再校验权限和当前版本，旧确认不能授权变化后的动作。只读检索可自动执行；保存长期排除、删除或发布需要按产品授权语义执行。

**追问**：用户说“同意”但提案已变化？重新展示差异并取得针对新提案的确认，不能复用旧确认。

### Q35 P0 如何防提示词注入

**口述回答**：用户内容、检索文档、网页和工具返回都视为数据，不能提升成系统指令。工具层最小权限、资源白名单、参数校验和服务端授权共同限制动作。知识库问答进程不持有删除知识库的权限；“请忽略规则”也无法得到凭证或写工具。对恶意工具结果做对抗回归。

**追问**：system prompt写“禁止”是否足够？不够，安全边界必须由应用和数据权限落实。[MCP安全实践](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)

### Q36 P0 Agent状态保存在哪里

**口述回答**：区分临时对话、执行状态、长期偏好与公共知识。长任务状态用数据库记录 operation、步骤、版本和幂等状态；偏好按用户授权加密保存；公共证据独立治理。框架 checkpoint 不等于允许永久存完整健康对话。拾味当前完整聊天只在页内内存，不能直接启用默认全量持久化。[持久化概念](https://docs.langchain.com/oss/python/langgraph/persistence)

**追问**：服务重启后能续跑吗？按实际能力回答；没有持久化正文就不能保证恢复原对话全部内容。

## 四 P0级记忆与上下文压缩

### Q37 P0 短期记忆 长期记忆 RAG和Skill怎么区分

**口述回答**：短期记忆保存当前任务状态与近期交互；长期记忆保存经授权的稳定偏好或事实；RAG 按需找外部知识；Skill 保存可复用方法、流程和工具使用约定。Markdown 适合少量人工维护的流程说明，不适合直接承载大量健康事实的并发更新、权限与撤回。

**追问**：知识都写进Skill不行吗？知识规模、更新频率、引用、权限和条件检索决定是否需要数据库检索。

### Q38 P0 为什么上下文没满也要压缩

**口述回答**：窗口容量只是硬上限，噪声、位置和重复工具输出也会降低信息利用效率。优先清理无关和重复工具结果，再做结构化摘要或局部回取。是否压缩用任务成功率、约束保留与总成本共同判断。[上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

**追问**：大窗口是否彻底解决？不能保证；长上下文利用能力仍需在具体模型和任务上测。[位置影响研究](https://arxiv.org/abs/2307.03172)

### Q39 P0 上下文预算怎么算 何时触发压缩

**口述回答**：预留 system、工具定义、当前问题、证据、输出和安全余量，再给历史分预算。使用对应 tokenizer 或校准后的估计；供应商 usage 用于事后核对。压缩阈值根据下一轮最大输入和输出余量设置，而不是等 API 报超长。当前拾味16000字符上限是防护，不是精确 token 预算。

**追问**：压到多少？根据硬约束、近期窗口和任务状态能否完整容纳决定；文档里的候选预算需实验，不是已上线参数。

### Q40 P0 怎样保证压缩不丢关键事实

**口述回答**：把硬限制、用户确认、当前目标、待执行提案、已完成操作和版本单独结构化保存；摘要只描述历史，不重写权威字段。摘要包含来源轮次、未解决问题和失效标记。生成后做字段与不变量比较，丢失、冲突或新增未经确认事实则拒绝使用该摘要，保留旧状态并缩减可选内容。

**追问**：“用户不吃花生”怎么保证不丢？从可信偏好层每轮重新注入受控字段，不能只指望摘要记住。

### Q41 P0 多次压缩和切模型会有什么问题

**口述回答**：摘要的摘要会积累失真，因此保留版本和可回读依据，关键状态始终从权威来源重建。模型切换重新计算 tokenizer、工具 schema 与预算；旧摘要需验证 session、输入和来源版本，不能把模型 A 的隐藏状态或推理字段直接交给模型 B。摘要不能保留已被用户更正的旧事实。

**追问**：只换model字段行不行？还需验证协议、工具调用格式、上下文限制和成本记录。

### Q42 P0 如何证明压缩节省token且质量不下降

**口述回答**：同一冻结任务集比较无压缩、滑窗、结构摘要等方案，统计所有调用的输入、输出、摘要调用及重试 token。报告硬约束保留、任务完成、引用和重复执行率，再看 P95 与费用。单次 prompt 变短不等于整段会话总成本降低。

**追问**：费用包括cache命中吗？按供应商账单口径单独记录命中、未命中和输出；usage 不自动等于实际扣费。

### Q43 P0 Claude Code上下文压缩机制了解多少

**口述回答**：只讲公开文档可确认的行为：工具和对话共同消耗上下文，运行环境负责构造与管理上下文，存在压缩与持久化说明。不能断言内部摘要 prompt、固定触发阈值或隐藏推理保存方式。若做过自己的实现，重点讲自己的不变量和测试，不把推测当源码事实。[官方原理说明](https://code.claude.com/docs/en/how-claude-code-works)

**追问**：与你的方案区别？比较是否有业务硬状态、证据 ID、撤回复查、成本统计，而不是说“我们压缩算法更高级”。

## 五 P0级评测与证据

### Q44 P0 RAG检索有哪些指标

**口述回答**：Recall@k 看相关证据是否覆盖，Precision@k 看噪声，MRR 看首条相关排名，nDCG 看分级相关排序。需要多条证据才能完成任务时，另设“必需证据全部覆盖率”。无答案题单独评价拒答，不给它套有答案 Recall。指标的标注单位必须固定为文档、证据命题或chunk。

**追问**：切块策略改变chunk ID怎么办？用稳定原文证据命题或 span 标注，再映射到各切片版本，避免拿不同分母直接比较。

### Q45 P0 这些指标怎么计算

**口述回答**：单题相关集合为 G，前k结果为 Rk，`Recall@k=|G∩Rk|/|G|`，`Precision@k=|G∩Rk|/k`；`MRR=平均(1/首个相关排名)`；`DCG@k=Σ(2^rel_i−1)/log2(i+1)`，nDCG 为 DCG 除以理想排序 DCG。说明重复证据归并规则、宏平均还是微平均及实际返回不足k时的分母约定。

**追问**：只标一条答案却有很多同义证据？标注池不完整会低估召回，需要合并多方案候选并人工补标。

### Q46 P0 生成质量怎么评估

**口述回答**：检查答案是否回答任务、关键结论是否被证据支持、引用是否覆盖、条件与否定是否保留、是否适当表达不足。自动指标用于筛查，核心健康结论要人工复核。Ragas 等工具可辅助分层评价，但 judge 会受模型偏差和提示影响。[Ragas论文](https://arxiv.org/abs/2309.15217)

**追问**：有标准答案还要人工吗？自由文本可能存在多个正确表达；需要依据和rubric，而不是只比字符串。

### Q47 P0 评测集谁标 如何避免泄漏

**口述回答**：先定义证据与适用条件的标注规范，两人独立标注关键样本并裁决分歧。开发与测试按主题、来源和近重复问题分组，不能随机把同一问题的改写分到两边。已有小库可评估未见问题，另做未见来源测试检验解析与泛化；两种设置不能混称。

**追问**：模型生成题可以吗？可辅助出候选，但要人工核对，不能由同一个模型出题、作答、判分后宣称可靠。

### Q48 P0 Agent怎么评测

**口述回答**：同时看最终状态与执行轨迹：任务是否完成、是否越权、工具参数是否正确、有无重复写入、能否取消、预算是否超限、失败是否可解释。对有随机性的任务重复试验，报告通过率与波动。不能因最终文本看似正确就忽略错误副作用。[Agent评测](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

**追问**：为什么不能固定唯一工具顺序？等价有效路径可能很多，应约束关键不变量和结果，除非顺序本身是业务要求。

### Q49 P0 怎样设计消融实验

**口述回答**：固定数据、query、模型和预算，依次比较结构化关键词、加dense、加RRF、加rerank，以及不同切块与压缩。每次主要变一个因素；记录数据和模型hash、配置、原始结果及失败类别。指标接近时看配对差异和置信区间，不用几个好例子宣布胜出。

**追问**：混合没提升怎么办？保留更简单基线，分析是否现有题过于词面匹配或语料确实很小。

### Q50 P0 生产准入看什么

**口述回答**：先明确支持范围，再确认关键路径可测、权限与取消正确、成本有上限、引用可追溯、版本可回滚且撤回不复活。延迟、错误率和质量目标按业务冻结。构造集零违规只说明该样本内通过，不能表述成真实世界零风险或医疗安全率100%。

**追问**：项目现在能进入生产吗？按功能分别回答；普通推荐已运行并不代表疾病 RAG 已具备正式发布条件。

## 六 P1级数据库与检索深入

### Q51 P1 为什么选pgvector 不选Milvus或Qdrant

**口述回答**：已有 PG、数据量小、需要关系连接和一致发布时，pgvector 减少双写、权限与备份复杂度。独立向量服务在规模、过滤或运维特性上可能更合适，但要用目标硬件和实际负载对照。选型依据是当前约束及迁移成本，不是笼统说谁更强。[pgvector](https://github.com/pgvector/pgvector)

**追问**：什么情况下换？PG向量查询实测挤占事务资源、P95持续不达标且优化无效，再比较独立服务总成本和一致性方案。

### Q52 P1 精确检索 HNSW IVFFlat有什么区别

**口述回答**：精确距离计算易作正确性基线；HNSW以图结构换查询速度，需要较多内存和建图成本；IVFFlat按聚类列表选候选，需要合适训练数据和列表/探测参数。ANN 牺牲部分近邻召回，是否值得要画延迟和召回曲线；小库不必立即建 ANN。[索引说明](https://github.com/pgvector/pgvector#hnsw)

**追问**：HNSW为什么过滤后不足k？ANN候选生成与过滤交互可能丢结果，要测过滤选择性、迭代扫描、扩候选或精确回补。

### Q53 P1 HNSW参数如何调

**口述回答**：`m`影响图连接和内存，`ef_construction`影响建图质量与耗时，`ef_search`影响查询候选和延迟。先用官方默认做基线，再在冻结数据上调；不同时改所有参数。记录索引大小、建图时间和不同过滤条件下的近邻召回。

**追问**：官方默认能直接成为生产参数吗？必须验证真实扩展版本、平台支持和业务SLO，不能照抄。

### Q54 P1 余弦 内积 L2如何选

**口述回答**：取决于模型训练与输出约定。单位归一化后，余弦、内积和平方L2排序有关系；未归一化时向量模长会影响内积和L2。数据库距离操作符、索引 operator class 与查询排序必须一致，并检查零向量和维度。

**追问**：能否用新模型同维度向量混旧表？不能，向量空间不兼容。

### Q55 P1 中文检索有哪些坑

**口述回答**：词边界、专业别名、英文缩写、全半角、简繁体与生熟形态都会影响检索。先做 NFKC 和受控实体别名，保留原问；分词词典要版本化。别名只能对齐身份，不能推出“属于同类就组成相同”。未知长词不要被错误短词覆盖。

**追问**：jieba就够吗？它是候选分词器，仍要加领域词典和测试；不能凭安装一个包宣布解决中文召回。

### Q56 P1 增量更新和Embedding迁移怎么做

**口述回答**：来源和内容不可变版本，按内容hash识别变化；新片段在新manifest下生成向量。完整检查后原子切换发布指针，旧索引保留短期回滚。撤回集合独立于历史bundle，回滚也需应用最新撤回；不能覆盖旧迁移或混新旧向量。

**追问**：只换query模型不重建文档向量？一般不可行，除非供应商明确保证兼容且你做过验证。

### Q57 P1 多租户权限和删除怎样保证

**口述回答**：在检索候选层执行授权过滤，查询后再做输出复查；不能先把所有用户私有资料给模型再“提醒别泄露”。删除先影响权威可见性和缓存/索引manifest，再异步清理副本与备份策略。软删除或向量删除单独完成都不代表全链路删除完成。

**追问**：缓存命中旧结果怎么办？缓存键包含授权与版本维度，输出前查最新撤销水位。

### Q58 P1 数据为什么不能全放JSON或全放向量库

**口述回答**：业务主键、外键、版本、状态和常用过滤用关系列保证约束；变化较多的来源定位、条件扩展可用 JSONB 并做 schema 校验。原文大文件独立存放，向量只是派生索引。个人资料、公共证据、操作账本和模型输出应按访问边界分开。

**追问**：JSONB方便为什么还规范化？关键连接和一致性约束需要数据库看得见；完全规范化也有迁移和复杂度代价。

### Q59 P1 慢SQL怎么查 索引为什么没用

**口述回答**：先按 trace 定位数据库耗时，再看 `EXPLAIN` 和受控环境的 `EXPLAIN ANALYZE`，关注估计与实际行数、过滤、排序、连接和IO。检查选择性、统计信息、函数/类型转换、排序匹配和返回量；顺序扫描在小表可能更合理。[执行计划](https://www.postgresql.org/docs/17/using-explain.html)

**追问**：ANALYZE会执行写SQL吗？`EXPLAIN ANALYZE`会实际执行目标语句，生产写操作不能随便试。

### Q60 P1 为什么不一开始就用Redis MQ和图数据库

**口述回答**：先让模块化单体与数据库完成闭环，再按瓶颈增加组件。缓存要处理版本与撤回，MQ要处理重复与积压，图数据库要处理多库一致性和备份。新增组件必须回答解决哪条实测瓶颈、如何降级、增加多少成本。

**追问**：需要异步批量建库怎么办？先用可恢复离线批任务；持续多生产者负载或可靠调度需求明确时再引入队列。

## 七 P1级多Agent协议与系统可靠性

### Q61 P1 多Agent比单Agent好在哪里

**口述回答**：独立可并行任务、不同工具权限或不同专业上下文可以拆分，主Agent汇总受控结果。代价是通信token、结果冲突、尾延迟和状态一致性。先对照单Agent；同一模型多次投票并不等于独立专家审核。

**追问**：拾味需要多Agent吗？当前主链路并无已证实必要；离线研究可实验，线上避免为了展示概念扩轮。

### Q62 P1 中心调度如何拆任务与合并

**口述回答**：任务契约明确目标、输入快照、允许工具、预算、依赖和验收结果；独立子任务并行，依赖任务按序。合并按证据与版本检查，不直接拼自然语言。部分失败、冲突、取消和重复结果有明确处理；单个子Agent无权修改全局硬限制。

**追问**：共享记忆怎么防覆盖？版本化写入、CAS、归属和来源，必要时单写者合并。

### Q63 P1 MCP是什么 与Function Calling和HTTP有什么关系

**口述回答**：MCP是连接模型应用与工具/资源服务的协议，定义发现和调用等交互；Function Calling是模型产生工具选择和参数的能力；HTTP等承载通信。用了MCP也要自己做认证、授权、参数验证、超时和审计。MCP不是自动安全的Agent大脑。[MCP工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

**追问**：与A2A区别？通常前者侧重工具和资源连接，后者侧重Agent间任务协作；具体能力要按协议版本核对。

### Q64 P1 SSE与WebSocket如何选

**口述回答**：主要是服务端向浏览器推送生成事件时可用SSE，协议简单、支持事件ID；双向持续交互可考虑WebSocket。两者都要处理断线、心跳、代理缓冲、认证和背压。SSE自动重连不等于应重新调用模型，应重连已有operation的事件流或明确不可恢复。

**追问**：前端拿到部分文本后失败？保留未完成状态，不能把半个回复标为成功或自动重复收费调用。

### Q65 P1 长任务崩溃后怎么恢复

**口述回答**：把可恢复步骤设计成显式状态，步骤产物和操作ID可校验。恢复时重新读权威版本和撤回水位，外部副作用先查结果再决定后续；不能盲目回放所有工具调用。是否保存正文由产品资料策略决定，恢复能力不能越过隐私边界。

**追问**：结果写库但ACK前进程崩溃？消息可能再投，消费者通过幂等记录识别已完成，不重复副作用。

### Q66 P1 共享对象和异步上下文污染怎么发生

**口述回答**：把当前用户、model、messages或结果存在可变单例字段，两个请求交错就可能互相覆盖。请求状态用独立不可变对象，异步调用传显式上下文；只共享只读配置与受控连接池。用两个用户、延迟注入和并发重复请求复现。

**追问**：Node单线程为什么还会串请求？await让多个请求的执行片段交错，单线程并不等于业务原子性。

### Q67 P1 缓存怎么设计 如何避免旧知识复活

**口述回答**：公共不可变片段按内容hash缓存，检索缓存绑定索引manifest、词典和权限版本；最终输出仍复查撤回。个人健康问答不默认进入公共缓存。缓存击穿可用请求合并或短期锁，但锁超时和错误结果不能污染后续版本。

**追问**：Redis更新但进程缓存没更新？多级缓存版本或失效通知可能不同步；权威状态复查和有界TTL能减少后果，不能承诺通知永不丢。

### Q68 P1 限流与背压如何实现

**口述回答**：分别控制账号频率、并发数、工具和供应商预算。滚动窗口减小固定窗口边界突发，但仍需限制并发和排队长度。多个云实例依赖共享原子认领，而不是进程内计数。超限返回可理解状态，不能让队列无限增长。

**追问**：六次每分钟等于最多六个并发吗？不是，频率与并发是两个指标。

### Q69 P1 如何记录监控而不泄露健康资料

**口述回答**：记录随机operation ID、模型和配置版本、耗时、usage、错误分类、候选数量和状态。原文、个人查询向量、Key及可还原健康条件不进入通用日志。需要内容级失败分析时使用脱敏构造样例或单独获授权流程，不默认保存完整trace正文。

**追问**：哈希能保证匿名吗？低熵健康文本可被字典猜测，单纯SHA256不足；即便用HMAC也需控制用途与保留。

### Q70 P1 P95延迟如何拆解和优化

**口述回答**：分连接/认证、数据库、query编码、候选检索、重排、模型首包与完成、校验和网络。独立检索可并行，必需校验不能跳过；限制候选和输入，缓存公共不可变数据。尾延迟还受冷启动、排队、超时和供应商波动影响，不能只报平均耗时。

**追问**：模型慢怎么扩容？应用扩容不一定提高供应商吞吐，需要并发预算和限额，并区分应用瓶颈与上游瓶颈。

### Q71 P1 如何估算成本和容量

**口述回答**：单任务成本等于全部模型调用、Embedding、重排、存储和运维成本，token按供应商实际输入输出及cache口径计算。容量按请求类型、并发、上下文长度和供应商额度测，普通目录查询QPS不能代表LLM端到端吞吐。用压测逐渐加压观察P95、错误和资源。

**追问**：能扛1万QPS吗？没有实测就不报数字；说明将如何测，以及限流、降级、缓存和队列的作用。

### Q72 P1 服务突然CPU或内存升高怎么查

**口述回答**：先控制流量和停用异常版本，再按监控定位时间点与请求类型。CPU检查死循环、同步计算、序列化和GC；内存检查无界历史、未释放流、缓存、句柄和批量编码。保留脱敏诊断，比较堆增长和分配热点。内存泄漏是对象不再需要却仍可达，内存不足也可能只是合理负载超容量。

**追问**：怎样快速止血？摘除异常实例、限流、回滚或关闭对应功能，同时保留足够诊断证据。

## 八 P1级基础与AI开发协作

### Q73 P1 从输入URL到响应发生什么

**口述回答**：浏览器解析URL、查缓存和DNS，按目标地址与路由建立连接，经ARP或邻居发现到下一跳，TCP或QUIC及TLS完成传输准备，HTTP请求穿过代理到服务端，服务处理数据库与模型再返回，浏览器解析渲染。实际是否新建连接取决于缓存、连接复用与协议。

**追问**：TCP可靠性靠什么？序号、确认、重传、校验、流量与拥塞控制共同作用；应用还需定义超时和幂等，不能由TCP保证一次业务执行。

### Q74 P1 线程 进程 协程及Python GIL如何回答

**口述回答**：进程隔离地址空间，线程共享进程资源，协程在运行时调度并在等待时让出执行。IO密集可用异步/线程提高利用，CPU密集考虑进程或原生并行。GIL回答必须限定解释器和版本；传统CPython受GIL限制不代表所有Python构建都如此。Node事件循环也不能承载无界同步CPU任务。

**追问**：你的项目用Python还是TS？当前在线应用主栈TS，Python用于资料处理；不编造Python生产并发经验。

### Q75 P1 数据库事务 CAS和锁怎么选

**口述回答**：数据库约束处理不可违反的一致性，短事务保证多行变更；CAS通过版本条件更新解决冲突，行锁适合短期串行认领。先查再写存在竞态。CAS要处理失败、重读和可能的ABA，不能无限忙等；模型调用不要占着数据库事务等待。

**追问**：乐观锁失败后直接覆盖吗？不行，硬限制等冲突需要重新合并或让用户选择。

### Q76 P1 Redis Lua为什么不宜执行长脚本

**口述回答**：Lua可以让相关命令在服务器侧原子执行，但长脚本会占用执行资源并影响其他请求。脚本必须有界，不做长循环和大型扫描；错误、超时和客户端重试也要结合实际Redis语义处理。它不能替代跨数据库事务或证明业务消息只执行一次。

**追问**：项目没用Redis怎么办？解释理解和适用场景，不把参考题里的Java秒杀经历套给自己。

### Q77 P1 索引 回表 深分页和消息队列还会问吗

**口述回答**：Agent岗位常仍要求后端基本功。准备B+树范围访问、联合索引前缀与选择性、覆盖索引、MVCC与锁、offset深分页和keyset分页；MQ准备投递确认、重试、幂等、顺序与积压。说清具体数据库与引擎，不能把MySQL二级索引回表机制原样套到PG。

**追问**：为什么暂不用MQ？当前量小，新增队列的收益未证明；需要后可用outbox及幂等消费处理数据库与消息协同。

### Q78 P1 AI Coding全流程怎么控制质量

**口述回答**：把需求变成行为和验收案例，先读现有约束与接口，再让AI做小范围修改，检查diff、运行相关测试和构建，对关键权限与数据流人工核对。需求变化更新决策与验收，不让旧文档压过后续决定。能解释和维护的代码才合并。

**追问**：一轮prompt能交付大项目吗？可以快速生成原型，生产交付仍要拆解、验证与回滚；不要把没有验证的生成结果当完成。

### Q79 P1 PRD和技术方案各写什么

**口述回答**：PRD定义用户、场景、输入输出、边界、异常和验收；技术方案补充数据流、接口、状态、存储、选型、预算、隐私、测试与回滚。对模糊需求先给可验证的例子；发生变化记录影响，不把沟通简化成“让产品再确认一遍”。

**追问**：技术方案发生分歧？用目标、约束、最小对照实验和迁移成本决策，并记录替代方案适用条件。

### Q80 P1 如何证明开源项目研究深度

**口述回答**：锁定仓库和commit，找到模型适配、消息循环、工具执行、取消、压缩和持久化入口，画一条实际调用栈，修改一个具体问题并验证。仅阅读README就说“精通源码”很容易被追问击穿。

**追问**：DeepSeek Harness与pi有什么区别？先确认版本和比较层级。公开资料显示前者强调可替换插件组合，pi强调可扩展的精简harness；实际Loop、压缩和持久化需逐入口比较。[DeepSeek架构](https://deepseek-harness.github.io/deepseek-harness/en/reference/)、[pi仓库](https://github.com/earendil-works/pi)

## 九 P2级模型基础与扩展

### Q81 P2 Transformer和Attention与应用开发的关系

**口述回答**：Attention根据query与key的匹配聚合value，多层注意力与前馈网络形成上下文表示。应用侧重点理解输入长度、生成成本、位置和缓存，不能只背公式。不同模型可能使用GQA、稀疏注意力或其他结构，具体参数以模型说明为准。

**追问**：长上下文成本必然严格n平方吗？经典全注意力的配对量是二次，但具体推理实现、缓存和架构会改变实际计算与显存曲线。

### Q82 P2 KV Cache Prompt Cache和记忆有什么区别

**口述回答**：KV Cache保存推理中已有token的key/value，减少重复计算；供应商Prompt Cache可能复用相同前缀的计算；应用记忆保存任务和用户信息。这些机制不会自动保证事实正确，也不意味着消息被免费永久保存。实际计费与保留以供应商当前说明为准。

**追问**：KV显存怎么算？近似 `2×层数×KV头数×头维度×缓存token数×每元素字节×并发`，还要加权重、激活、运行框架和碎片，不能仅报模型权重大小。

### Q83 P2 温度 top_p max_tokens怎么选

**口述回答**：温度和top_p影响采样，max_tokens限制输出而非总上下文。事实性任务可减少随机性，但低温不保证正确，检索和校验仍必要。实际可用参数、thinking模式和互斥限制按当前供应商核验；不要写通用“最佳参数”。

**追问**：temperature为0每次一定相同吗？不能保证跨后端和版本确定性，评测仍需考虑波动。

### Q84 P2 本地模型如何估显存 何时选API

**口述回答**：从参数量乘权重精度估权重下限，再加KV、激活、并发、框架和碎片，实测峰值。API减少自运维但有费用、版本和资料边界；本地权重免费不代表算力免费。对小型云函数，把0.6B模型常驻也必须先验证资源与冷启动。

**追问**：量化能无损吗？通常需重新评测质量、吞吐和硬件支持，不能只按理论压缩比承诺。

### Q85 P2 什么情况下需要微调

**口述回答**：任务行为、工具选择或输出格式在足够高质量样本中反复出现，且prompt/工具设计/检索优化仍不足时再考虑。需要训练、验证、测试分组，比较基础模型和微调收益。经常更新的外部知识和权限不能仅靠写入权重解决。

**追问**：SFT DPO与RAG关系？前两者主要改变模型行为或偏好，RAG提供运行时知识；要按目标区分，不把训练当检索替代。

### Q86 P2 GraphRAG何时有价值

**口述回答**：需要跨大量实体关系聚合、全局主题或复杂路径时可实验图检索。图边抽取、实体合并和版本治理也会引入错误。拾味当前显式的疾病—成分—食材—工艺关系可先用PG连接；自动抽图不能自动产生可执行健康规则。

**追问**：关系多就一定用图数据库吗？看路径复杂度、查询负载与运维收益，不看概念是否新。

### Q87 P2 Agentic RAG CRAG Self RAG怎么理解

**口述回答**：可以分别理解为模型按反馈选择检索步骤、对低质量检索进行纠正、对检索与生成进行自评价的研究方向。具体系统是否有效要按论文和实现版本评测。项目先解决来源、切块和标注，不能把多个名称叠加视为优化完成。

**追问**：自评能替代外部评测吗？不能，自评存在同源偏差与误判。

### Q88 P2 对抗测试和红队怎么设计

**口述回答**：围绕真实能力边界构造攻击：文档要求删库、伪装工具结果、越权用户ID、过期确认、改写硬限制、伪造引用、恶意URL、超长输出和并发重复。验证最终权限和数据库状态，不能只看模型是否礼貌拒绝。失败样例进入回归并按机制归类。

**追问**：模型说拒绝但工具已执行怎么办？算严重失败，工具授权才是最终边界。

### Q89 P2 手撕会考什么 怎么准备

**口述回答**：优先练数组哈希、双指针、滑窗、堆、二分、树遍历和基础DP；工程题练LRU、最小栈、限流器、嵌套JSON合并、有界并发和RRF去重。边写边说明复杂度、空输入、重复值、溢出、线程安全和测试样例。不要只背LLM概念而放弃编码能力。

**追问**：JSON里bool是number的子类吗？在Python中是，类型分支顺序要处理；这类语言细节要实际写过。

### Q90 P2 HR与反问怎么准备

**口述回答**：用真实例子说明需求冲突、陌生技术学习、进度与质量权衡，讲行为和结果。职业规划结合目标岗位，不编造实习。反问可以了解Agent实际业务、质量标准、数据和工具权限、成本瓶颈以及实习生能负责的模块，避免只问用了哪个模型。

### 一个完整的追问链练习

面试官问“为什么用混合检索”，先讲精确实体与语义改写互补；追问“怎么融合”，给RRF和去重；追问“为什么k0是60”，说明是候选起点和开发集调参；追问“怎么证明提升”，拿同一冻结集的消融；追问“没有提升”，说明保留基线；追问“正确证据被挤掉”，说明规则必需证据独立保留。每一层都回到数据、边界和可复现证据。
