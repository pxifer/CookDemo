# 多 Agent 本地协作

当前使用本地 Git 提交审核，不依赖 GitHub PR、推送、分支保护或公网连接。2026-11-12用户取消定时任务后，按用户发起的审核执行，不再设置后台巡检；管理 chat 收到当前审核任务后可自主检查，不等待额外通知。

## 角色和隔离

- 开发 agent 从同一已确认本地 `main` 基线建立独立 worktree / clone 和任务分支，完成必要验证并提交；不直接修改或自行合并 `main`。
- 分支采用 `agent/<名称>/<任务编号>-<简述>`；新建 worktree 优先使用客户端工具。独立 clone 也可使用，但提交须先导入当前仓库任务分支才能审查。
- 管理 chat 按任务和完整提交 SHA 独立审查，串行合入本地 `main`，再复验实际合并提交。新提交或基线变化会使旧审核结论失效。
- 不自动推送、部署、创建云资源、发送真实邮件或调用付费模型。

## 任务与范围

开发前登记任务编号、负责人、目标、可改目录/共享文件、分支、基线、依赖和验收口径。统一状态见[任务登记](tasks.md)，详细范围和提交交接见 `submissions/`；并行任务涉及共享登记时，先明确协调范围，不覆盖其他 agent 的未提交修改。

共享类型、Schema、依赖、迁移、`AGENTS.md`、协作规则和检查脚本有交叉时，先明确接口和文件范围；登记不等于永久锁。多个任务可从同一验收基线同时开工，第一个合并后，其他任务纳入最新 `main`，处理文本和语义冲突并复验。

不能使用 `git add .` 混入其他任务，不执行 `reset --hard` / `clean` 丢弃工作，不强推或重写主分支历史。保持原件、密钥、本地配置、数据库及历史验收边界。

## 验证与提交

依据根目录[AGENTS.md](../../AGENTS.md)及改动范围选择检查。代码默认检查构建、主/验收类型和单元；UI、规则、资料或RAG补对应回归，纯文档检查链接、事实、行数及受保护文件。未运行、跳过和缺配置分别记录，不把本地构造验证写成真实云端或专业质量通过。

`scripts/run.ps1 pr:check` 名称保留兼容，实际检查本地提交；基线传本地 `main`，不要改回依赖远程分支。详细命令、退出码和干净工作区要求见[审核手册](review-runbook.md)。

完成后使用精确路径暂存并 `git commit`，交接写明任务 head/main 完整 SHA、差异范围、真实检查结果、缺口和回退方式；可参考[提交说明格式](../../.github/pull_request_template.md)，但不要求创建远程PR。开发完成记“待审”，管理员完成主分支复验后才记“完成”。

## 审核与历史

管理员只审查已提交的确切版本，不将管理工作区或另一个任务的未提交内容混入。默认以 merge commit 保留任务历史；合并后发现问题，通过新的修复/回退提交处理，不擅自改业务代码或跳过复验。
