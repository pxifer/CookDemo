# INPUT-001：食材清单去量与图片识别

基线：`09b03b0f533096fe7387031f668d9db681a21482`。任务分支：`agent/codex/INPUT-001-photo-ingredients`。因工作区挂载在仓库上级，桌面create_worktree工具拒绝子目录sourceRoot，按协作规则改用独立本地clone `D:/codex_AI/菜谱推荐/ingredient-photo`，没有修改管理目录main业务文件。

## 最终行为

1. 食材清单移除用量、单位、数量冲突选择及提示；新输入和旧草稿恢复时清除输入amount/quantityUnit/alternative。文字中的数量仍可被解析并忽略，不变成未知食材。保留菜谱原方配料、数量和做法。已知食材去重，未知食材待改名/删除，原过敏、忌口、补买与推荐条件保留。
2. 图片入口支持文件与手机拍照、内存预览、重编码、明确点击才上传、识别候选勾选确认、取消及迟到丢弃。不确定项单独提示，不自动加入。只识别名称，不推断重量、健康资料或隐藏配料。
3. 默认复用个人健康DeepSeek Key（无需打开健康开关）；服务端可显式配置官方免费智谱GLM-4.6V-Flash及独立Key。固定两个供应商地址/型号，无跨供应商自动回退。环境模板及本地/云函数/研究预览启动入口已接线，不部署、不配置真实新Key。
4. API要求真实账户、同源/CSRF、当前内容版本、共享PG原子认领与原有限额；复用并发保护，20秒截止、取消、失败不重试。原始图片不写文件/公共知识库/调用表，响应不包含Key或图片。

共享契约新增 `shared/image-recognition.ts`、SessionInfo供应商标记、Extraction.method模型类型。没有新依赖或数据库迁移，未启用平台统一支付/每日10次新策略。
