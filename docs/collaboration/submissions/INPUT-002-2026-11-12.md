# INPUT-002：食材匹配与健康对话更新

分支 `agent/codex/INPUT-002-conversation-matching`；从最新本地main bfa1567开始，复用独立开发副本ingredient-photo。没有更改管理main或服务进程。

## 决策与实现

1. 确定同义词自动匹配：如小西红柿/小番茄/圣女果/樱桃番茄。只有目录中唯一对应项才自动归一，不用相似名称自动放宽食材/过敏规则。“生肉、干果”不是同义词，不猜具体种类；清单给可点击的候选，用户确认后走既有合并和资格校验。识图提示优先具体常见名，不确定的对象独立保留。
2. 补问每次只问一个可独立回答的问题，不要求固定答题格式。对旧多项问题的“是的”不能全部解释成肯定，更不能推断医嘱。模型省略profile或局部字段时，仅使用本轮已知档案填补省略字段；不从短回答猜新健康事实。错误类型、未知字段、空正文/截断等仍拒绝，没有自动重试。
3. 允许随时更改过敏、忌口，不锁定设置，不要求重置健康档案。前端发现限制变化即取消在途回复、保留未发成功文字，并划分上下文边界；旧消息仍可回看，后续不送旧消息。服务端每轮用账户当前限制替换旧客户端自用限制，保留明确启用且已登记的同行人限制；客户端限制过期时只送本轮消息。模型系统提示明确当前限制为唯一依据，历史不可恢复撤销项。
4. 认领后与回复后复核账户限制；变化时拒绝旧回复。saveHealthGuidance新增可选限制快照检查，并结合既有版本CAS防止保存重试期间采用旧限制。健康档案、已接受的目标食材记录不因修改忌口被清空；接受的独立AI避开记录仍由用户自行取消。
