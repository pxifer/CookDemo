# 审核与合并手册

## 当前执行方式：本地 Git

用户已改为本地 Git 提交审核；下方远程 PR 操作仅保留作旧方案参考。本地流程不依赖 GitHub 或推送。

1. 查看本地任务分支相对 `main` 的新提交，记录任务 head 和 main 的完整 SHA，审查完整差异及任务验收证据。只读已提交内容，不把脏工作区混入待审版本。
2. 在独立干净审核目录检出待审 SHA，纳入最新本地 main。冲突先在任务分支处理；即使没有文本冲突，也检查系统逻辑与 AI 的契约和行为。
3. 运行 `scripts/run.ps1 pr:check`，`--base` 使用本地 `main` 而非 `origin/main`，`--head` 使用待审完整 SHA；工具名称保留兼容，实际可用于本地提交。按改动补专项。记录结论和证据于 `.local-data/management/`。
4. 合并前确认 main 和任务分支未变，串行将已审确切 SHA 以 merge commit 合入 main。不得在用户或其他 agent 的脏工作区操作；main 被其他工作区占用时先停止集成，不能强制绕过工作区保护。
5. 在干净 main 目录对实际合并 SHA执行 `post-merge` 检查，`--base main`，补与合并前相同专项。复验通过后才完成，失败冻结后续合并并保留证据；修复或回退通过新的审查提交完成，不重写历史。

检查期间相关 SHA 或源码变化则旧结论失效。仍须等待用户通知原开发结束，才能建立初始化本地基线。

## 收件与审查

1. 确认任务编号、负责人、改动范围和验收标准。读取 PR 描述、所有 commits、完整 diff、讨论和已有检查；Draft、依赖未合入或冲突未处理的 PR 不进入合并。
2. 记录远程目标 `main` SHA、PR 完整 head SHA。获取最新远程引用，在独立干净审核目录检出该 head；确认 head 包含当前 main。不要在管理脏目录切分支或合并。
3. 独立追踪调用方与契约，检查输入校验、身份隔离、并发 / 取消 / 旧响应、过敏与库存硬限制、证据条件、迁移兼容、费用、秘密及功能开关。审查测试本身，不能只看作者结论或绿灯。
4. P0 / P1 / P2 缺陷写明触发条件、影响、文件行号及修复要求；阻断合并。建议性 P3 记录是否后续处理。把意见留在 PR，修复后逐项复核，不自动接受作者标记已解决。

## 合并前验证

```powershell
git fetch origin
$reviewedHead = git rev-parse HEAD
.\scripts\run.ps1 pr:check -TaskArguments @('--phase','pre-merge','--base','origin/main','--head',$reviewedHead)
# UI 相关例：在上述数组末尾添加 '--browser','core,health'
```

按实际改动补充数据库 / RAG / 浏览器专项；缺配置先记录，不切换生产环境。保存 SHA、基线 SHA、各阶段结果、手工检查、未运行项和剩余风险。

合并前再从 GitHub 查询 PR head、目标 main、状态、讨论、冲突和保护规则。任何 SHA 改变，或源码在检查期间改变，都必须重新审查对应变化和重新运行受影响检查。自动检查为通过只是必要条件；管理员还要明确记录“已审查 `<head>`，基于 `<base>`，允许合并 / 要求修改”。同账号使用 COMMENT，不伪造 APPROVE。

合并 API 必须携带已审核的完整 head SHA，禁止无 SHA 条件合并；默认 squash，初始化 PR 用 merge。若目标分支发生变化先暂停并更新验证，不用强推绕过；API head 条件不锁定 base，管理员必须串行操作并尽量缩短最终核对到合并的间隔。

## 合并后复验

在干净的 `main` 审核目录拉取仅快进更新，确认 HEAD 等于 GitHub 返回的合并 SHA，重新运行同一组检查：

```powershell
git switch main
git pull --ff-only origin main
$mergedHead = git rev-parse HEAD
.\scripts\run.ps1 pr:check -TaskArguments @('--phase','post-merge','--base','origin/main','--head',$mergedHead)
```

UI / 健康等选项与合并前一致。复验报告必须绑定合并 SHA；再核对远程 `main` 未被其他操作改变。完成后在 PR 评论记录合并 SHA、复验摘要和证据位置，更新任务状态为完成。

失败时冻结后续合并，记录失败证据并查明是环境还是代码。代码问题通过修复 PR 或 revert PR 处理；回退涉及迁移 / 撤销水位时先审兼容和数据风险，不重写 `main` 历史，不自动恢复已撤回来源或个人资料。

## 验证选择

| 改动 | 必要补充 |
| --- | --- |
| 文档 | 链接、事实、命令和已有约束；纯文档可说明免跑业务检查的理由 |
| 业务 / API / shared | 相关单元、完整基础检查；输入 / 运行时 Schema 与调用方核对 |
| UI | 相关浏览器套件，手机 / 桌面、键盘、弹层、溢出与位置保持 |
| 账户 / 健康 / 模型 | 身份与资料隔离、密钥处理、撤销、预算与失败不重试；只运行构造模型 |
| SQL / 存储 | 本地真实 PG 集成、前后版本兼容、回退与撤销水位；不得连接正式库 |
| RAG / 资料 / 评测 | 来源、条件、撤销、配方绑定与相关离线专项；专业和真实生成缺口分别记录 |
| 检查脚本 / 协作规则 | 审查脚本实现和绕过可能，验证失败 / 脏工作区 / 提交变化的拒绝路径 |
