# 本地提交审核与合并

当前流程只使用本地 Git，不依赖GitHub PR或网络。后台定时检查已取消；按用户发起的审核执行。管理员可自主审核当前已提交任务，开发 agent 不自行合并。

## 1. 收件与版本固定

1. 读取任务登记/交接，确认负责人、范围、依赖、验收和回退方式；记录任务 head 与当前 `main` 的完整 SHA。
2. 确认提交位于本仓库任务分支。独立 clone 先导入提交，再审核；不以未提交工作区、口头说明或旧 SHA 报告作为候选。
3. 在独立干净审核目录检出待审版本并纳入最新本地 `main`；冲突在任务分支处理，不在脏的管理目录合并。按目录隔离任务、配置、构建、端口和测试账号。

## 2. 差异审查

按任务追踪入口、调用方及契约：运行时校验、身份/Key/资料隔离、并发/取消/旧响应、限制与食材有无、事实/证据/版本、迁移兼容、费用及功能开关。系统逻辑与AI任务即使没有文本冲突，也要核对语义集成。

检查测试本身，不能只接受作者结论或绿灯。P0/P1/P2记录具体触发条件、影响、文件位置和修复要求，阻断合并；P3建议标明是否后续处理。原件、冻结定位、旧知识包、面试材料及验收报告按各自保留规则核对，不能当缓存批量删除。

## 3. 必要验证

工具名保留兼容，实际基线使用本地 `main`：

```powershell
$reviewedHead = git rev-parse HEAD
.\scripts\run.ps1 pr:check -TaskArguments @('--phase','pre-merge','--base','main','--head',$reviewedHead)
# UI相关时在TaskArguments中补 '--browser','core,health' 等实际相关组。
```

按根目录[AGENTS.md](../../AGENTS.md)和实际改动选择必要专项。代码默认核对构建、主/验收类型、单元；UI、数据库、资料与RAG使用已有本地包装器；纯文档检查引用、事实、行数与保护范围。不新增云端/付费检查，不用正式服务补缺失环境。

报告在忽略目录 `.local-data/management/reviews/`，记录精确 SHA、命令、各阶段、跳过/未运行和剩余影响。退出码0表示所选检查通过，1失败，2不完整；`preflight` 允许脏工作区但不构成可合并通过。PGlite不能代替真实本机PG并发，构造供应商不能代替真实生成质量。

检查期间任务 head、main 或相关源码改变，旧结论失效。不能借用另一开发目录中随后修改的代码作为原提交的审核证据。

## 4. 串行合并

1. 管理员明确记录“已审查完整head，基于完整base，允许合并/要求修改”，重新核对两端未变。
2. 干净管理工作区串行合入已审确切提交，默认使用 merge commit。主分支被其他工作区占用时停止集成，不能绕过Git工作区保护或强改引用。
3. 在干净 `main` 对实际合并 SHA执行 `post-merge`，`--base main`，补合并前相同的相关专项。源码和基线必须稳定。
4. 复验通过才登记完成；失败暂停后续合并并保留结果，通过新修复或明确回退提交处理，不重写历史。

用户或其他agent的脏工作区需要先完整保存文件、索引和恢复清单，按已授权范围处理；不能直接覆盖、清空或跳过快照。Git合入仅表示本地代码集成，不表示已推送、部署或完成未测能力。

当前任务与独立审核结果见[任务登记](tasks.md)、`submissions/` 和 `reviews/`，共同基线见[BASE-001审核](reviews/BASE-001-2026-11-05.md)。
