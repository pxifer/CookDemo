## 背景

一致性审计（"折叠到某大类 ⇒ 该大类必须能匹配它"）此前剩 15 处不一致，另在按使用频次抽查时发现 2 处类别错归。

## 修正

**调味汁/加工品不再折叠**（它们在目录里是独立条目）：

| 曾被折叠 | 现归为 |
|---|---|
| 蚝油 → 贝类 | 蚝油 |
| 鸡汁 → 鸡肉 | 鸡汁 |
| 蒸鱼汁 → 鱼 | 蒸鱼汁 |
| 虾油 / 卤虾油 → 虾 | 虾油 / 卤虾油 |
| 奥尔良鸡翅腌料 → 鸡肉 | 奥尔良鸡翅腌料 |
| 泡发新西兰花胶 → 西兰花 | 泡发新西兰花胶 |
| 鸡蛋干 / 鸡蛋酱 → 鸡蛋 | 各自独立 |

**同义词头名改为目录中真实存在的名字**：`包菜 → 卷心菜`、`圣女果 → 小番茄`（此前指向 `洋白菜`/`小西红柿`，这两个名字在目录里不存在，导致折叠后的条目选不到）。同时 `compatibleNames` 认同义词，`包菜` 与 `卷心菜` 互为同一食材。

**去掉 `小根蒜 → 蒜`**：`蒜` 不在目录里，映射后反而无法选择。

**类别错归**（v82）：`杏鲍菇` 曾被"鲍"误判为贝类 → 蘑菇；`鲍鱼` 曾被"鱼"误判为鱼 → 贝类。

- 线上 `index-DuojcUcj.js`，`/readyz` 200。

## 关于全量审计的判断

没有做全量审计，理由是收益低、成本高：

- 696 个主料名里 454 个没有大类映射，但它们绝大多数是**名字即食材**的具体词（冬瓜、丝瓜、韭菜、芹菜），输入原名就能命中；
- 名字带修饰的变体（小土豆、黄洋葱、鲜香菇）由**子串包含**覆盖，本来就能命中；
- 真正会漏的是"**同一食材的另一种叫法**"（二刀肉 vs 猪肉、梅头 vs 猪肉），这类问题无法靠机械扫描发现，只能靠语义清单——全量扫 696 条也只是把它们重新列一遍。

更有性价比的两条检查已经做完并固化为脚本化审计：① 折叠与匹配的一致性；② 同一名字被多个大类同时命中（类别互串）。二者都是 O(n) 且能自动判定对错。后续若再出现用户反馈的个例，按个例补 `matchNames` 或同义词组即可。
