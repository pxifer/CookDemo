# main-v84：自由文本与下拉走同一套归并

2026-11-14。仅匹配规则，未改内容版本（仍 `gallery-listed-foods-1000-20261114-v3`）。

## 问题

用户手打"肉丝"能进「我的食材」，但蒜薹肉丝的补买里仍出现 `猪里脊`。

原因是两条输入路径口径不同：

- 下拉里的条目已经是归并后的名字（`肉丝` 显示为 `猪肉`），所以选它就命中猪肉族；
- 自由文本保留用户原词 `肉丝`，而家族判定只看 `inputs`（`猪肉`/`瘦肉`），`肉丝` 不在其中，于是落到"名字包含"兜底，`猪里脊` 不含 `肉丝` → 判为缺货。

## 修改

`compatibleNames` 判断家族成员时改用各家族的 `matchNames`：`肉丝 / 肉末 / 肉片 / 五花肉` 都属于猪肉族，因此都能覆盖 `猪里脊`、`梅花肉` 等同族部位。

一个反向的坑：最初我改用"归并后的名字"去判族，结果 `大白菜` 被归并成 `白菜`，进而覆盖了 `小白菜`——把两个不同蔬菜混为一谈。改用 `matchNames` 后不会放宽词义。

顺带补了 `咸鸭蛋 / 熟咸鸭蛋 / 生咸鸭蛋 / 咸蛋` 同义词组（成对审计剩下的 4 处不一致）。

## 验证

- 用户场景：`肉丝`、`肉末`、`肉片`、`五花肉` 均覆盖 `猪里脊`；`香菇` 仍**不**覆盖 `金针菇`（不同商品）。
- 成对审计：把 271 个被归并的食材按归并名分组，组内两两互测 —— **6960 对，0 不一致**。
- 单元 `430 / 427 通过 / 2 跳过 / 1 失败`（`离线原件重建` 需 python 3.11，默认 3.14，属环境）；`tsc --noEmit` 与 Vite 构建通过。
- 线上 `index-DYQ3rZ-l.js`，`/readyz` 200。

## 边界

- 命中仍为 `unverified`：代表"算同一种食材"，不证明部位、形态或数量够用。
- **刻意保留的差异**：自由文本写得比下拉更具体时不会放大（`香菇` 只算香菇）。下拉把 `香菇/金针菇/杏鲍菇` 折叠为"蘑菇"是列表长度上的取舍；手打的 `香菇` 不应因此被当成"有任意菌菇"。
