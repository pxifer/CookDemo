# 本地数据库业务链路验收报告

日期：2026-10-21。范围：React → Fastify → 本机Docker PostgreSQL → 推荐计算 → React展示。数据全部为隔离构造资料，不是正式菜谱、营养或健康内容；本轮未访问CloudBase、重复云迁移、创建云资源、修改原001～003或扩展备份工具。

## 1. 审查结论与最小实施方案

审查依据为PRD、需求基线、TDD、D7-01～14/D8决策，以及最新版部署记录和操作手册。D7-14继续优先：人数只影响自动菜数，单道用量/营养不缩放。推荐排序继续家常优先、同层少补买，候选每页最多六个不同父菜谱，自定义最多20道。

| 模块 | 审查时实际状态 | 本轮结果 |
| --- | --- | --- |
| 文本/手动食材输入（FR-02/03） | 本地词典可用，但词典绑定源码目录 | 可使用数据库食材及别名；未知信息保留核对，不伪造食材 |
| 过敏/忌口、库存与数量（FR-04/05） | 已有规则和回归，食物索引绑定源码 | 通过请求级内容上下文接入数据库；类别范围仍需确认，库存/补买规则不变 |
| 推荐/单换/变体/候选（FR-06～08） | 构造目录内可计算，数据库只用于启动检查 | 同一数据库快照进入既有引擎；版本变化拒绝旧请求/游标 |
| 食材/菜谱/营养/步骤读取（FR-07/09） | 表已建好，没有读取适配 | 从现有关系表重建可验证快照，营养保留来源、单位及缺项 |
| 导入/发布/回退 | 无业务执行入口 | 构造内容事务导入、校验、发布、撤回及显式版本选择已接通 |
| React详情/收藏（FR-09/10） | 结果展示可用，收藏详情仍直接查源码目录 | 页面先读目录API；数据库变体、步骤、用量和收藏复查可用 |
| 默认资料/草稿（FR-12） | 浏览器本机保存 | 继续本机保存；没有冒充云同步 |
| 登录/同步/凭证 | 有机制类和构造测试，正式HTTP链路未接通 | 仍未接通，本轮默认不启用测试登录 |
| 图片/具体模型（FR-01） | 图片接口明确不可用 | 继续后置；文字整理仍是词典，不是大模型识别 |
| 健康建议（FR-11） | 正式健康未准入 | 保持关闭，未执行疾病规则或提供适宜性判断 |

必要修改按“统一内容上下文 → 数据库导入/读取与发布 → API → React → 故障/回退验证”实施。缓存、SQL全文/向量召回、批量导入性能、管理后台和正式数据治理可推迟；没有引入新数据库产品、服务或Agent。

## 2. 数据和运行隔离

- 复用现有Docker实例 `shiwei-local-db-1`，新建必要的独立构造业务库 `shiwei_business_local`。原 `shiwei_dev`、`shiwei_test_structure` 和数据卷保留；未把业务构造数据导入原空库或云库。
- 仅复用未改写的001/002初始化此构造库，共24张核心/账本表。业务链路不需要向量，因此没有在该库启用003或生成Embedding；原本地/云端26表及pgvector部署保持原状。
- 当前版本 `local-business-v1`：25个食材、18道菜谱、36个变体。17道原构造菜谱之外，增加数据库专有的“构造西葫芦”/“构造角瓜”及测试菜谱，验证没有混用源码目录。
- PostgreSQL中的营养值为刻意构造的计算测试值。示例：100g构造西葫芦的菜谱返回20kcal、蛋白质2；钠缺项返回null。另一变体150g返回30kcal。它们不是真实食物成分结论，不供实际饮食判断。
- 导入使用 `shiwei_owner`；运行使用 `shiwei_app`，在该构造库仅授予读取权限。运行账号更新内容被真实PG以42501拒绝；没有为应用挂载管理员凭证。
- 配置/连接串存于Git忽略且已有ACL保护的 `.local-data/deployment/`。本阶段运行方式为本机Node24/Fastify读取Docker中的PG，旧应用Docker镜像未重建，不宣称旧镜像已包含本轮代码。

## 3. 读取、发布与回退行为

`backend/src/content-repository.ts` 从食材、别名、营养、成分关系、菜谱、变体、配料、步骤及来源表读取数据；`public_releases.manifest` 仅保存现有表未单列的格式标识、类别确认范围、图片类别/标准份数等元数据，没有把整份业务内容塞入JSON替代关系表，也没有新增DDL。

导入在单个专用连接的事务内写入草稿并回读校验。检查主料一致、关联对象、用量/单位/形态、步骤、营养来源和重复记录等；规范化内容hash绑定食材、变体、营养、步骤和展示元数据。发布重新校验后原子修改食材/菜谱/变体及版本状态；来源失效或中途SQL错误不留下半发布内容。

每个业务请求在可重复读事务中获得同一版本快照；计算在事务外完成，返回前另查当前发布/来源/撤回状态。不同请求使用独立上下文，不替换全局食物索引。数据库模式下，连接、内容或校验失败均返回错误，不回退内存菜谱。

版本由 `CONTENT_RELEASE_ID` 显式指定，不用最新时间自动选版。切换到B后可以重启选择仍有效的A；撤回B会留下 `catalog-release:B` 撤回记录，即使把旧发布状态改回published也不能重新读取。来源撤回也会阻断读取。此撤回记录位于同一业务库，**不是**已经完成的独立最新清除日志或完整灾备防复活方案。

本轮导入器只生成/导入项目内构造包。表中approved是本地测试状态，不代表正式内容许可或专业审核通过。多来源裁决、模糊别名消歧、复杂类别/替代关系和正式审核发布工具仍缺；当前未支持的关系会拒绝读取，不猜测其语义。

## 4. 错误处理验收

| 情况 | 已验证行为 |
| --- | --- |
| 无所选版本、仅草稿、空内容 | 503；进程/结构探针成功不冒充业务就绪，页面提供重读入口 |
| 内容被篡改、步骤不完整、营养记录冲突 | 拒绝发布/读取，不拼凑部分目录作为成功结果 |
| 来源或版本撤回 | 拒绝读取/重发；计算途中撤回只发错误终态 |
| 候选少于六道/自定义目标不足 | 如实返回已核验结果及targetMet=false，不重复父菜谱或生成目录外菜 |
| 确实无候选 | no_results与complete；搜索预算耗尽仍为incomplete，不冒充无解 |
| 数据库连接池失效 | 503与稳定错误码，不暴露驱动细节/连接串 |
| 流式计算后数据库检查失败 | 进度后仅一个error终态，不发送成功结果 |
| 页面首次读目录失败/推荐请求失败 | 不显示源码备用结果；已有本机草稿/输入保留，可主动重试 |
| 版本或游标过期 | 409，提示刷新/重新生成，不自动重复推荐或模型调用 |

## 6. 本机使用与复现

在仓库根目录、Docker已启动时执行：

```powershell
.\scripts\run.ps1 build
.\scripts\business-local.ps1 -Task Prepare
.\scripts\business-local.ps1 -Task Start
```

打开 http://127.0.0.1:4180/ ，可输入“构造角瓜200g”或手动添加“构造角瓜”。Prepare重复执行保留原版本内容；已有版本不能被新导入覆盖。Start默认不开测试登录、模型或健康。终端中Ctrl+C停止应用，数据库和卷保留。

需要演练新构造版本时：

```powershell
.\scripts\business-local.ps1 -Task Import -Release local-business-v2
.\scripts\business-local.ps1 -Task Publish -Release local-business-v2
# 先停止旧应用，再显式选择版本启动；回退时选仍有效的v1。
.\scripts\business-local.ps1 -Task Start -Release local-business-v2
# 撤回指定构造版本，不删除其表或记录；不会自动选另一版本。
.\scripts\business-local.ps1 -Task Withdraw -Release local-business-v2
```

本轮持久库实际只发布了v1；上述v2命令为复现入口，A→B→A和撤回行为已在隔离真实PG测试中执行。

```powershell
.\scripts\run.ps1 test
$env:RUN_BUSINESS_POSTGRES_TESTS='1'
$env:ACCEPTANCE_DIR='acceptance/business-chain-recheck'
.\scripts\run.ps1 test:business:postgres
$env:BUSINESS_BROWSER='1'
.\scripts\run.ps1 test:business:e2e
```

业务浏览器配置使用4181端口，测试完成自动停应用；构造模式32项回归本轮另用4182端口。重跑测试不会访问CloudBase或调用模型。

## 7. 尚未完成与可以推迟的优化

仍未接通：正式菜谱/食材/营养资料的许可审核、通用导入/审核工具和质量治理；真实图片/模型、真实认证/跨设备同步/凭证生命周期；经审核的健康规则；独立最新撤销日志及全系统恢复；云应用和公开入口。本阶段暂停云部署、空结构和备份扩展，这些未完成项保留。

可以推迟：快照缓存与失效优化、批量写入、SQL全文/语义检索、向量索引评测、较大内容库压测及管理后台。当前读取整版小型构造目录后在既有引擎计算，没有证明大数据量性能或正式服务容量。

本轮验收结论仅为：**数据库提供构造内容的本地业务闭环可用；正式资料、模型、身份/同步及健康能力尚未就绪。**
