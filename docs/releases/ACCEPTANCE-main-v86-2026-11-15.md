# main-v86：花椰菜别名 + 未识别文案区分

2026-11-15。匹配别名与前端提示，未改内容版本（仍 `gallery-listed-foods-1000-20261114-v3`）。

## 现场

用户上传一张食材图，识别出 10 项：西红柿、樱桃番茄、牛肉、大蒜、花椰菜、生菜、干辣椒、洋葱、迷迭香、莳萝。加入清单后 `迷迭香`、`莳萝` 显示"请确认具体食材"。

逐项核对目录：

| 名称 | 目录直有 | 解析结果 |
|---|---|---|
| 西红柿 / 樱桃番茄 / 牛肉 / 大蒜 / 生菜 / 干辣椒 / 洋葱 | 是/同义 | 正常绑定 |
| 花椰菜 | 否 | **原本未识别**——库里是 `花菜`/`菜花`，缺别名 |
| 迷迭香 / 莳萝 | 否 | 未识别——**1000 道菜谱里确实没有这两种香草** |

所以是两类问题：一个是我们的别名缺口，一个是内容缺口。识别本身没错。

## 修改

1. `花椰菜` 并入花菜家族（`inputs`/`recipeNames` 增加 `花椰菜`）。
2. 顺带修一个既有误匹配：西兰花在目录里的别名是 `绿花菜`，含"花菜"两字，导致 `花菜`/`菜花` 会匹配到西兰花。花菜家族排除 `绿花菜`。
3. 未识别项的文案区分两种情况：
   - 有候选 → "请确认具体食材；确认后参与推荐"（不变）；
   - 无候选 → "现有菜谱暂未使用「迷迭香」，可移除或换个名称"。

第 3 点是为了不再让用户以为识别错了——实际是菜谱里没有这个东西。

## 未做

`迷迭香`、`莳萝` 没有加入目录。目录等于"菜谱里出现过的食材"，为它们单独造条目会制造永远匹配不到的空转食材。要支持它们，应该是在菜谱内容侧引入使用这些香草的菜，而不是改匹配表。
