# main-v85：图片识别为什么不需要重做接入

2026-11-14。仅匹配别名，未改内容版本（仍 `gallery-listed-foods-1000-20261114-v3`）。

## 结论

图片识别**已经和手打走同一条解析链路**，不是"未经限制直接把模型输出塞进食材"。

`backend/src/image-recognition.ts:42` 对每个识别出的名称执行 `resolvePantryFood(name, context.foodById)`：

- 解析成功 → 绑定目录食材，`status:'pending'`；
- 解析失败 → `foodId:null`，前端渲染为**可编辑行**，提示"请确认具体食材；确认后参与推荐"，并给出候选 chip；
- 匹配只认 `status==='confirmed'`，所以未识别的词**不会**伪造"我有"或"我缺"。

## 召回率（离线抽样，未调用模型）

用 166 个视觉模型常见输出词（蔬菜/肉/蛋/菌菇/调味料）跑 `resolvePantryFood`：

- 直接解析 **155 / 166 = 93%**；
- 未解析 11 个：`银耳 面条 米饭 核桃 奶酪 梨 草莓 芒果 牛肉丸 鸡蛋液 红糖`。

其中除 `鸡蛋液` 外，全部是**1000 道菜谱里没有出现过的食材**——按"以菜品食材为基准"的原则，它们即使被处理也无法用于推荐，落在待确认是正确行为。

本轮把 `鸡蛋液/鸡蛋清/鸡蛋黄` 补进蛋类别名（模型高频输出），`鸡蛋液` 现在解析为 `鸡蛋`。

## 判断：不需要重做接入

真正的成本不是"名字不一致导致推荐错"，而是"少数未识别项要用户点一下确认"。这属于 UX 打磨，不是数据链路缺陷。若以后识别率成为瓶颈，优先做的是**批量确认**，而不是放宽匹配。
