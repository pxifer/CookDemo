# main-v69：单菜理由按“已接受食材选择”判定；食材细分类

2026-11-14 00:2x 更新既有 CloudBase HTTP 函数成功。函数超时 60 秒。

## 1. 为什么会出现“无法判定”

用户接受 AI 给出的“优先/少选食材”后，程序确实把它们用于排序与排除，但**单菜理由**只读取了疾病/目标知识绑定；当这些主题没有可绑定到具体菜谱的知识时，就退回“暂时没有足够资料判断这道菜是否适合你”。用户明明已经做了选择，却看不到判断依据。

v69 改为：

- 单菜理由优先匹配用户接受的食材：
  - 含优先食材 → “含你优先选择的鸡蛋。”
  - 含少选食材 → “含你选择少选的油炸食品。”
  - 有接受记录但本菜未命中 → “没有命中你标记的优先或较少食材。”
- 只有在既没有知识依据、也没有接受记录时，才显示“暂时没有足够资料判断……”。
- 结果说明继续保留“已参考你接受的食材选择”。

注意：这不把“优先食材”变成硬性必含；它是判断/排序依据，硬排除仍只对“排除”项生效。

## 2. 食材下拉细分类

仍只列 1000 道已发布菜谱中真实作为主料/辅料使用的食材，但不再把一整列具体物种堆在“鱼虾海鲜/肉禽”下：

- 肉禽 → 猪肉、牛肉、羊肉、禽肉、其他肉类
- 鱼虾海鲜 → 鱼类、虾类、蟹类、贝类、其他海鲜
- 蔬菜 → 叶菜与花菜、瓜茄类、根茎类、其他蔬菜
- 主食杂粮 → 米面、杂粮
- 其余：蛋类、菌菇、豆制品、奶类、水果、豆类坚果、其他食材

腌料/调味料仍不进入食材下拉；手动输入保留。
