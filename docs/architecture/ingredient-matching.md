# 用户输入处理总纲

从"用户填了什么"到"能不能用来选菜"的完整规则。覆盖食材、忌口、人数、调料、补买、口味等全部输入，以及食材的分类体系。
适用版本：v75–v86；内容 `gallery-listed-foods-1000-20261114-v3`。

## 1. 三条总原则

1. **目录是唯一基准。** 菜谱里没出现过的食材不参与推荐，也不为它造目录条目。
2. **只核有无，不比数量。** 用户填写的用量在进入推荐前被剥离；菜谱原用量只用于做饭参考。
3. **认不出就不算。** 未识别的输入保持"待确认"，不伪造"我有"或"我缺"。

## 2. 输入面

| 输入 | 入口 | 是否影响选菜 |
|---|---|---|
| 食材 | 下拉选择 / 文字输入 / 图片识别 | 是（仅 `confirmed` 项） |
| 忌口、过敏 | 文字输入 + 常见项快捷添加 | 是（硬限制） |
| 人数 | 1–12 | 只影响自动菜数，不影响配方量 |
| 调料库存 | 开关 + 清单（默认不查） | 开启后按有无检查 |
| 本餐补买 | 开关（默认关闭） | 开启后允许缺料出餐 |
| 口味 | 预设口味 / 单菜覆盖 | 只影响目标菜，不改其他菜 |
| 自定义菜数 | 各类 0 表示不需要，合计 1–20 | 只影响出餐数量 |
| 健康档案 | 健康模式 | 叠加饮食限制（另见健康文档） |

食材上限 100 种；人数与食材不写入个人默认，只在本次使用。

## 3. 食材名称处理管线

| 步骤 | 规则 | 例子 |
|---|---|---|
| ① 采集 | 下拉给目录条目；文字/图片给名称串 | `肉丝 200g`、`西红柿` |
| ② 清洗 | 去用量与单位、去括号注释、去做法尾注 | `五花肉 200克（切块）` → `五花肉` |
| ③ 归并 | 同义词组 → 宽食材家族 → 名称包含 | `圆葱`→`洋葱`；`二刀肉`→猪肉族 |
| ④ 绑定 | 命中目录 → 绑定食物 ID；否则为空 | `迷迭香` → 无 |
| ⑤ 确认 | 命中即 `confirmed`；未命中 `pending` | 只有 `confirmed` 参与匹配 |
| ⑥ 再剥离 | 进入推荐前清空用量、数量单位、基准 | 改数量不触发重新请求 |

步骤 ③ 的顺序决定了"宽词能不能覆盖具体词"；步骤 ⑤ 决定了"认不出的词会不会污染结果"。

## 4. 食材分类体系

### 4.1 下拉导航（11 组）

肉禽、鱼虾海鲜、蛋类、蔬菜、菌菇、豆制品、主食杂粮、奶类、水果、豆类坚果、其他食材。

判定顺序：人工覆盖表 → 显式例外（如 `米醋`/`酱油` 归调味料、`牛油果` 归水果、`牛百叶` 归肉禽）→ 关键词匹配。这是一个**导航归类**，不代表营养或过敏分类。

### 4.2 宽食材家族（18 个，用于匹配与折叠）

猪肉、牛肉、鸡肉、鸭肉、鹅肉、羊肉、鱼、虾、蟹、贝类、鸡蛋、粉条、蘑菇、豆腐、白菜、青椒、西兰花、花菜。

- 家族只在"你有的能不能覆盖这道菜的配料"时使用，命中一律记为 `unverified`（不证明部位、形态、数量）。
- 下拉折叠到家族名的**前提是该家族确实能匹配它**，否则部位保留为独立条目（详见 4.4）。

### 4.3 调料与水

| 分层 | 内容 |
|---|---|
| 库存快捷组（4） | 油盐酱醋、葱姜蒜与辣味、香辛料、勾芡与提鲜 |
| 设置面板分组（8） | 酱料与调味汁、醋与酒、糖与甜味、盐与基础调味、鲜味与勾芡、油与脂、香辛料与葱姜蒜、其他调料 |
| 水 | 清水/开水/热水/冰水等不入库存，不参与检查 |
| 葱姜蒜 | 库存键合并为姜/蒜/葱，避免 `姜片`、`姜末` 各算一项 |
| 调料库存 | 默认不查；开启后只查有无，默认视为有 油/盐/生抽/蒜（可增减）。牛奶、面粉等即使原文写在调料段也要照常查 |

### 4.4 归并与不归并

| 情况 | 处理 |
|---|---|
| 部位肉 → 大类 | `二刀肉/梅头肉/通脊/肉片` 归猪肉，可覆盖 `猪里脊` |
| 内脏、骨、蹄、皮、油、腊制品 | **不归**猪肉（分开采购）。`排骨/猪肝/猪蹄/猪皮/猪油/腊肉/咸五花肉` 保持独立 |
| `羊排/鸡排/牛排` | 算肉（部位肉，不是排骨） |
| 蛋类 | `蛋液/蛋清/蛋黄/鸡蛋液` 归鸡蛋；`皮蛋/咸鸭蛋/鹌鹑蛋` 独立 |
| `花椰菜` | 归花菜；`绿花菜`（西兰花别名）排除，避免串类 |
| 调味汁与加工品 | `蚝油/鸡汁/虾油/鸡蛋干/火腿肠` 不折叠进肉类或蔬菜 |
| 名称像数量的真实食材 | `千张` 白名单保护，不当成"千+张"删除 |
| 裸单位 | `g/ml/瓣/克` 判为非法名，不进食材也不进下拉 |

### 4.5 映射规模

| 项 | 数值 | 说明 |
|---|---|---|
| 目录食材 | 1106 个 | 全部至少被一道菜使用，无空转条目 |
| 作为主料出现过的 | 696 个 | 其余是调料或辅料 |

## 6. 食材以外的输入

| 输入 | 处理 | 边界 |
|---|---|---|
| 忌口 / 过敏 | 解析成限制项，需用户确认目标食物 | 未知或冲突时暂停相关推荐；不猜来源 |
| 人数 | 1–12，自动菜数按人参考 | 不改配方量、不改库存判断 |
| 补买 | 默认关闭；关闭时缺必需食材即排除 | 开启后每道菜至少复用一种现有主料，盐油不充数 |
| 口味 | 只更新目标卡，保留其他菜与滚动位置 | 不改整桌条件 |
| 草稿恢复 | 恢复时丢弃输入用量，同名食材合并 | 不因旧数量冲突阻断 |

## 7. 拒绝与降级

| 情况 | 行为 |
|---|---|
| 名称认不出 | 可编辑行 + 候选 chip，`pending`，不参与推荐 |
| 认不出且无候选 | 提示"现有菜谱暂未使用「X」"，可移除或换名 |
| 只有一个宽词（`生肉`、`干果`） | 不自动选具体食材，要求用户挑一个 |
| 食材超过 100 种 | 阻止添加并提示先移除 |
| 只改用量 | 不清空结果、不新增请求 |
| 菜谱暂不可用 | 保留用户输入，报内容未就绪（不静默回退） |

## 9. 不做的事

- 不按用户填写的量判断"够不够"，也不把全天限量除成每餐阈值。
- 不把部位、品种、加工形态当成可互换（除 4.4 列出的明确归并）。
- 不跨物种匹配（猪肉不覆盖牛肉），不把调味汁当成食材。
- 不为了匹配而给目录加"没有任何菜谱使用"的食材。
- 手打比下拉更具体时不放大：`香菇` 只算香菇，不覆盖金针菇。
