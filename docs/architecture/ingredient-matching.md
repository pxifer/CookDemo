# 用户输入 → 食材匹配

记录"用户说自己有什么"到"能不能用来选菜"这一段的处理规则与验证范围。
适用版本：v75–v86（内容 `gallery-listed-foods-1000-20261114-v3`）。

## 1. 一句话结论

**目录（菜谱里出现过的食材）是唯一基准。** 下拉、手打、图片识别三条入口都用同一套解析落到目录食材上；解析不到的一律不参与推荐。

## 2. 数据基准

| 项 | 数值 | 说明 |
|---|---|---|
| 菜谱 | 1000 道 / 1004 个口味版本 | 341 道基础 + 659 道扩展 |
| 目录食材 | **1106** 个 | 全部至少被一道菜使用（0 个空转） |
| 作为主料出现过的 | 696 个 | 其余是调料/辅料 |
| 归并到大类的 | 271 个 → 31 个大类名 | 例如 五花肉→猪肉、千张→豆腐 |
| 下拉可见条目 | 463 项 / 11 个分组 | 调料与水不进入下拉 |

"目录食材全部被菜谱使用"是构建期反推出来的，不是巧合；因此没有"选了但永远匹配不到"的条目。

## 3. 三条入口，一套解析

| 入口 | 处理 | 解析失败时 |
|---|---|---|
| 下拉选择 | 直接绑定目录食材 | — |
| 文字输入 | `resolvePantryFood`：精确名 → 别名 → 同义词组 → 大类 → 名称包含 | 可编辑行 + 候选 chip，`status=pending` |
| 图片识别 | 模型返回名称数组，**逐个**走同一个 `resolvePantryFood` | 同上，并标注"现有菜谱暂未使用" |

匹配只认 `status === 'confirmed'`。所以未解析的词既不会伪造"我有"，也不会伪造"我缺"。

## 4. 大类匹配

18 个家族（猪肉/牛肉/鸡肉/鸭/鹅/羊/鱼/虾/蟹/贝类/鸡蛋/粉条/蘑菇/豆腐/白菜/青椒/西兰花/花菜）。家族匹配只用于"你有的东西能不能覆盖这道菜的配料"，**不证明部位、形态或数量够用**——命中一律记为 `unverified`。

### 4.1 肉类的判定：只有肌肉部位算"肉"

| 输入「猪肉」 | 命中 | 不命中 |
|---|---|---|
| 部位肉 | 二刀肉、梅头肉、通脊肉、五花肉、猪颊肉、前腿肉、肉片/肉丝/肉末 | — |
| 内脏 | — | 猪肝、猪腰、猪肚、猪大肠、猪血 |
| 骨/蹄/皮/油 | — | 排骨、猪小排、筒子骨、猪蹄、猪尾巴、猪皮、猪油 |
| 加工品 | — | 腊肉、咸五花肉、火腿肠、肉丸 |

理由：这些是分开采购的东西。反向同理——有猪肝不等于有猪肉。
同一规则用于牛/鸡/鸭/鹅/羊；`羊排`、`鸡排`、`牛排` 仍算肉（是部位肉，不是排骨）。

### 4.2 蛋类

`鸡蛋` 覆盖 `蛋液/蛋清/蛋黄/鸡蛋液`；`皮蛋/咸鸭蛋/鹌鹑蛋/鸽子蛋` 各自独立。

### 4.3 展示与匹配同口径

下拉会把部位折叠成大类别名，**折叠的前提是匹配确实覆盖**：`canonicalIngredientName` 与 `matchNames` 共用判定。否则用户会看到"猪肉"却选不到"排骨"。

## 6. 图片识别后的处理

1. 模型只输出食材名数组（不含数量、单位），非食材返回空。
2. 每个名字走 `resolvePantryFood`：命中即绑定，未命中标记待确认。
3. 前端对未识别项给出两种文案：
   - 有候选 → "请确认具体食材；确认后参与推荐"
   - 无候选 → "现有菜谱暂未使用「迷迭香」，可移除或换个名称"
4. 未确认项不参与推荐。

## 7. 特殊处理

| 情况 | 处理 |
|---|---|
| 裸单位 `g / ml / 瓣 / 克` 成为食材名 | 判定为非法名，不进入食材与下拉 |
| 用量词混进名字（`菠菜 几颗`） | 构建期从用量字段剥离，展示文本保留原量 |
| 名称看起来像数量（`千张`） | 白名单保护，不当成"千+张"删除 |
| `花椰菜` | 并入花菜家族（库内是 花菜/菜花） |
| `绿花菜`（西兰花别名） | 花菜家族排除，避免"花菜"误匹配西兰花 |
| `杏鲍菇` / `鲍鱼` | 分别归蘑菇 / 贝类，不让"鲍""鱼"串类 |
| 调味汁（蚝油/鸡汁/虾油）、加工品（鸡蛋干/火腿肠） | 不折叠进肉类或蔬菜大类 |
| 同义词头名 | 必须是目录里真实存在的名字，否则折叠后选不到（曾出现 洋白菜/小西红柿） |
| 手打比下拉更具体（`香菇`） | **不放大**，只算香菇，不覆盖金针菇 |

## 9. 已知边界

- 命中是"算同一种食材"，**不证明部位、形态、数量够用**，一律 `unverified`。
- 图片识别只解决"名字对不对得上目录"，不保证识别本身准确（本节未做真实模型测评）。
- 目录里没有的食材（如迷迭香、莳萝）不会为匹配而硬加条目——只能从菜谱内容侧引入。
- 少数同名配料重复行（如两道盐）未处理。
