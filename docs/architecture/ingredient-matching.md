# 用户输入 → 食材处理

记录用户从输入端填的东西，如何变成可用的选菜条件；以及食材的分类体系。
适用版本：v75–v86（内容 `gallery-listed-foods-1000-20261114-v3`）。

## 1. 一句话结论

**目录（菜谱里出现过的食材）是唯一基准。** 下拉、手打、图片识别三条入口都用同一套解析落到目录食材上；解析不到的一律不参与推荐。

## 2. 数据基准

| 项 | 数值 | 说明 |
|---|---|---|
| 菜谱 | 1000 道 / 1004 个口味版本 | 341 道基础 + 659 道扩展 |
| 目录食材 | **1106** 个 | 全部至少被一道菜使用（0 个空转） |
| 作为主料出现过的 | 696 个 | 其余是调料/辅料 |
| 归并到大类的 | 271 个 → 31 个大类名 | 例如 五花肉→猪肉、千张→豆腐 |
| 下拉可见条目 | 463 项 / 11 个分组 | 调料与水不进入下拉 |

"目录食材全部被菜谱使用"是构建期反推出来的，不是巧合；因此没有"选了但永远匹配不到"的条目。

## 3. 输入面

| 输入 | 入口 | 影响 |
|---|---|---|
| 食材 | 下拉 / 文字 / 图片识别 | 是（仅 `confirmed` 项） |
| 忌口、过敏 | 文字 + 常见项快捷添加 | 是（硬限制） |
| 人数 | 1–12 | 只影响自动菜数 |
| 调料库存 | 开关 + 清单（默认不查） | 开启后查有无 |
| 本餐补买 | 开关（默认关闭） | 决定缺料能否出餐 |
| 口味 | 预设 / 单菜覆盖 | 只改目标菜 |
| 自定义菜数 | 各类 0 表示不需要，合计 1–20 | 只影响出餐数量 |

食材上限 100 种；人数、食材、补买不写入个人默认。

## 4. 名称处理管线

| 步骤 | 规则 | 例子 |
|---|---|---|
| 采集 | 下拉给目录条目；文字/图片给名称串 | `肉丝 200g` |
| 清洗 | 去用量单位、去括号注释、去做法尾注 | `五花肉 200克（切块）` → `五花肉` |
| 归并 | 同义词组 → 宽食材家族 → 名称包含 | `圆葱`→`洋葱` |
| 绑定 | 命中目录给食物 ID，否则为空 | `迷迭香` → 无 |
| 确认 | 命中 `confirmed`，未命中 `pending` | 只有 confirmed 参与匹配 |
| 再剥离 | 进推荐前清空用量与数量单位 | 改量不触发新请求 |

## 5. 分类体系

### 5.1 下拉导航（11 组）

肉禽、鱼虾海鲜、蛋类、蔬菜、菌菇、豆制品、主食杂粮、奶类、水果、豆类坚果、其他食材。

判定顺序：人工覆盖表 → 显式例外（`米醋`/`酱油` 归调味料、`牛油果` 归水果、`牛百叶` 归肉禽）→ 关键词匹配。这是导航归类，不代表营养或过敏分类。

### 5.2 匹配大类（18 个家族）

猪肉、牛肉、鸡肉、鸭肉、鹅肉、羊肉、鱼、虾、蟹、贝类、鸡蛋、粉条、蘑菇、豆腐、白菜、青椒、西兰花、花菜。

家族只用于判断"你有的能不能覆盖这道菜的配料"，命中一律记为 `unverified`——不证明部位、形态或数量够用。

### 5.3 肉类的判定：只有肌肉部位算"肉"

| 输入「猪肉」 | 命中 | 不命中 |
|---|---|---|
| 部位肉 | 二刀肉、梅头肉、通脊肉、五花肉、肉片/肉丝/肉末 | — |
| 内脏 | — | 猪肝、猪腰、猪肚、猪大肠、猪血 |
| 骨/蹄/皮/油 | — | 排骨、猪小排、筒子骨、猪蹄、猪皮、猪油 |
| 加工品 | — | 腊肉、咸五花肉、火腿肠、肉丸 |

理由：这些是分开采购的东西，反向同理。同一规则用于牛/鸡/鸭/鹅/羊；`羊排`、`鸡排`、`牛排` 仍算肉。

### 5.4 蛋类与同口径

`鸡蛋` 覆盖 `蛋液/蛋清/蛋黄/鸡蛋液`；`皮蛋/咸鸭蛋/鹌鹑蛋/鸽子蛋` 各自独立。

下拉把部位折叠成大类别名，**折叠的前提是匹配确实覆盖**（`canonicalIngredientName` 与 `matchNames` 共用判定），否则用户会看到"猪肉"却选不到"排骨"。

### 5.5 调料与水

| 分层 | 内容 |
|---|---|
| 库存快捷组（4） | 油盐酱醋、葱姜蒜与辣味、香辛料、勾芡与提鲜 |
| 设置面板分组（8） | 酱料与调味汁、醋与酒、糖与甜味、盐与基础调味、鲜味与勾芡、油与脂、香辛料与葱姜蒜、其他调料 |
| 水 | 清水/开水/热水/冰水等不入库存 |
| 葱姜蒜 | 库存键合并为姜/蒜/葱 |
| 默认库存 | 开启调料检查时视为有 油/盐/生抽/蒜，可增减 |

牛奶、面粉等即使原文写在调料段，也照常按食材查库存。

### 5.6 刻意不归并

`青椒↔红椒`、`大白菜↔小白菜`、`大葱↔小葱`、`猪肉↔排骨`、`香菇↔金针菇`——相近但属于不同商品，合并会让"有 A"错误覆盖"要 B"的菜。

## 7. 图片识别

模型只返回名称数组（不含数量、单位），每个名字走同一套解析；未命中的标待确认，不参与推荐。前端两种情况分开提示：有候选说"请确认具体食材"，无候选说"现有菜谱暂未使用 X，可移除或换名"。

## 8. 非食材输入

| 输入 | 规则 | 边界 |
|---|---|---|
| 忌口 / 过敏 | 解析成限制项，需确认目标食物 | 未知或冲突时暂停相关推荐 |
| 人数 | 1–12，按人参考菜数 | 不改配方量与库存判断 |
| 补买 | 默认关闭；关闭时缺必需食材即排除 | 开启后每道菜至少复用一种现有主料，盐油不充数 |
| 口味 | 只更新目标卡 | 不改整桌条件 |
| 草稿恢复 | 丢弃输入用量，同名食材合并 | 不因旧数量冲突阻断 |

## 9. 拒绝与降级

| 情况 | 行为 |
|---|---|
| 认不出 | 可编辑行 + 候选，`pending`，不参与推荐 |
| 认不出且无候选 | 提示"现有菜谱暂未使用 X" |
| 只有一个宽词（`生肉`、`干果`） | 不自动选具体食材，要求用户挑 |
| 食材超过 100 种 | 阻止添加并提示先移除 |
| 只改用量 | 不清空结果、不新增请求 |
| 菜谱暂不可用 | 保留输入，报内容未就绪 |
