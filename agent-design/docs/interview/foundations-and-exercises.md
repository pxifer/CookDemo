# 理论、公式、代码练习与追问路线

本页是理解和练习，不表示项目已经实现所有算法，也不表示读者已经亲手完成练习。问答卡负责口述，[参数总表](../rag-parameters-and-chunking.md)负责当前实现值。

## 1. 从模型基础讲到项目参数

| 概念 | 简明解释 | 与项目的关系/常见误解 |
| --- | --- | --- |
| Token与自回归 | tokenizer把文本转ID；生成模型逐步预测后续token | 中文字符不等于token。Embedding tokenizer计数、应用估算与DeepSeek usage分开 |
| Attention | softmax(QKᵀ/√d)对V加权；mask约束可见位置 | 长上下文可表达关联，但模型未必利用好每条限定；检索与完整证据仍有价值 |
| Embedding | 文本映射固定维数表示，bi-encoder可预先计算文档 | 检索快且可缓存；不直接证明否定、人群或证据支持 |
| Cross-Encoder | 问题与每条候选一起编码打相关分 | 比独立向量更能交互，代价随候选数增加；本项目未接入 |
| Prefill/Decode | 先处理输入，再逐token生成；TTFT与总输出时长不同 | 当前不展示模型逐token流，应用NDJSON进度另算 |
| KV Cache | 为解码复用attention的key/value | 不是个人健康长期记忆；Prompt Cache是前缀计算复用，命中条件看供应商，不等于业务结果缓存 |
| temperature/top_p | 前者改变logit分布尖锐程度，后者保留累计概率候选 | 低温不保证事实正确或完全确定；当前请求未显式设置二者 |
| SFT/LoRA/DPO | SFT学示范，LoRA低秩适配参数，DPO学偏好 | 与检索更新知识是不同维度；项目未微调，不能拿这些名词解释来源撤回 |

理论来源：[Attention原论文](https://arxiv.org/abs/1706.03762)、[LoRA](https://arxiv.org/abs/2106.09685)、[DPO](https://arxiv.org/abs/2305.18290)、[BGE reranker模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)。以上是概念解释，不是本项目训练或质量实验。

### 与AI服务有关的后端基础

| 追问 | 作用与项目对照 |
| --- | --- |
| URL到响应 | 一般包括URL解析、DNS、TCP/TLS、HTTP、服务路由、认证、数据读取与响应渲染；127.0.0.1本地HTTP没有公网DNS/TLS阶段。本站先过Fastify身份/同源与输入门禁，再进入业务，不能一上来就调用模型 |
| 进程、线程、协程 | 进程有隔离地址空间，线程共享进程资源，协程/异步用于协作等待；共享对象要防跨请求串号。Node异步网络等待不等于CPU任务并行，Python模型运行时是独立进程 |
| Python GIL | 当前Python3.11中同进程Python字节码执行受GIL限制；原生扩展可能释放GIL并使用自己的线程。Torch CPU线程数与Web请求并发不是同一个设置，不能简单说“Python多线程完全无用” |
| 事务与CAS | 短事务/行锁约束共享认领；CAS检查版本防覆盖新档案。数据库事务不跨供应商等待；死锁/超时和业务版本冲突分别处理 |
| Cookie/Session/Key | Cookie是浏览器携带数据的机制，Session是服务端身份状态，个人模型Key是外部凭证；三者不能互当。模型不从用户文字获取UID/权限，日志不能记录凭证 |
| 工具目录与内容索引 | 索引保存ID/位置/版本等定位关系，按需取内容可减少上下文膨胀；不是把整个库复制进会话缓存。当前facts/evidence及候选关联已分层，动态工具索引未实现 |

GIL解释依据[Python3.11 threading文档](https://docs.python.org/3.11/library/threading.html)；不外推到未来或free-threaded构建。

## 2. 把RRF和分数标定讲明白

```text
RRF(f) = Σ通道 w通道 / (c + rank通道(f))
rank从1开始；缺席贡献0；当前研究外层w_A1=2、w_dense=1、c=60。
A1内部还把实体路、词面路等权融合；两层不要混为一次。
```

RRF解决**不同检索分数不在同一量纲**的问题，使用名次较容易组合。它损失绝对分差信息，不能识别事实真假或自动消除偏题。c大时相邻头部差距更平；不是“c大就更重视第一名”。对A1第1、dense第10的同一事实，当前外层是 `2/61+1/70≈0.047073`；等权才是 `1/61+1/70≈0.030679`。

替代方案是将分数归一化/校准后加权、学习排序或cross-encoder；需要足够标注和跨版本稳定性。min-max受候选极值影响，z-score依赖分布；不能仅因为麻烦就断言都比RRF差。[RRF原论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)是方法依据，其数据集不替本项目证明60最优。

## 3. 切块追问必须落到数据

1. **先答真实算法**：冻结证据是脚本指定起止原文锚点，没有固定512/overlap；新增结构块未接入索引。
2. **再给实测长度**：98条retrievalText Qwen token为最小24/P50 68/P95 130/最大339，BGE为27/73/137/306。原文最短7字符只是表号级锚点，长度短不表示精确。
3. **解释语义单元**：声明＋对象＋人群/否定/例外/单位，表格需表头和脚注。长度约束不能优先切断限定。
4. **解释未来候选**：结构段落＋128/256/512 token上限，overlap 0/32/64，父子块；这是对照范围，尚无胜者。
5. **闭环检查**：比较召回只是中间指标；还看实际注入支持、条件完整、理由及本餐硬限制。

## 4. 三个离线练习

执行 `python agent-design/docs/interview/exercises.py`，只用标准库、构造ID和内存数据，不读取Key、数据库或个人资料，不发网络请求。输出是**教学微型数据结果，不是项目27题新评测**。可让读者先遮住实现亲手写，再对照。

### 练习A：手写RRF

输入两路排名：A1=`A,B`，dense=`C,B,A`。实现：每通道去重→按1起始排名累加→缺席0→按分降序、ID稳定破同分。支持权重与c；先验证参数有限且正值。不要对同一通道的重复ID多次投票。

### 练习B：亲手跑最小对照并手算

构造两个问题，完整相关集分别为`{A}`、`{B}`。给定各模式的排名，计算Recall@2、MRR；本例三个模式均值相同，但逐题排序不同，可修改排名观察变化。**不能拿教学结果证明项目混合有效**。真实对照要读冻结数据、禁止gold泄漏、保存版本与每题结果。

### 练习C：修JSON边界

测试正常JSON、围栏JSON、截断JSON、重复键和“结构正确但目录外ID”。演示解析层拒绝非JSON和重复键；之后验证结构、ID及去重。不要用 `\{.*\}` 抽取任意第一/最后大括号，也不要修补半条付费响应后假装完整成功。

当前项目采用严格JSON与完整终态门禁，并非用本练习Python代码处理线上输出。若未来允许外层代码围栏，必须显式限定完整唯一围栏、保留原文和解析状态，业务复核仍不能省略。

### 额外场景：小模型压缩与大量工具

小模型做摘要可能便宜、快，但并非天然不会丢健康条件；先用结构化限制表保存不可变约束，再比较不同模型的保留率、纠错和成本。当前没有小模型摘要服务。工具过多可先按任务与权限检索工具目录，再注入少量相关Schema；返回数据用字段选择、分页或受控引用读取，不能靠模型自行丢掉单位/限定。当前也没有动态工具检索平台。

同一个资料的排名不是永久固定：相同索引、同一query向量和排序规则下精确距离可复算；问题、规范化、条件、知识/模型版本变化会改变距离或资格。不能为让某条“权威资料”每次第一而固定加分，先确定它是否真的支持当前任务。

## 5. 一条完整追问路线

“为什么RAG？”→“为什么不是全文？”→“资料怎么提取？”→“块多大、为什么？”→“向量模型和版本？”→“A1是不是BM25？”→“RRF的60怎么定？”→“重排启用了吗？”→“最终k和预算？”→“证据真能支持这道菜吗？”→“错引用怎么拦？”→“实验有泄漏吗？”→“线上边界和个人贡献？”

回答时始终回到三件事：**实际数据如何流动、哪个约束由哪段程序执行、结论由什么证据支持**。框架、协议、GraphRAG或多Agent只在追问到扩展时解释，不装成项目已经部署。
