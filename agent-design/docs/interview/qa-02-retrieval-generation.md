<a id="q016"></a>
### Q016 · 为什么不只用向量，暴露了什么问题？

状态：**研究有实测；业务未用dense**

- **口述**：向量接近可能只是同一疾病、相似措辞，未必支持当前对象或动作。早期少盐问题混入无关脂肪事实，说明语义相关不等于任务适用。
- **实现/参数**：目前加疾病/对象/关系类型与条件过滤，再比较研究A1、dense、hybrid；实际食谱指导按主题和显式映射取。
- **为什么/比较**：同27道调试题A1已很强，没有证明加向量更准；不能把纯向量描述成永远不可用。
- **难点/追问**：高相似的错误证据不能靠再加一句提示解决，应先定位表示、过滤和证据支持。

依据：[E06](sources-and-coverage.md#e06)、[E12](sources-and-coverage.md#e12)。

<a id="q017"></a>
### Q017 · Embedding用什么、维度多少，怎样选？

状态：**两模型真实研究对照**

- **口述**：比较了Qwen3-Embedding-0.6B和BGE-M3，均固定1024维、独立索引，各98条真实证据向量。本轮保留Qwen，BGE作更低CPU编码延迟的备选。
- **实现/参数**：同27题hybrid Recall@10均1；MRR约0.9375/0.90625，同16查询编码P95为1706/656.1ms。两模型revision、pooling和tokenizer锁定。
- **为什么/比较**：Qwen本轮排序略高、BGE更快；题已曝光用于调试，没有统计显著或全领域优越性结论，也没做维度消融。
- **难点/追问**：不能只凭模型榜单选，也不能把两种模型的同维向量放一张索引混查。

依据：[E05](sources-and-coverage.md#e05)、[E12](sources-and-coverage.md#e12)、[S02](sources-and-coverage.md#s02)。

<a id="q018"></a>
### Q018 · A1到底怎么做，是BM25或倒排索引吗？

状态：**研究基线已实现**

- **口述**：A1用NFKC、受控别名最长匹配、实体歧义/否定检查，再取中文二元组及英文数字词。对象命中加8、疾病主体加4，词面命中按长度封顶4累加。
- **实现/参数**：实体和词面分别排名后做等权RRF，c=60；外层请求最多50事实。当前没有BM25的IDF和长度归一化，也不是成熟倒排搜索服务。
- **为什么/比较**：优势是小库下对象/条件可解释；没有与真正BM25公平横评，手工权重未扫参。
- **难点/追问**：数据库预备GIN或全文字段不意味着当前应用路径就是中文BM25。

依据：[E06](sources-and-coverage.md#e06)、[E12](sources-and-coverage.md#e12)。

<a id="q019"></a>
### Q019 · 混合检索怎样互补，有没有实际收益？

状态：**研究已接通；收益未被证明**

- **口述**：词面/实体对明确术语和身份约束更直接，向量可补不同措辞下的证据。两者可能互补，但也可能一起偏题或向量引入噪声。
- **实现/参数**：A1最多50事实，dense最多30证据，后者先映射到事实ID再融合。来源有效性与适用条件不由融合分数决定。
- **为什么/比较**：已有三模式工程比较，但同题A1 Recall/MRR已为1；目前只能说向量链跑通，不能说混合胜出。
- **难点/追问**：应在口语化、歧义、无答案和偏题高相似样本上看配对变化，而不只看成功示例。

依据：[E06](sources-and-coverage.md#e06)、[E12](sources-and-coverage.md#e12)。

<a id="q020"></a>
### Q020 · RRF原理及公式中的60是什么？

状态：**研究两层RRF已实现**

- **口述**：RRF把不同通道的名次转成倒数分再求和，避开原始分数量纲不一致。一般为Σw/(c+rank)，缺席通道贡献0；c越大，头部相邻名次差距越缓。
- **实现/参数**：A1内部实体/词面等权；外层为2/(60+r_A1)+1/(60+r_dense)。60是平滑常数，不是召回数量或top-k。
- **为什么/比较**：方法有论文依据，当前2:1偏重可控A1是工程初值；没有证明本项目最优。
- **难点/追问**：融合不判断事实是否真实或条件是否适用；两路都偏题时仍会把偏题事实排高。

依据：[E06](sources-and-coverage.md#e06)、[S01](sources-and-coverage.md#s01)。

<a id="q021"></a>
### Q021 · 为什么RRF取60，做过10/60/100对比吗？

状态：**当前初值；该消融未做**

- **口述**：60沿用RRF常见平滑设置，本项目还没有10/60/100的公平对照，所以不能讲“实验证明60最好”。外层2:1也尚未调优。
- **实现/参数**：后续固定数据、知识、索引、模型、候选池和输出预算，单独改变c，再报告相关性、偏题和成本；测试集不反复挑参数。
- **为什么/比较**：实验目标是选择有证据的方案，不是预先要求60获胜；若差异小应如实保留简单配置。
- **难点/追问**：如果10更好就接受结果；不能拿不同候选数或不同题集包装K值收益。

依据：[E06](sources-and-coverage.md#e06)、[E12](sources-and-coverage.md#e12)、[E14](sources-and-coverage.md#e14)、[S01](sources-and-coverage.md#s01)。

<a id="q022"></a>
### Q022 · 为何不把向量距离和词法分数直接相加？

状态：**方法取舍，未做融合算法横评**

- **口述**：两套分数的方向、范围和分布不同，距离越小越好，手工匹配分越大越好。直接相加会让量纲主导结果，先变成排名更容易审计。
- **实现/参数**：也可做同向化、归一化和权重校准，或训练排序；RRF省去当前分数校准，但丢失原始分差。
- **为什么/比较**：这是工程理由，不是RRF击败分数加权的实测结论；比较时需固定同一候选集合。
- **难点/追问**：即使归一化到0～1，也不代表两路分数变成可比较的正确概率。

依据：[E06](sources-and-coverage.md#e06)、[S01](sources-and-coverage.md#s01)。

<a id="q023"></a>
### Q023 · A1第一、向量第十的事实怎样算分？

状态：**数学示例，非效果实验**

- **口述**：按本项目外层权重，得分为2/61+1/70≈0.04707；若用等权RRF则1/61+1/70≈0.03068。必须先讲清采用哪套权重。
- **实现/参数**：若同事实关联多条dense证据，当前取最早命中的证据名次，不重复加票；统一fact ID后再融合。
- **为什么/比较**：较高分仅表示两路排名意见，不是47%概率；示例计算没有证明排序改善。
- **难点/追问**：追问同名ID、重复候选和同分时，说明稳定ID去重、按ID破同分及0贡献规则。

依据：[E06](sources-and-coverage.md#e06)、[S01](sources-and-coverage.md#s01)。

<a id="q024"></a>
### Q024 · Top-10里出现互斥或相反结论怎么办？

状态：**冲突/限定保留，自动裁定不完整**

- **口述**：先确认是否真矛盾，还是人群、剂量、形态或工艺不同。明确不适用项排除，适用但相反的支持与限定保留，未知条件不能补齐。
- **实现/参数**：研究上下文携带冲突；业务按同对象的方向记录冲突，避开不被推荐益处抵消。证据过期或误引先隔离。
- **为什么/比较**：没有“来源名更权威就无条件覆盖全部”的自动裁决算法；专业争议仍待复核。
- **难点/追问**：不要让模型挑一个更顺口的结论；无法确定时限制对应判断，不无故阻断无关可行菜。

依据：[E02](sources-and-coverage.md#e02)、[E06](sources-and-coverage.md#e06)、[E11](sources-and-coverage.md#e11)。

<a id="q025"></a>
### Q025 · 粗筛多少、最终多少，为什么？

状态：**研究默认值，未扫参**

- **口述**：研究A1最多50事实、dense默认30证据；统一事实后RRF排序，最终最多8个适用事实并受估算6000 token约束，证据闭包可能多于8条。
- **实现/参数**：数字分别是发现候选、最终事实和上下文预算，不可混称top-k。业务另有最多48父菜谱与24000输入预算。
- **为什么/比较**：都是当前工程初值，尚无召回10/20/30/50、事实4/8/12的参数消融。
- **难点/追问**：8不是必须凑满；有条件未知、撤回或预算不够时会减少或返回待确认/证据不足。

依据：[E06](sources-and-coverage.md#e06)、[E07](sources-and-coverage.md#e07)。

<a id="q026"></a>
### Q026 · 怎样检测和量化“偏题”？

状态：**已有规则回归；独立分级标签待补**

- **口述**：不能只看同疾病或向量高分。看该片段能否支持本次对象、动作、条件和任务；人工标签可分无关、同主题、部分支持、直接完整支持。
- **实现/参数**：偏题率可定义为实际注入上下文中无关/仅同主题项占比，需声明分母与标注规则；候选top-10另报，不混用。
- **为什么/比较**：当前修复过具体偏题，有标签规范和工程回归，但独立gold尚缺，不能报全库偏题率。
- **难点/追问**：检索相关性、条件适用性和证据对陈述的支持必须分别评分。

依据：[E06](sources-and-coverage.md#e06)、[E14](sources-and-coverage.md#e14)。

### Q027 · Rerank解决什么，和Embedding有何不同？

状态：**方案，当前未接入**

- **口述**：Embedding分别编码问题和文档，距离匹配便于提前建库；Cross-Encoder把两者一起输入，直接打相关性分，更适合对小候选池精排。
- **实现/参数**：可放在融合/去重与资格过滤之后，取足够候选再重排；之后仍补支持/限定并做预算选择。项目尚未安装专用reranker。
- **为什么/比较**：可能改善细粒度相关性，但无法召回根本没找到的事实，也不能保证医学适用性或原文真实性。
- **难点/追问**：BGE-Reranker的分数不是向量，更不是安全概率；效果须用本项目误选/漏选对照。

依据：[E06](sources-and-coverage.md#e06)、[E18](sources-and-coverage.md#e18)、[S04](sources-and-coverage.md#s04)。

### Q028 · 如何权衡Reranker延迟和收益？

状态：**实验方案，未实施**

- **口述**：分开测检索、重排、上下文和生成时间，固定候选池和模型比较有无重排。看最终相关证据、偏题、理由支持，而不只看重排器自己分数。

<a id="q029"></a>
### Q029 · 超预算为何回退完整事实，不截断半段证据？

状态：**研究上下文选择已实现**

- **口述**：截断可能留下“推荐”却删掉“仅适用于/除外/未证实”，改变含义。上下文以事实和它的必需支持/限定为一组，超预算整组回退。
- **实现/参数**：研究最多8事实/估算6000 token；业务减少候选尾部并重算关联指导，不能截配方或丢必要限定来保住结论。
- **为什么/比较**：这是语义完整性原则，不是已证明6000最优；如果一组都放不下，返回不足而不伪造摘要。
- **难点/追问**：更大的块未必更好，父块也必须完整且受预算约束。

依据：[E06](sources-and-coverage.md#e06)、[E07](sources-and-coverage.md#e07)、[E08](sources-and-coverage.md#e08)。

<a id="q030"></a>
### Q030 · 怎样防模型编造医学常识？

状态：**职责约束已实现；不能保证零幻觉**

- **口述**：先收窄任务，只提供可用事实和真实配方，明确禁止新疗效、营养阈值和诊断。程序输出依据绑定与未知范围，不让自由文字发布成新规则。
- **实现/参数**：研究核验本次fact/evidence集合及限定引用；业务模型只选目录ID，健康理由由代码形成。
- **为什么/比较**：RAG、JSON和提示都不是零幻觉证明；实际语义质量仍要抽检/评测，结构通过不代表陈述被支持。
- **难点/追问**：“原文说含某成分”不能跳成“吃这道菜可治疗某病”；少选也不能偷换成禁止。

依据：[E07](sources-and-coverage.md#e07)、[E08](sources-and-coverage.md#e08)、[E09](sources-and-coverage.md#e09)。

### Q031 · 残缺JSON或带Markdown围栏怎么办？

状态：**当前严格拒收，无自动修复重试**

- **口述**：要求JSON模式，检查完整终态，再JSON.parse和运行时验证。空白、截断、额外非JSON导致解析失败就返回明确错误，不擅自补ID或再花一次模型调用修复。
- **实现/参数**：当前不靠贪婪正则抓第一个到最后一个大括号，也不剥掉任意文字假装正确；64KiB响应和内容长度有限制。
- **为什么/比较**：未来若允许受控清理，要独立定义仅外围包装的无损规则并保留原文；这不是现有实现。
- **难点/追问**：先区分超max_tokens、供应商协议失败与JSON语法失败，修parse报错不等于修内容事实。

依据：[E09](sources-and-coverage.md#e09)。

### Q032 · 如何校验evidenceId真实，存在就够了吗？

状态：**研究引用校验与业务绑定分开**

- **口述**：研究要求ID属于本请求上下文，事实至少有支持引用且限定引用齐全；还核对来源状态。业务不接受模型自由填写证据ID，由程序按实际配方绑定。
- **实现/参数**：合法ID只能证明引用对象存在及关系合约成立，不能证明任何自由陈述都被原文蕴含。
- **为什么/比较**：第4次真实调用中模型误填引用被拒，第5次改为程序绑定；不能把失败改写为通过。
- **难点/追问**：其他菜的有效证据也不能借用；配方变化、撤回后旧理由应失效。

依据：[E09](sources-and-coverage.md#e09)、[E13](sources-and-coverage.md#e13)。

<a id="q033"></a>
### Q033 · “迷失在中间”是什么，项目怎样处理？

状态：**理论；位置消融未做**

- **口述**：长上下文中相关信息的位置会影响模型利用效果，不等于窗口装得下就能稳定读懂。项目用任务过滤、较小事实集和预算减少无关信息。
- **实现/参数**：没有实现或验证专门的位置重排策略，也没有证明当前模型已解决该现象；原论文的模型与任务不能直接外推。
- **为什么/比较**：后续同内容换证据位置、固定其他条件做对照，检查限定/引用保留，而非只把结论挪到开头。
- **难点/追问**：人群例外也须紧邻其适用事实，不能仅把“好消息”放头部而把限制扔掉。

依据：[E07](sources-and-coverage.md#e07)、[E14](sources-and-coverage.md#e14)、[S07](sources-and-coverage.md#s07)。

### Q035 · 证据冲突时，大模型应听谁？

状态：**冲突表达已实现；无全面自动仲裁**

- **口述**：先按对象、形态、人群、时间和来源版本拆清适用范围；不能简单按排名投票。真实冲突应明示争议并限制受影响结论，必要时复核来源。
