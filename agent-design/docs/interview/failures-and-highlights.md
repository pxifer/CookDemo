# 真实问题、解决过程与可讲的亮点

以下是项目记录中的事件，不是为了面试编出的“踩坑故事”。本人参与程度、提交和验证应据实说明；历史检查数量不当作本手册新跑的测试。

## 1. 证据问答偏离“今晚吃什么”

**触发**：用户想按疾病/减脂和现有食材选菜，而证据问答只会复述指南。**原因**：知识终点停在营养成分和问答，缺少食物对象、适用条件和实际配方桥梁。**改进**：增加直接食物/工艺指导，疾病与目标分开，用受控成员和真实主做法绑定目录，再复用资格程序。成分机制保留作解释，不自动变成食物获益。**证据**：[业务计划与实施](../business-rag-plan.md)、[真实例子](../business-rag-example-2026-11-05.md)。**局限**：映射不是全目录覆盖，尚不能输出全天营养处方。

口述：“最大的调整是把技术闭环改成用户闭环：检索出一段话还不够，还要能说明它关联哪项食材、哪道实际配方，以及哪些地方仍未知。”

## 2. 合格的小葱拌豆腐被模型拒选

**触发**：第2次真实调用，程序有合格普通菜，模型因油量未知、推测与减脂冲突而返回空选择。**原因**：把缺依据、少选和硬避免混在一起；提示词给模型过大的医学否决权。**修复**：无映射不全局禁普通菜；少选只排序/提醒；目录已硬筛，不能凭未提供的营养判断拒绝唯一合格候选。**验证**：第3次该普通菜真实返回，健康判断保留。**局限**：单例证明缺陷修复，不是全部模型拒选率对照。

口述：“不是让模型更敢推荐，而是把无依据的地方缩成未知，让代码负责可验证的条件，避免AI自己新增禁忌。”

## 3. 模型拿真实证据ID挂给不匹配的菜

**触发**：第4次调用给白菜心挂错引用，程序拒绝；ID存在但该配方没有映射。**原因**：让模型同时选菜、解释和声明来源归属，结构合法仍可能语义错配。**修复**：模型只交目录ID和本餐理由；程序按真实配料、主做法和支持/限定绑定。研究业务不发布自由健康summary/reason。**验证**：第5次3菜有真实回执，输出1道有据、2道保留健康判断。**局限**：研究问答自由claim仍需独立蕴含/专业评测。

口述：“我们没有靠第二个Prompt让模型自己证明，而是收回引用权限，把它变成程序可检查的配方关系。”

## 4. 旧导航引用被唯一同名正文“洗白”（RAG-005 P2）

**触发**：资料重建时，旧引文来自导航；新正文恰有唯一同名内容，定位恢复提前成功，绕过旧来源角色核验。**发现**：管理审核端到端调用builder复现，不只测帮助函数。**修复**：任何迁移/重定位前先审旧定位来源，导航仍隔离；唯一正文也不自动批准。**验证**：修复已复审并合入main，见[管理审核](../../../docs/collaboration/reviews/RAG-005-2026-11-06.md)及[定位治理](../evidence-resolution-2026-11-06.md)。**局限**：旧冻结知识/向量没有因此被自动重整替换。

口述：“hash和字面唯一只能说明定位候选，不能证明原先引用正确。这里暴露的是校验顺序问题，我们把来源核验提到了所有快捷路径之前。”

## 5. 表格看似抽出来，实际对象—值可能错位

**现象**：无竖线表宽列漏分、上下标数字错序、跨列串文；旧短摘有的只剩表号。**方法**：保留词框/字号，修订上下标与列界、按物理格输出；表题、表头路径、单位、脚注单独关联候选；原词守恒和回查检查。**证据**：[表格/OCR记录](../table-ocr-execution-2026-11-06.md)、[v3治理](../evidence-resolution-2026-11-06.md)。**局限**：322表/14214格/7510关系候选不是审核通过的营养事实，OCR一致不是准确率。

口述：“PDF转出文字不是结束。营养表必须知道哪个数属于哪个对象、单位和限定，否则整齐的JSON也会保存错误。”

## 6. 建了向量，指标却不如A1

**事实**：研究27题的A1已达Recall@10/MRR=1；两模型hybrid Recall相同、MRR未优于A1。**解释**：小而受控的库、明确实体和已曝光调试题有利于A1；向量相近不一定对象/限定一致。**处理**：保留基线，报告无增益；业务直接指导不强行使用向量。**待做**：独立难题、否定/别名、无答案和跨来源条件，固定其他变量消融。不能为了漂亮结论修改gold或删除失败题。

口述：“我验证了向量通路，但没有把‘用上向量’等同于收益。真实业务仍用更可控的直接指导，等独立数据证明需要再接。”

## 7. 建议列表被大类别占满、补问过泛

**原因**：同一蔬菜类有多个成员，按固定遍历取前20挤掉其他方向；不相关条件也问用户。**修复**：avoid/limit/prefer方向轮转，再按主题/对象分配；仅对相关且可映射指导问明确条件，允许不清楚。**证据**：[质量治理记录](../quality-governance-execution-2026-11-05.md)。**局限**：轮转是覆盖策略，没有证明用户满意度提升或已学到最优排序。

## 8. 迟到请求把旧Key或疾病状态带回来

**风险**：发起时合法，返回时用户已清空Key、删病或改食材。**方法**：当前档案为准、operation/输入/版本绑定、返回前再核验；图片读取/上传也检查最新会话和Key，不能换供应商偷偷续跑。**证据**：[账户及限制规则](../../../AGENTS.md)、[照片入口专项](../../../docs/development/ingredient-photo-recognition.md)。**局限**：本地延迟供应商回归不等于真实供应商收到取消就不计费。

## 可以用的五项亮点

| 亮点 | 能展示的工程证据 | 不夸大的边界 |
| --- | --- | --- |
| 业务纠偏 | 指导—映射—配方—本餐链与真实例子 | 不说已完成临床个体营养推荐 |
| 职责收缩 | 先硬筛、模型选ID、后复核；程序绑定理由 | 不说纯Prompt就能零幻觉 |
| 资料可回查 | 原件/位置/派生/修订分层及来源角色门禁 | 不说OCR/表格候选全自动审核 |
| 有对照的研究 | 两Embedding、三模式及不占优结果均保留 | 不编RRF增益或独立100% |
| 状态与费用边界 | PG认领、版本绑定、零自动重试、游标复用 | 不说供应商exactly-once或已生产压测 |

面试反问可围绕团队知识更新、gold标注、线上错误归因、工具授权与费用SLO；HR内容不虚构成技术实现。把“如果有10万预算先做什么”回答为数据/覆盖与独立质量闭环优先，再根据瓶颈决定rerank或服务扩容，而不是先花完预算。
