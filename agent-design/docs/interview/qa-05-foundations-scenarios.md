<a id="q085"></a>
### Q085 · 上下文满了再压缩吗？哪些信息不能压？

状态：**当前结构打包；无LLM自动摘要压缩**

- **口述**：应预留系统、工具/资料、回答和安全余量；在溢出前按结构裁减。健康条件、否定、单位、来源与撤回水位不能仅靠一段模型摘要保留。
- **实现/参数**：研究context估算6000；业务系统prompt＋packet估算24000。当前减完整fact或候选并重算闭包，不用LLM压缩原文。
- **为什么/比较**：后续可对普通对话摘要做实验，与原始约束表并存；比较遗忘/错归属、实际token和成本，而不是只看压缩率。
- **难点/追问**：token估算与模型真实usage不同；压缩后更短但漏掉“肾功能异常除外”就是失败。

依据：[E07](sources-and-coverage.md#e07)、[E11](sources-and-coverage.md#e11)、[S07](sources-and-coverage.md#s07)。

<a id="q086"></a>
### Q086 · 反复摘要、换模型和跨轮记忆会漂移吗？

状态：**风险设计；当前无摘要型长期记忆**

- **口述**：每次摘要可能累积遗漏或把推测变事实，换模型还改变token数和解释。稳定健康约束应来自带来源/版本的结构化档案，不以摘要覆盖。
- **实现/参数**：当前完整聊天只保留页内内存，健康接受记录按主题保存/撤销；删病后相关历史不得继续送模型。
- **为什么/比较**：后续比较连续N轮、重复压缩、删除与反转条件，检查约束保留率；不照搬其他产品的私有压缩阈值。
- **难点/追问**：用户说“之前不是我过敏，是家人”需要纠正归属；不能将旧摘要认定为最高优先级记忆。

依据：[E11](sources-and-coverage.md#e11)、[E18](sources-and-coverage.md#e18)。

<a id="q087"></a>
### Q087 · Recall、MRR和nDCG能手算吗？它们测的是什么？

状态：**现有工具计算；独立分级gold待补**

- **口述**：某题相关集合为A/B，排名为X/A/Y/B：Recall@3=1/2，首个相关在第2位所以RR=1/2；MRR是多题RR均值。Recall@k需完整相关标注。
- **实现/参数**：DCG可用Σ(2^rel-1)/log2(rank+1)，nDCG=DCG/理想DCG。当前工具是二值相关，不是0～3专业分级。
- **为什么/比较**：MRR看首个相关，不保证证据完整；Recall高仍可能有偏题或错误适用。另报精度、实际注入证据覆盖与硬约束违规。
- **难点/追问**：无相关证据题需单列正确拒答/误答率；不能从分母删掉失败题让均值变好。

依据：[E12](sources-and-coverage.md#e12)、[E14](sources-and-coverage.md#e14)。

<a id="q088"></a>
### Q088 · LLM-as-judge和人工审核怎么配合？

状态：**现有工程标签；独立/专业评测延期**

- **口述**：程序先检查ID、来源、限定和硬条件；语义支持/表达可用盲评辅助，但评委模型也会偏好措辞或重复生成模型错误。健康适用性需要独立专业审核。
- **实现/参数**：训练/调参/测试按问题及来源划分，人工预期不送生成；双人独立标注和分歧裁决是候选流程，尚非本项目已完成事实。
- **为什么/比较**：用户决定上线后结合真实输出完善评测；当前27题已暴露，不可称独立准确率100%，也不因此停止已授权研发。
- **难点/追问**：Ragas帮助组织指标，不会自动生成可信gold；评委提示、版本、样本和一致性同样需记录。

依据：[E14](sources-and-coverage.md#e14)、[S12](sources-and-coverage.md#s12)。

<a id="q089"></a>
### Q089 · Prompt注入、SSRF和恶意资料如何防？

状态：**多层边界已有；完整红队覆盖未完成**

- **口述**：用户问题与检索文本都是不可信数据，资料中的“忽略规则/上传Key”不能成为工具指令。URL和供应商入口固定，鉴权、用途、Schema、权限与业务复核由程序落实。
- **实现/参数**：公共抓取/图片来源与模型请求分别限制；原图仅请求内存，日志不含Key和健康正文。不能让模型自由访问任意URL或执行SQL。
- **为什么/比较**：OWASP明确RAG本身不是注入免疫；后续用恶意原文、混淆ID、跨用户游标、过期档案和大响应做红队评测。
- **难点/追问**：任何单条“不要听注入”提示都不是证明；输出合法JSON仍可能携带恶意或不合业务的决定。

依据：[E09](sources-and-coverage.md#e09)、[E10](sources-and-coverage.md#e10)、[E16](sources-and-coverage.md#e16)、[S13](sources-and-coverage.md#s13)。

<a id="q090"></a>
### Q090 · Trace要记什么？如何既可定位又保护隐私？

状态：**已有验收/调用元数据；非完整线上观测平台**

- **口述**：记录operation、阶段、版本、候选/命中ID、输入不可还原绑定摘要、耗时、状态和真实usage；将失败定位到清洗、检索、打包、生成或校验。
- **实现/参数**：不记录完整Key、个人健康正文、原图或模型隐藏思维链；公共构造案例可保存必要证据，真实用户另按保留策略处理。
- **为什么/比较**：阶段指标比一句“模型表现不好”更可排查；日志ID真实存在不等于输出语义正确。当前无全站线上SLO看板数据。
- **难点/追问**：脱敏不是只遮前几位；低熵疾病字段直接hash可能被枚举，应采用符合用途的受保护绑定摘要。

依据：[E10](sources-and-coverage.md#e10)、[E12](sources-and-coverage.md#e12)、[E14](sources-and-coverage.md#e14)。

<a id="q091"></a>
### Q091 · 工具/SQL沙箱、最小权限和只读Agent怎样设计？

状态：**当前模型无SQL工具；只读Agent属扩展**

- **口述**：把工具限定为明确输入输出的少量能力，服务端重新鉴权；查询用参数化SQL、固定范围和资源限额。提示词不能限制任意数据库账号实际权限。
- **实现/参数**：当前选菜模型只交目录ID，不执行SQL或发布知识。外部题库的只读教学Agent不能写成产品已实现工具循环。
- **为什么/比较**：将来可先接只读目录查询；写入、资料发布、部署与付款按授权和确认边界单独设计，不使用万能shell工具。
- **难点/追问**：工具名叫readOnly并不足够；要核对数据库角色、事务、连接可访问范围和返回字段。

依据：[E08](sources-and-coverage.md#e08)、[E10](sources-and-coverage.md#e10)、[E18](sources-and-coverage.md#e18)。

<a id="q092"></a>
### Q092 · 不引入MQ也能做异步Agent任务吗？

状态：**架构储备；当前在线链非持久任务队列**

- **口述**：可用PG job表保存任务、状态、重试预算、lease到期、版本和结果引用；工作者原子认领，长任务续租，fencing token防旧工作者迟到覆盖。
- **实现/参数**：当前没有该持久任务系统，页面NDJSON进度不等于后台可恢复任务；进程崩溃后恢复不能凭聊天记录猜执行状态。
- **为什么/比较**：是否引入MQ取决于吞吐、路由、运维和重放需求；数据库队列也要测锁争用与表膨胀，不是免费替代。
- **难点/追问**：按至少一次执行设计幂等外部动作；网络超时下不能仅靠队列宣称端到端exactly-once。

依据：[E10](sources-and-coverage.md#e10)、[E18](sources-and-coverage.md#e18)。

### Q093 · 灰度、版本回退和上线门禁怎样安排？

状态：**本地版本/审核已有；疾病RAG未发布**

- **口述**：代码、知识、映射、索引和评测证据分别锁定，先离线回归，再按获准范围验证；撤回和硬限制错误单独阻断，不用平均质量分覆盖。
- **实现/参数**：当前Git分支提交本地审核；定时PR管理已于2026-11-12取消，本手册不恢复自动审核、部署或模型测试。
- **为什么/比较**：未来灰度比较业务可行性、证据支持、失败率、延迟和成本；回退代码不能复活被撤回知识或用户已删除条件。
- **难点/追问**：本地通过不等于线上已验收；方案中写“自动回滚”不能当作已经具备灾备能力。

依据：[E17](sources-and-coverage.md#e17)、[E18](sources-and-coverage.md#e18)。

<a id="q094"></a>
### Q094 · AI写代码后你怎样审，真实修过什么？

状态：**有真实缺陷与修复证据**

- **口述**：沿数据流核对外部类型、条件、ID和失败路径，再用最小反例复现；不只看编译与漂亮结果。例：模型把白菜心理由挂到豆腐证据上，程序拒绝后改由真实配方绑定。
- **实现/参数**：另一例是旧导航引用因正文唯一同名而绕过隔离：管理审核端到端复现，修复先审旧来源角色，再允许迁移定位，加入builder级回归。
- **为什么/比较**：有真实失败、修复提交和回归范围才可讲个人参与；不能把AI生成代码或团队审核全部说成自己手写。
- **难点/追问**：面试可现场画字段流、手写RRF与JSON边界校验；强调能发现什么、凭什么验收，而不是声称不用读代码。

依据：[E13](sources-and-coverage.md#e13)、[E15](sources-and-coverage.md#e15)、[E17](sources-and-coverage.md#e17)。

### Q095 · PRD、技术设计、ADR与个人贡献怎么区分？

状态：**项目文档/协作实践**

- **口述**：PRD写用户行为和验收，技术设计写边界、数据流与失败状态，ADR记录取舍及证据。面试必须用自己的真实承担范围解释，而不是照读全部仓库。
- **实现/参数**：产品决定如忽略用户食材用量，与算法参数如RRF常数是不同依据；实际命令/测试、AI辅助和他人审核应如实归属。
- **为什么/比较**：成熟产品作为对标，不能复制其参数当本项目实验结果；记录不适用原因与未来验证方法即可。
- **难点/追问**：准备“我提出/我审核/我验证”的证据，未亲自完成手写练习前不能说已经做过。

依据：[E01](sources-and-coverage.md#e01)、[E17](sources-and-coverage.md#e17)、[S16](sources-and-coverage.md#s16)、[S17](sources-and-coverage.md#s17)。

<a id="q096"></a>
### Q096 · Agentic RAG、CRAG、Self-RAG和普通检索有什么区别？

状态：**概念储备；项目未实现**

- **口述**：Agentic RAG允许规划选择检索/工具；CRAG围绕检索质量评估与纠正；Self-RAG原论文包含训练出的反思标记机制，不等于Prompt里多写一句自检。
- **实现/参数**：当前是受控流程，没有模型自发循环、联网补证或反思token训练。低置信不自动跑外网以免把未审核资料当医学证据。
- **为什么/比较**：只有固定链路暴露可测瓶颈后才加纠正步骤；比较成功率、错误传播、调用数和时延，不能只比回答更长。
- **难点/追问**：评估器也可能错；允许最多几轮、何时停止、失败如何解释必须可执行。

依据：[E18](sources-and-coverage.md#e18)、[S18](sources-and-coverage.md#s18)、[S19](sources-and-coverage.md#s19)。

<a id="q097"></a>
### Q097 · MMR、多样性和去重能解决什么？项目用了吗？

状态：**父菜谱去重/轮转已有；未用MMR**

- **口述**：MMR在查询相关和已选结果相似之间折中，常见形式λ×相关性-(1-λ)×最大重复度。它改善多样性，不证明证据适用或医学正确。
- **实现/参数**：当前按fact/evidence ID去重、建议按方向和主题轮转、父菜谱不重复；没有MMR相似度矩阵或λ选值。
- **为什么/比较**：后续先测重复候选挤占率，再对比简单去重与MMR；不能为了菜品多样把不满足过敏/库存的菜补进来。
- **难点/追问**：多个近似段落未必都是冗余：一条可能是另一条必需的例外限定，应整体保留。

依据：[E06](sources-and-coverage.md#e06)、[E08](sources-and-coverage.md#e08)、[E18](sources-and-coverage.md#e18)。

<a id="q098"></a>
### Q098 · 多个知识库如何路由？不同Embedding能一起查吗？

状态：**扩展方案；当前非多私有库平台**

- **口述**：按任务、来源与权限先确定可查集合，query改写保留原意，再在各自匹配的向量空间检索；返回统一事实/证据ID后才谈名次融合。
- **实现/参数**：同为1024维的Qwen与BGE距离不能直接横向比较；不能把一个模型query去查另一个模型文档。当前双模型研究分别建立/评测索引。
- **为什么/比较**：多库路由可对比显式主题规则与模型分类的漏路由/多查成本；没有必要先部署多个向量数据库。
- **难点/追问**：权限前置、版本与撤回贯穿；路由错误的库即使第一名很像也应拒绝。

依据：[E05](sources-and-coverage.md#e05)、[E06](sources-and-coverage.md#e06)、[E18](sources-and-coverage.md#e18)。

### Q099 · 用户让Agent删除知识、忌口或疾病怎么办？

状态：**个人主题撤销已有；公共知识维护无模型工具**

- **口述**：个人档案变更与公共资料删除是不同权限。用户删除自己的疾病主题，撤销该主题接受记录与无来源摘要；不能替用户修改过敏或删公共指南。
- **实现/参数**：服务端核对最新账户/版本，迟到返回不能把已删除主题写回；公共知识撤回走受控维护与版本流程。
- **为什么/比较**：记忆删除不只是前端隐藏一句聊天，还要检查后续模型上下文、缓存、建议与游标失效。
- **难点/追问**：模型回复“已经删除”不构成事实；要有真实授权操作结果，当前模型不直接执行公共库删除。

依据：[E11](sources-and-coverage.md#e11)、[E10](sources-and-coverage.md#e10)。

### Q100 · 项目亮点怎么写，哪些简历数字不能写？

状态：**可用已有证据；无业务提升百分比**

- **口述**：可讲：业务事实与证据分层；真实目录先筛后选再复核；配方动态绑定依据；条件完整的预算裁减；原文可回查的解析治理与版本边界。
- **实现/参数**：可引用98证据/260事实、27题工程对比、5次界面调用，但注明版本/范围；这些不是临床准确率、转化率或生产容量。
- **为什么/比较**：不能写“RRF提升召回XX%”“重排降低幻觉”“100%医学准确”，因为没有对应独立实验，重排也未接入。
- **难点/追问**：面试优势在能解释失败与取舍，不在堆技术名。描述个人贡献须根据本人实际参与调整。

依据：[E02](sources-and-coverage.md#e02)、[E07](sources-and-coverage.md#e07)、[E08](sources-and-coverage.md#e08)、[E12](sources-and-coverage.md#e12)、[E13](sources-and-coverage.md#e13)、[E15](sources-and-coverage.md#e15)。

<a id="q101"></a>
### Q101 · Markdown没有标题，或者资料格式特别乱，怎样切？

状态：**未来接入方案；当前主要治理HTML/PDF**

- **口述**：先保留原件和行号，识别段落、列表、代码、表格与可能的标题；没有标题不等于必须按固定字数盲切。再按语义边界和token上限产生候选。
- **实现/参数**：表格须带表头/单位/脚注，正文条件跨段关联；不能因为短行就当标题，也不能把代码/数字里的符号当自然语言分隔。
- **为什么/比较**：比较结构块、固定窗口和父子块，观察限定保留/召回/预算；当前没有完成通用Markdown清洗器及横评。
- **难点/追问**：来源排版变化要版本化；格式恢复失败进复核队列，不让摘要掩盖损坏。

依据：[E03](sources-and-coverage.md#e03)、[E05](sources-and-coverage.md#e05)、[E18](sources-and-coverage.md#e18)。

<a id="q102"></a>
### Q102 · 脏数据、Unicode、类型和重复数组怎样处理？

状态：**已有规范化/Schema/ID校验**

- **口述**：先用Schema检查对象/数组/类型/长度与允许字段，再核对实体ID和业务含义。检索用NFKC、小写和受控别名；归一化后仍保存原文与可回查定位。
- **实现/参数**：中文字符、JS UTF-16长度与token不是同一单位；当前接口字符保护存在Node/Python计数差异，不能称跨语言完全等价。
- **为什么/比较**：重复ID、未知变体、空内容、NaN向量或归一化异常都需显式处理，不靠TypeScript断言把未知JSON变可信。
- **难点/追问**：不能全局正则删除Markdown/标点来修证据；数字单位、负号和“不”被删会改变事实。

依据：[E03](sources-and-coverage.md#e03)、[E05](sources-and-coverage.md#e05)、[E09](sources-and-coverage.md#e09)。

<a id="q103"></a>
### Q103 · 过滤后检索不到怎么办？怎样区分索引漏召回与没有依据？

状态：**当前精确检索；ANN问题为储备**

- **口述**：先验证知识覆盖和适用条件，再查query解析、索引版本及候选数；有精确相关结果但ANN没取到才是近似检索漏召回。
- **实现/参数**：当前PG精确余弦，无ANN误差；研究入口还可能因实体未知或必要条件不明在编码前停止。业务无健康依据可保留合格普通菜的健康未知。
- **为什么/比较**：未来ANN过滤需比较前置过滤、迭代扫描/候选扩张的授权可行性和Recall；不能调低医学或权限约束来凑k。
- **难点/追问**：“返回0条”至少区分无覆盖、不适用、待补问、撤回、技术失败；产品反馈与监控分别统计。

依据：[E05](sources-and-coverage.md#e05)、[E06](sources-and-coverage.md#e06)、[E08](sources-and-coverage.md#e08)、[S03](sources-and-coverage.md#s03)。

### Q104 · 用户在调用中改食材、删病或清空Key怎么办？

状态：**版本绑定与迟到保护已有**

- **口述**：这是检查与使用之间的竞态：调用前验证通过不代表返回时仍有效。发送前同步设置，发布前核对当前用户、输入、Key、档案及目录身份。
- **实现/参数**：加密游标绑定相同范围；数量编辑按用户新策略不改变食材存在语义，不能误判为需要重调模型。图片上传前也检查Key/会话是否已撤销。
- **为什么/比较**：回归使用可控制的延迟供应商复现中途改变；这证明程序保护，不等于真实模型取消后必然零计费。
- **难点/追问**：不要用“最后返回的结果获胜”；应使用当前operation/version获胜，旧请求只能过期。

依据：[E10](sources-and-coverage.md#e10)、[E11](sources-and-coverage.md#e11)、[E16](sources-and-coverage.md#e16)。

### Q105 · 本地大模型显存怎么估？为什么现在用API？

状态：**生成复用API；本地仅Embedding实测**

- **口述**：权重内存约参数数×每参数字节，还需运行框架、激活与KV缓存；KV随层数、KV头、维度、序列长度、批量和精度变化，GQA会改变规模。
- **实现/参数**：项目测的是CPU Qwen0.6B/BGE Embedding，不是本地生成LLM或GPU服务；DeepSeek API是既有入口复用，无本地生成/API公平效果成本横评。
- **为什么/比较**：量化可减少权重，但质量、算子支持和吞吐需测；不能用模型文件大小估计峰值显存或承诺某显卡并发。
- **难点/追问**：Prefill/Decode瓶颈不同；应用长期记忆不是KV cache，缓存前缀也不会自动记住用户过敏。

依据：[E05](sources-and-coverage.md#e05)、[E09](sources-and-coverage.md#e09)、[S08](sources-and-coverage.md#s08)。

### Q109 · 用户配置错数据库连接，系统怎样兜底？

状态：**场景题；当前用户不配置数据库**

- **口述**：数据库属于服务端运维配置，不让普通用户给任意连接串，更不能把密码发给LLM诊断。错误配置应在启动/就绪检查发现，日志脱敏并给可操作状态。
- **实现/参数**：当前用户配置个人模型Key，非数据库账号；模型技术失败不静默降级普通推荐，不能混用两种配置错误。
- **为什么/比较**：未来多数据源可先独立连接探测、最小权限、超时和白名单；回退只能到已授权且语义一致的数据源。
- **难点/追问**：显示“系统繁忙”可保护秘密，但运维仍需错误分类；不能靠Agent试遍内网地址修连接。

依据：[E09](sources-and-coverage.md#e09)、[E10](sources-and-coverage.md#e10)、[E18](sources-and-coverage.md#e18)。

- **口述**：回调描述交互方式，Webhook是服务间HTTP通知，MCP通知属于协议语义。SSE适合服务端单向事件推送，WebSocket适合双向持续通信；持久、重放与鉴权另设计。

### Q112 · Schema通过了为什么仍会出错？怎样做语义约束？
