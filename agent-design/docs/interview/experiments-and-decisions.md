# 实验与选型账本：为什么选、比过吗、还能怎样比

代码快照见[入口](README.md)。本页记录证据等级，不执行新实验。独立质量集按用户决定放上线后结合输出与预期完善；下列候选实验不是本次新增完成项。

## 1. 已经比较或检查到哪一层

| 问题 | 已有记录 | 可以讲的结论 | 不能讲的结论 |
| --- | --- | --- | --- |
| Qwen与BGE | 同27题、各98证据；hybrid Recall@10均1；MRR分别0.93750 / 0.90625 | 这批研究题上Qwen融合首相关排序较好 | Qwen普遍更准、线上已验证或临床更安全 |
| 编码速度 | 同16查询真实编码P95：1706.0 / 656.1ms | 该本机CPU与锁定版本下BGE编码P95较低 | 任何硬件/批量都更快；检索总时延全由Embedding决定 |
| A1/dense/hybrid | 三模式真实工程评测；该题集A1 Recall@10/MRR已经1 | 语义检索通路跑通，但未证明增益 | RRF显著提升召回；混合必然优于简单基线 |
| 切块长度 | 冻结98证据与3717结构块逐条计字符/token | 知道实际长度与可能超窗范围 | 选择64字符/512 token是实验最优 |
| 资料解析 | v2/v3真实失败、原词守恒、builder级回归、两套离线重建 | 工程保真和已知缺陷修复有记录 | 独立正文/表格/OCR准确率100% |
| 生成与业务 | 5次真实界面调用保留2次关键失败，最终3菜有真实回执 | 少量真实闭环成功、错误推动职责调整 | 生成模型总体胜率/用户满意度/安全性已评估 |
| pgvector及框架 | 复用既有PG的需求/运维方案对照 | 当前小规模、版本一致性和部署简单是选择理由 | 已压测击败Milvus/Qdrant、手写比LangChain快 |

证据：[研究执行](../execution-2026-11-04.md)、[参数实测](../rag-parameters-and-chunking.md)、[真实界面例子](../business-rag-example-2026-11-05.md)。27题已参与调试；dense/hybrid在一个进程可共享query编码缓存，模式耗时不是公平的独立冷启动对照。旧延迟分位数实现与后来长度统计的nearest-rank不同，应随记录说明。

## 2. 所有关键参数是什么性质

| 阶段 | 当前做法/数值 | 原因与代价 | 比较状态 |
| --- | --- | --- | --- |
| HTML/PDF清洗 | DOM正文优先、坐标版面/重复页边检测；阈值详见参数表 | 保留原词与定位，避免全文导航污染；启发式也会误保留/漏识别 | 真实反例回归；无解析器/阈值系统横评 |
| 表格/OCR | 结构格/表头脚注候选；Windows OCR，PDF144/216dpi、长图3000px/180重叠 | 恢复结构而非把数字按行拼；两分辨率一致仍可能同错 | 有两组输出与工程核验；无引擎质量横评 |
| 证据切块 | 脚本给定起止锚点；无固定chunk_size/overlap | 小库可追溯；部分摘录短到只有表号，跨页条件仍需重整 | 无128/256/512或父子块消融 |
| 表示与向量 | 两模型1024维、L2；Qwen lasttoken/BGE CLS；原文＋摘要，部分加章节 | 遵循锁定模型配置；摘要可能改善检索，也可能掩盖弱证据 | 两模型整体比较；无维度/pooling/模板单变量比较 |
| 查询 | NFKC、受控别名、实体及否定检查；中文二字词 | 明确领域对象与限定；不是完整自然语言理解或BM25 | 有歧义/偏题回归；无分词器横评 |
| A1 | 对象+8、疾病+4、词面min(4,len)；内部等权RRF | 轻量、可解释；手工权重泛化有限 | 数值初值；A1为现有强基线 |
| 外层召回/融合 | A1≤50事实，dense≤30证据，映射fact后2:1、c=60 | 统一fact空间、避免不同量纲直加；会带入偏题项 | 有模式对比，无候选量/权重/c的消融 |
| 上下文 | ≤8事实＋全部支持/限定；估算6000 context token | 控制噪声和费用；闭包大时可能更少事实 | 工程初值，无4/8/12或预算消融 |
| 业务候选 | 可行基线500ms/6000节点；≤48父菜谱；24000估算输入 | 不让模型拿到无法组成一餐的候选；候选不全会影响选择 | 有功能回归，无24/48/96用户质量A/B |
| 生成 | DeepSeek flash、JSON object、非流式、研究2000/业务2400输出 | 复用现有入口，易做严格校验；截断即拒收 | 无生成模型/温度/输出上限横评；温度未显式设置 |
| 引用与发布 | ID/版本/限定核验，研究业务按配方形成健康理由 | 真实错挂引用后的职责收缩；映射仍有限 | 有前后缺陷回归及少量真实样例，不是全局零幻觉证明 |

完整模型revision、运行库、批量三层区别、单位、所有版面阈值及源码在[参数总表](../rag-parameters-and-chunking.md)。这里不另维护第二套权威参数。

## 4. 后续实验怎样做到可执行且公平

先冻结语料/模型/问题族、版本和评分脚本，记录曝光。开发集调参，独立测试集只在选择后用；变化只针对一类变量。报告每题结果、失败和代价，样本小则说明不确定性。不能先决定结论再找数据。

| 实验 | 候选与控制 | 看哪些结果 | 允许得到的结果 |
| --- | --- | --- | --- |
| 切块 | 同原文/解析版本/固定tokenizer：旧锚点、结构段落、128/256/512 token | 限定/否定/单位保留，Recall、上下文覆盖、偏题、token | 大块或小块均可能输；不因长度均匀就认为更好 |
| Overlap | 对被长度拆分的连续正文比较0/32/64 token | 边界漏检、重复候选挤占、索引量和代价 | 表格/脚注不机械滑窗；重复率上升可能抵消收益 |
| 父子块 | 同子块召回，只送子块 vs 加回父段/表头脚注 | 限定完整率、证据支持、上下文预算 | 父块可能过大；必须保存parent ID/范围/版本，不能动态猜父文 |
| 表示模板 | 原文 / 章节＋原文 / 审核摘要＋原文 | 相关/偏题，原文实际支持程度 | 摘要可能让弱证据更靠前，需联合支持检查 |
| 模式消融 | A1 / dense / hybrid，其他过滤与预算相同 | Recall@10、MRR、nDCG、实际top-8覆盖、偏题率 | A1可能最好，允许不启用混合 |
| RRF常数 | 先固定权重与候选量，c=10/60/100；若延续旧计划另加20并预登记 | 排序与偏题、每题变化；再单独测1:1/2:1 | 60不预设为赢家；缺席通道贡献0，名次从1开始 |
| 粗召回 | dense 10/20/30/50，A1固定；再单测最终4/8/12 | 候选覆盖、打包后覆盖、时延、token | 候选更多不保证最终更好 |
| Rerank | 固定召回候选与适用性门禁，无重排 vs paired模型，候选20/30/50 | 实际注入偏题率、生成支持率、额外P50/P95/内存 | 无收益或过慢则不用；不能只挑成功案例 |
| 上下文/提示 | 固定候选，3000/6000/9000；最小prompt vs 当前约束 | 漏限定、完整JSON、无依据拒选、理由与配方一致 | 预算不够丢整事实；合法输出仍须业务审核 |
| 端到端 | 固定库存/过敏/目标场景，先测构造模型边界，再获新授权测真实生成 | 可行菜覆盖、硬限制违规、正确未知、支持理由、真实usage/延迟 | 硬违规单判失败；问答Recall满分不抵消违规 |

当前c与候选量部分为代码常量；**现有CLI没有通用 `--rrf-k` 扫参开关**。届时须先增加仅离线的参数入口和身份记录，不能写一条不存在的命令假装跑过。

## 5. 评分与人工是什么关系

程序精确检查：原词/ID/hash、来源/撤回、支持限定闭包、输入版本、过敏库存及整餐可行性。语义相关可做0～3分级：无关/仅背景/部分支持但缺关键条件/直接支持且条件完整；**这是建议标注尺度，未伪装成人审完成**。最终医学适用交独立专业复核。

偏题率需先写清分母，例如“实际注入的去重事实中，不支持问题或不适用的占比”；不同论文/工具口径不能混用。无答案、误拒、未覆盖、冲突和技术失败分别统计。LLM评委只能辅助，不让同一个模型给自己出题、答题、判满分。
