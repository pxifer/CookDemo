<a id="q036"></a>
### Q036 · 项目算Agent还是Workflow？

状态：**当前主要是受控Workflow**

- **口述**：这里主要是预先定义的业务流程加模型选菜；模型没有自主决定任意工具和循环步骤。可以说是Agent应用工程中的受控工作流，不能包装成全自主医疗Agent。
- **实现/参数**：普通函数编排检索/指导、候选、生成、校验；无ReAct循环、Planner或多Agent通信运行时。
- **为什么/比较**：可验证、风险可控比名词高级更重要；尚无单Agent/多Agent或自由规划对照。
- **难点/追问**：未来若任务确需动态工具选择，只在小范围开放，并设置授权、步数与预算。

依据：[E01](sources-and-coverage.md#e01)、[E08](sources-and-coverage.md#e08)、[E18](sources-and-coverage.md#e18)、[S06](sources-and-coverage.md#s06)。

<a id="q037"></a>
### Q037 · 库存、过敏、忌口怎样和模型交互？

状态：**业务已实现**

- **口述**：服务端读取当前账户档案和本餐，程序先筛目录；模型看到的是通过初筛的真实候选和食材有无，返回后再检查单菜与整套。
- **实现/参数**：用户填写用量不参与选菜或发送为库存数量约束；补买须主动开启。过敏、忌口、口味和健康少选分开。
- **为什么/比较**：双层检查防候选不完整或模型忽略条件；不把用户限制只写在system prompt里。
- **难点/追问**：复合调料和未知成分只能按当前可验证范围表达；不能把未知解释成已证明安全。

依据：[E08](sources-and-coverage.md#e08)、[E11](sources-and-coverage.md#e11)。

<a id="q038"></a>
### Q038 · 为什么硬过滤交给代码？

状态：**业务已实现**

- **口述**：过敏和有效避免项是必须满足的约束，不能用模型给出的健康收益平均抵消。程序能检查实际食材ID、可选项、做法和补买状态，结果可重复。
- **实现/参数**：模型只能从提供的目录ID选择；修改口味、换菜和翻页也复核输入和配方版本。
- **为什么/比较**：这是把约束问题与语言偏好分开，不是让规则解决所有语义质量；有硬限制回归，无总体安全率结论。
- **难点/追问**：任一必要限制未知或冲突，按对应业务规则暂停相关判断，不能让模型猜一个最可能值继续。

依据：[E08](sources-and-coverage.md#e08)、[E11](sources-and-coverage.md#e11)。

<a id="q039"></a>
### Q039 · 高血压用户只有培根，怎样反馈？

状态：**场景分析；不作个体医学判断**

- **口述**：先查真实菜谱及必要配料、过敏/有效避开和补买；再读该用户适用指导。若只是少选信号，不能自动变成禁食；若没有可行配方或存在硬冲突，明确说明对应缺口。
- **实现/参数**：不得凭一个食材编造新菜，也不能说某菜能降压；可由用户选择补买或补充条件，不能偷偷改变库存。
- **为什么/比较**：场景的答案来自具体规则/指导与配方，不是背“有病就禁止某食物”的统一模板。
- **难点/追问**：库存不够是食材缺失还是填写克数少要分清：后者当前不作为拒选理由。

依据：[E08](sources-and-coverage.md#e08)、[E11](sources-and-coverage.md#e11)、[E18](sources-and-coverage.md#e18)。

<a id="q040"></a>
### Q040 · 模型写“吃某道菜降血压”，程序怎么拦？

状态：**本地研究业务采用受控理由**

- **口述**：当前本地研究选菜不发布模型自由健康summary/reason，而是按所选真实配方的指导绑定生成aiReason和覆盖说明；没有匹配就用保留健康判断的文本。
- **实现/参数**：这条程序路径比要求模型“别乱说”更可控；独立研究问答仍有自由claim，ID合法不能自动证明其语义正确。
- **为什么/比较**：真实错引用促成职责收缩；不能据此声称所有一般聊天或非研究模式都已自动做完整医学蕴含检测。
- **难点/追问**：追问代码时指出publish中的proof/guidanceReason分支；不要只说“正则检测降压词”就保证无幻觉。

依据：[E08](sources-and-coverage.md#e08)、[E09](sources-and-coverage.md#e09)、[E13](sources-and-coverage.md#e13)。

<a id="q041"></a>
### Q041 · 疾病分型不明确，多轮怎么补？

状态：**局部规则补问已实现**

- **口述**：只有对应指导需要某个条件时才问，保存明确回答，不把“糖尿病”自动当2型，也不把“不清楚”改成正常。非关键缺项不全局阻断本餐。
- **实现/参数**：已有成人、血脂分型、肾功能、训练等条件标签；短回答结合上一轮明确提问键解释，取消/删病会撤销所属建议。
- **为什么/比较**：有明确跟进标签回归，尚非任意自然语言临床问诊，更没有自动诊断。
- **难点/追问**：检查用户已填信息、否定和迟到响应，避免反复追问或旧疾病结果复活。

依据：[E11](sources-and-coverage.md#e11)、[E08](sources-and-coverage.md#e08)。

<a id="q042"></a>
### Q042 · 模型调用同步还是异步，高并发怎样处理？

状态：**当前异步I/O；非后台任务队列**

- **口述**：HTTP里使用async/await等待供应商返回，业务仍是一轮请求，不等于后台异步任务系统。应用可用NDJSON发进度，模型本身stream=false。
- **实现/参数**：进程内聊天/选菜占位上限4；真实账户通过PG认领/限额，防多实例重复请求；本地Embedding互斥CPU编码。
- **为什么/比较**：能解释当前控制机制，不能把构造回归说成日活十万并发压测；排队、工作池与分布式任务恢复属于扩展。
- **难点/追问**：异步不让CPU密集编码自动变快，Node事件循环与Python推理职责分离。

依据：[E05](sources-and-coverage.md#e05)、[E08](sources-and-coverage.md#e08)、[E10](sources-and-coverage.md#e10)。

<a id="q043"></a>
### Q043 · 模型超时或429怎么办？

状态：**当前明确失败，自动重试0**

- **口述**：区分认证、余额、限流、供应商异常、取消和超时，返回可理解状态；当前禁止自动重发或跨模型兜底，防隐性费用与行为改变。
- **实现/参数**：业务路由总预算17秒、研究生成60秒、Embedding适配180秒，范围不同；取消尽力传播，不能承诺供应商零消耗。
- **为什么/比较**：退避/抖动/熔断是可设计机制，不是本项目已经采用；付费/有副作用请求不能照抄通用重试模板。
- **难点/追问**：超时后结果未知不等于没执行；账本保留已认领/已预留，后续用户主动新操作须按契约处理。

依据：[E09](sources-and-coverage.md#e09)、[E10](sources-and-coverage.md#e10)。

<a id="q044"></a>
### Q044 · 一次推荐多少Token，怎样降本？

状态：**有单例回执，无总体均值**

- **口述**：2026-11-05第5次真实样例为8232输入、184输出、合计8416 token；这只是该输入和目录下的一次调用，不能当所有推荐的固定开销。
- **实现/参数**：业务输入估算上限24000、输出2400；只带实际候选关联指导，分页复用15分钟结果，用户主动搭配/重推/换菜才调用。
- **为什么/比较**：5次调用费用估算上界0.070274元是当时价格与usage计算，不是当前报价或账单；未做普遍降本百分比A/B。
- **难点/追问**：缩短上下文不能删除过敏、人群限定或真实做法；缓存省时要说明命中条件及版本。

依据：[E07](sources-and-coverage.md#e07)、[E13](sources-and-coverage.md#e13)。

<a id="q045"></a>
### Q045 · Memory怎么做，多轮怎样记忌口？

状态：**档案/接受记录已实现；无长期向量记忆**

- **口述**：过敏、忌口和按疾病/目标接受的建议属于结构化账户状态，不仅放在聊天历史中。完整聊天页内内存；删病撤销对应建议与接受记录。
- **实现/参数**：保存建议与本餐使用指导分开，服务端以当前档案为准；公共知识库不存个人查询向量或推荐正文。
- **为什么/比较**：这不是自动总结画像的Memory Agent，也没有长期记忆向量召回实验。
- **难点/追问**：摘要可以辅助语言连续性，但不能覆盖原始限制、用户取消或账户归属。

依据：[E10](sources-and-coverage.md#e10)、[E11](sources-and-coverage.md#e11)。

### Q046 · 怎样证明效果，用哪些指标？

状态：**已有研究指标与少量业务样例**

- **口述**：分层报告解析保真、检索覆盖/排序、上下文偏题与限定、菜谱可行性/理由、延迟/成本。硬限制违规、伪造ID、撤回复活单独判失败，不能由均分抵消。
- **实现/参数**：工具已有Recall@10、MRR、二值nDCG及闭包/状态检查；业务要看实际注入和最终整餐，不只看前10候选。
- **为什么/比较**：当前有调试回归、真实PG及少量真实生成；独立gold、专业审核、用户效果尚未完成。
- **难点/追问**：回答“准确率多少”先问清分母和任务；用期望事实覆盖率不能代替临床正确率。

依据：[E12](sources-and-coverage.md#e12)、[E13](sources-and-coverage.md#e13)、[E14](sources-and-coverage.md#e14)。

### Q047 · 27题怎么选，怎样防自己考自己？

### Q048 · 了解Ragas吗，为什么没直接用它？

状态：**了解框架；当前未集成**

- **口述**：Ragas可辅助做context相关性、faithfulness等评估，但指标定义和评委模型仍需验证。项目最先已有确定性的ID、条件、撤回和整餐规则检查。

- **难点/追问**：评委与生成模型可能相关犯错；需要人工抽检、争议记录和规则交叉检查。

### Q049 · 重新设计时，Rerank放哪里？

状态：**候选方案，尚未接入**

- **口述**：先认证/路由与必要适用性检查，再多路召回、统一fact、去重/融合，对小池做query—fact/evidence精排，最后补完整支持/限定并选择预算内上下文。
- **实现/参数**：明确不适用或无权限的项不能靠精排高分复活；不能把例外证据当普通候选挤掉。
- **为什么/比较**：对照无rerank、有rerank但不改其他变量；记录最终上下文和菜品任务，而非只看重排分。
- **难点/追问**：如果一段证据关联多事实，应给重排器足够的对象和条件上下文，不能只重排一个孤立表号。

### Q050 · 最大踩坑怎么讲，怎么定位和修复？

状态：**真实案例可选**

- **口述**：用一次可复现问题讲清触发、错误后果、日志/回执、代码分支、修复和复验。例如普通豆腐菜已合格，模型却凭缺油量与减脂判断拒选。

- **为什么/比较**：保留第2次真实失败、第3次普通菜返回及后续完整样例；不把修改后的回归伪称旧调用已通过。
- **难点/追问**：另一个强案例是RAG-005唯一正文命中绕过导航核验，绿色测试没覆盖分支，管理端复现后补builder测试。

依据：[E13](sources-and-coverage.md#e13)、[E15](sources-and-coverage.md#e15)。

### Q051 · 为什么加向量后反而不如A1？

状态：**真实小样本现象**

- **口述**：旧题术语直接且参与过调试，A1的实体/条件规则与题分布很贴合；dense可能召回同主题但对象不对的证据，融合还会引入噪声。
- **实现/参数**：同27题A1 Recall/MRR均1；Qwen hybrid MRR约0.9375，BGE约0.90625，不能只挑向量成功样本。
- **为什么/比较**：结论是当前没证明增益，不是向量天然无用。先检查题分布、表示、条件过滤、候选映射，再决定是否增加复杂度。
- **难点/追问**：保留简单基线体现工程判断，不必为简历强行让复杂方案获胜。

依据：[E06](sources-and-coverage.md#e06)、[E12](sources-and-coverage.md#e12)、[E14](sources-and-coverage.md#e14)。

### Q055 · 冰箱照片如何接入，CV与RAG什么关系？

状态：**食材图片识别入口已有；非完整视觉RAG**

- **口述**：先认证与费用认领、限制图片格式/大小和固定提供商，识别只生成食材候选；用户确认并做受控实体匹配后，仍走原配方资格与RAG指导。
- **实现/参数**：当前已有照片识别/取消相关工程，照片不进入公共知识库；不能从照片确定过敏、隐藏调料或个人摄入克数。
- **为什么/比较**：没有“识别对了就营养计算对了”的证据；多模态质量要分别看食材命名、形态和下游菜品影响。
- **难点/追问**：清Key、换会话、取消与迟到识别结果不能重新上传或覆盖新草稿。

依据：[E16](sources-and-coverage.md#e16)、[E11](sources-and-coverage.md#e11)。

### Q056 · 加入视频或音频指南，需要改变什么？

状态：**设计，未接入**

- **难点/追问**：一句字幕脱离上下文可能反转结论；不要靠模型补听不清的数字并直接发布事实。
