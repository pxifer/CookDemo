# 基础 RAG 技术选型与跑通计划

日期：2026-11-04（Asia/Shanghai）。本文件整理用户确认的计划，并记录本轮执行范围；各阶段是否已经完成，以实际运行报告为准。

## 目标与入口

建立可验证链路：**问题 → 查询向量 → 检索证据 → 组装上下文 → DeepSeek 生成 → 引用与条件复核**。

首版以本地命令行证据问答交付，聚焦检索、增强、生成和向量存储。运行代码留在后端，设计与运行说明在本目录。本阶段不将研究问答接成正式疾病推荐或临床结论，不扩展前端、长期记忆、自主 Agent 和全目录健康选菜。

生成端按用户选择复用 DeepSeek API；Embedding、事实存储和检索在本机运行。已有普通推荐、账户、API、正式数据和云端入口不随研究链路自动改变。

## 1. 技术对比与初选

| 环节 | 对比方案 | 首版选择或实验方向 |
| --- | --- | --- |
| 向量存储 | PG/pgvector、Qdrant、Chroma、Milvus | 复用 PG/pgvector；当前小库使用精确余弦，不先增加第二套存储同步与恢复链路 |
| Embedding | Qwen3-Embedding-0.6B、BGE-M3、BGE-small-zh-v1.5 | Qwen 0.6B 与 BGE-M3 主要对照；CPU 延迟不合适时验证轻量备选；模型分别建索引，不混查 |
| 检索 | 已有 A1、纯向量、A1＋向量 | 保留 A1 基线，对比混合召回与 RRF |
| 增强 | 直接拼接、条件化证据包、重排 | 先做条件化证据包；重排不是跑通前提，可另做有开关的对照 |
| 生成 | DeepSeek API、本机生成 | 复用现有 DeepSeek 请求能力，新增证据问答适配；每次最多一次生成，无自动重试 |
| 编排 | 普通 TypeScript 函数、LangChain/LlamaIndex | 使用普通函数与明确接口，复用校验、调用账本和撤回逻辑 |

初选理由及官方来源见[技术决策](technology-decisions.md)。本机已核对约 32 GB 内存、i5-13500H 与 Intel 集成显卡，没有依据宣称 GPU 性能。模型取舍依据本地质量、CPU 延迟与内存观测，不按排行榜预定胜者。

## 2. 数据与索引

1. 第一版复用已有 98 个证据片段及关联事实，不扩库，不改写原始知识包。保留原文、出处、页码、条件和版本；模型 token 超长必须明确拒绝，不能静默截断例外或限定条件。
2. 新增独立的研究向量索引 manifest 与证据向量表，关联知识包和 evidence ID。现有菜谱变体向量表不能存健康证据。
3. manifest 锁定知识包 hash、模型 ID、权重 revision、维度、pooling、归一化、query/document 指令、文本 hash、切片/表示版本和运行库版本。
4. 完整生成并校验向量后才原子发布可用索引。不同模型、revision、维度或指令不混查；重新编码生成新索引，而不覆盖旧索引。
5. 向量是独立派生资产，不修改冻结知识包中的 `embeddingBuilt:false`，不修改既有冻结 SQL 或生产迁移。

## 3. 检索、增强与生成

现有 A1 返回 fact，向量命中 evidence。先经事实—证据关联将 dense 命中转换为 fact 排名，再与 A1 在同一层做 RRF；不能直接混排不同层级的 ID。

```text
A1 → fact 排名 ──────────────────┐
                               ├→ fact 层融合
向量 → evidence → 关联 fact 排名 ┘
    → 补齐支持/限定证据、适用条件与冲突
    → 预算内上下文
    → DeepSeek JSON 生成
    → 引用、终态及撤回状态复核
```

- 查询只使用逐题明确给出的条件，未知保持未知，不能默认成人、正常肾功能、透析状态或营养计划。
- 先核对疾病/食品形态歧义及适用性；必要条件未知与证据缺失分别表达。多疾病组合不能机械取最严或让益处抵消限制。
- 上下文包含所选事实、原始证据、出处、适用条件和缺口；补齐必需支持与限定证据。预算不足时减少事实数量，不截断证据闭包。
- 输出包含回答、逐项 fact/evidence 引用、条件、待补信息和明确状态。程序只允许引用本请求证据，生成前后复查来源、证据和索引撤回状态。
- 引用 ID 合法只说明可定位；结论是否被证据支持，仍需人工复核真实样本，不由生成模型为自己签字。

终态约定：正常研究回答 `answered`；歧义、必要条件未知或未核验组合 `needs_confirmation`；无相关/必需证据、必需来源撤回 `insufficient_evidence`；模型超时、非法引用、协议错误或索引身份不匹配 `unavailable`。所有结果保持 `executionAllowed:false`、`clinicalRelease:null`。

## 4. 执行阶段

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| ① 基线与选型 | 核对依赖、模型环境、PG/vector，保存比较矩阵与决策 | 当前能力、初选和未测项清楚；先修复 `test:cloudbase` 命令名遗留误改 |
| ② 真实向量建库 | 建本机 Embedding 适配器、编码现有证据、写研究库 | 完整入库，校验身份及维数，新进程回读一致 |
| ③ 检索对照 | 实现 dense/hybrid、事实关联、条件及撤回复核 | 同题集复现 A1、dense、hybrid，报告统一 fact 层指标 |
| ④ 增强与生成 | 证据上下文、DeepSeek 问答、输出校验 | 回答可追溯，正确表达缺条件、冲突与证据不足 |
| ⑤ 验收与定型 | 少量真实端到端样本、失败分析、资源与质量指标 | 可重复命令、索引 manifest、比较报告及最终选型理由 |

目标入口为 `rag:index`、`rag:query`、`rag:evaluate`、`rag:smoke`。本机 Embedding 适配器只绑定回环地址，模型加载一次后复用；Node 负责业务编排，Python 负责本地推理。

## 5. 实验与验收

相同语料、问题和标注下比较 A1、纯向量及混合召回；统一 fact 层统计 Recall@K、MRR/nDCG，另测必需证据完整率。记录冷启动、预热 P50/P95、内存、建库耗时与索引体积。先满足条件处理和必需证据要求，再权衡质量、CPU 延迟与维护成本。

用例覆盖正常命中、别名、否定、无证据、缺分型、缺条件、跨主题冲突、来源撤回、向量缺失、索引身份不匹配、非法引用、空白/截断/超时及预算耗尽。现有 50 题继续作编辑回归；[新增构造验收集](../../datasets/evaluation/rag-acceptance-v1.json)显式区分开发/验收，不能借旧统一 context 冒充真实输入，也不声称独立临床评价。

“基础 RAG 跑通”必须同时有：真实 document/query 向量、PG 持久化、真实召回、实际注入上下文、真实 DeepSeek 回答及引用复核。Mock 只验证接口和失败分支，不计为真实端到端通过。
