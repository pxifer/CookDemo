# RAG 全链路实现与参数核对：切块、检索、增强及生成

核对日期：2026-11-06；测量代码基线`187ba823ebd99869ac88cb64748ac196133919d8`，已随RAG-005集成；RAG-006纳入main `7ae73569dad8478c5b05bf63b65cf26098f3f8c5`管理结论，运行/数据代码保持一致。本文回答“具体怎么做、参数是多少、为什么、比较过吗”，补充[技术原理说明](rag-technology-explained.md)。本次只核对、离线测量和补文档，不更改推荐或知识/索引，不发起Embedding模型推理、生成API或部署。

口径：**业务**＝本地疾病/目标指导和实际菜谱选择；**研究**＝独立证据问答及A1/dense/hybrid；**候选**＝清洗/表格/OCR派生资料。当前业务选菜没有调用dense/hybrid，新清洗块尚未接入旧索引。参数表中的“工程初值”表示解释其作用和取舍，不冒充历史上已做过选型实验；有回归不等于做过参数消融。

## 1. 切块的实际实现：没有配置512-token滑窗

### 1.1 当前到底怎样切

1. 冻结v2的98条证据由两代构建脚本整理，标记`proposition-v1`。脚本事先写明来源、页/章节、起始原文、可选结束原文及整理摘要，再从规范化文本中摘取相应范围。
2. 没有结束锚点时，只摘取起始字符串本身；有结束锚点时，从起点取到随后第一个结束锚点。PDF操作限定在指定物理页，不能自动跨页补齐；视觉证据是指定图像区域的目视短摘。旧构建器用`find`选锚点，并不是通用语义边界识别器，旧导航误引正是需要修正的真实缺陷。
3. 所谓“命题级”是整理意图和版本标签，**不是已经实现自动命题抽取或经过比较选出的语义切块算法**。内容由脚本明确整理，不是LLM自动抽取整库事实。
4. 没有统一`chunk_size`、目标token长度、最小语义长度或滑窗`overlap`。Schema仅要求`originalSpan`非空，没有切块长度上限；后续Embedding接口有输入保护限制，两者不能混称。
5. 没有滑窗重叠参数不表示原文区间绝不重叠：在可比较的同源/同页/同规范化偏移中，实测有1对重叠（`dm-carbs`与`dm-low-gi`）。视觉引用不能靠字符偏移计算重叠。
6. 实际向量化的是`retrievalText`。继承v1的53条为`章节 + 空格 + 摘要 + 空格 + 原文`，v2新增45条为`摘要 + 空格 + 原文`。没有把这两种格式重新统一，也没有验证加章节/摘要一定更好。
7. 新目标包有4条原文短摘，31～53字符，没有`retrievalText`，未建立目标向量。业务通过主题/条件直接读取这些指导，不靠向量找出它们。

代码：`scripts/build-health-knowledge.py:ev`、`scripts/build-health-knowledge-v2.py:ev/evidence_row/visual`、`scripts/build-goal-guidance.py:ev`；长度合约见`datasets/health/knowledge-bundle.schema.json`。

### 1.3 清洗块为什么另算

v3候选按HTML的段落/列表项/表格单元格等DOM块归并，PDF按布局恢复后的正文块与独立表格块组织；块间以换行分隔，并回指原词/节点。它们没有token上限，也不是现有98条向量的重切版本。

实测13来源/479单元得到**3717个结构块**，长度为最小1、P50为26、P95为798、最大4036字符，总计517,990字符。单元格/标题可能很短，整表可能较长；不能把3717块直接全部向量化并声称“切块设计完成”。尚未实现从清洗块自动生成新证据/事实、父子块检索或按需取父段落的完整接入。

本次另对这些结构块离线计token（仍不建向量），得到：

| tokenizer | 最小/P50/P95/最大token | >128 token块数 | >256块数 | >512块数 |
| --- | --- | ---: | ---: | ---: |
| Qwen | 2 / 16 / 606 / 1934 | 449 | 321 | 223 |
| BGE | 3 / 17 / 565 / 935 | 459 | 319 | 204 |

这些计数只能估计若加长度上限会涉及多少原块，**不是已经执行切分或比较检索质量**。大量短块不宜因为“没超限”就单独索引；较长表格也不应只按token位置硬切而丢掉表头/对象关系。

### 1.4 为什么这样做、是否比较过

- 已记录的目标是保留一个声明及其适用人群、否定、例外和单位，方便逐条溯源。脚本指定锚点是小库可落地的整理方式；这解释边界选择，**不能解释成经实验确定64字符或339 token最合适**，它们只是测量结果。
- 没有比较过固定128/256/512 token、语义切块、滑窗重叠0/32/64、命题块/段落块/父子块，也没有测统一加入章节/摘要的消融收益。
- 当前真实缺口包括：部分短摘过短，摘要可能掩盖原文支持不足；表格需具体行列及脚注；跨页和共用人群限定不能靠一次字符串摘取解决。新资料的切块策略仍需要设计和版本接入，不能从模型8192输入上限推导“块应该8192”。

## 2. 清洗、版面及OCR的具体参数

PDF几何值使用原页坐标（通常为point），OCR/扫描网格使用像素；不要把两套数值混用。本组多数为针对现有开发来源的启发式初值，有样例回归和原词守恒核验，**没有系统扫参或独立准确率对照**。

| 参数/方法 | 代码实际值/行为 | 作用及选取依据/对比 |
| --- | --- | --- |
| HTML正文优先级 | `article=4`、`main/role=main=3`、已知正文/摘要class/id=2；同级选文字更多者；无候选保留根并标待核 | 利用网页结构避免全页混入；手工规则，不是经过训练的正文分类分数 |
| HTML保护与删除 | 脚本/样式/template/noscript删除；导航/隐藏区域按角色处理；关键条件/否定、脚注和标题有保护例外 | 减少删掉重要限定；也可能保留噪声。无正文提取器横评 |
| PDF原词提取 | `extract_words(extra_attrs=['size'], use_text_flow=False)`；其余参数沿用锁定pdfplumber版本 | 保留字号/框，用自有几何重排；未对照库内部不同容差 |
| 同行归并 | y差容差`max(3,min(4,字号×0.22))`，只看最近4个候选行 | 容忍混合字体基线差异；工程初值 |
| 同行横向分段 | 词间距大于`max(10,页宽×0.035)`才拆段 | 避免远处两列串成一行；未扫间距阈值 |
| 数字上下标 | 数字字号小于基字母0.8倍，水平邻接小于`max(3,基字号×0.4)`，垂直重叠至少较小高度20% | 修复维生素字母/数字错序；实际失败前后回归，不扩展成所有上下标已解决 |
| 页边范围 | 顶部9%、底部9% | 将重复检测限制在页边，减少误删正文；初值而非最优区间 |
| 重复页边阈值 | 支持页数≥`max(3,总页数×0.55)`；或同奇偶页支持≥`max(3,同奇偶页数×0.8)`；重复文字须<120非空白字符 | 兼容奇偶页页眉和页码；表题/脚注/关键语义继续保护；未比较0.4/0.55/0.7等阈值 |
| 双栏探测 | 至少20词；分界遍历页宽42%～58%；行按y/4归组，左右间隙≥页宽2% | 只检测相对居中的双栏；并非通用任意多栏 |
| 双栏成立条件 | 支持行≥5且≥35%，穿越分界的行<20%；按`支持−2×穿越`选候选 | 排除孤立空隙；现有开发样例支持，未做参数横评 |
| 正文断行连接 | 同栏/同body角色；中文缩进差<45，否则<25；行距<`max(14,min(24,字号×1.05))`；遇句末或新条目不并 | 保守连接，不替换数字/单位/连字符；不是语义段落模型 |
| 有线表 | pdfplumber找到至少2行、首行至少2格 | 先保持物理结构，不批准语义表头；沿用库默认表探测设置 |
| 横线表候选 | 横线长>页宽70%，区域高≥40、含数字词≥15、与已知表重叠≤50% | 排除部分普通下划线/正文；不证明区域一定是营养表 |
| 无竖线列界 | 间隙≥`max(12,表宽×0.025)`；支持≥`max(2,文本行数×0.18)`；空隙带宽≥4，避开表两端各5% | 用重复对齐推列界；列界候选数1～12，已有3表回归，无其他表提取器横评 |
| 无竖线宽列补查 | 宽列>表宽45%才检查零词框穿越带；连续空白≥6，两侧均至少2行 | 修复居中换行标签的漏列；本轮缺陷回归，不是完整列界准确率 |
| 表格序列化 | 每个物理格输出一次，按行列排序，保留跨行/列跨度和词ID | 不使用固定字符切表；不能因格完整就生成数值事实 |
| 表题/单位/脚注范围 | 表上方45、下方35坐标单位取邻近候选 | 避免无限带入附近段落；未做上下文窗口消融 |
| 跨页表候选 | 相邻页、明确续表标记、同表号，归一化列界差<0.01；`headerInherited=false` | 不凭位置自动继承表头，仍需语义审核 |
| 表头边界启发式 | 含数字格数≥`max(2,列数/3)`作为首数据行候选；首数据行上限索引4；对象列按标签词，否则回退首列 | 仅产生表头路径/对象—值—单位候选，不能当已核营养关系 |
| OCR触发 | 非空白文字<40；或文字<250且图片框面积和>页面45%；乱码另标 | 进入待识别/待核队列，不把少字页默认识别成功 |
| OCR引擎/语言 | Windows.Media.Ocr；固定引擎/语言资源hash；英文来源用`en-US`，其他用`zh-Hans-CN` | 复用现有离线资源；没有与其他引擎比较，也不自动检测所有混排语言 |
| PDF渲染 | 144与216dpi两组；长图原尺寸与1.5倍 | 观察分辨率差异，成本低且可复现；未对照更多dpi；一致不等于正确 |
| 长图分片 | 边长≤3000px、重叠180px，步长2820px；覆盖末端；引擎最大边长10000px | 避免超限及截断；180px是保留边界上下文的工程初值，没有重叠量消融 |
| OCR旋转/置信度 | 非零角度不猜回原坐标，扫描网格跳过；词confidence为null | API没提供置信度，不伪造0.9；没有自动旋转纠正已通过的结论 |
| 扫描网格暗像素 | 灰度<145；扩散半径`clamp(round(宽×0.0035),2,8)`；邻近线位置差≤4px归组 | 容忍扫描直线漂移；不是深度表格识别模型，阈值未横评 |
| 扫描网格成立 | 横向覆盖≥60%、纵向≥65%；至少3横线、跨度≥50px；纵线数3～24、横线≤100、横跨度≥图宽35% | 限定有线表候选，保留复杂表漏检；表上80px/下60px取标题和脚注候选 |
| 原词/节点守恒 | 缺失、重复、未知引用均为0；原字符只能保留或带原因删除 | 结构保真门禁是严格约定，不是可放宽的质量平均分 |
| 重复资料/块 | 原件/产物hash及ID核验；检索/上下文按fact/evidence ID去重；没有通用MinHash、SimHash或语义近重复聚类 | 不把多次转载当独立支持；一般重复块治理仍不能称完整完成 |
| 旧引用消歧 | 原件hash、旧规范化/偏移逐字核对；多命中用前后各48个旧文本字符再去空白唯一匹配；导航来源先核验 | 48是局部上下文初值，未扫窗口；唯一正文也不能绕过旧导航隔离，P2修复待复审 |

实现见[正文解析器](../../scripts/lib/document-parser.py)、[表格候选](../../scripts/lib/table-review.py)、[OCR入口](../../scripts/ocr-health-documents.py)与[扫描网格](../../scripts/build-ocr-table-review.py)。

| Document指令 | 两模型均空 | 不把查询前缀同样加在文档上；没有做其他文档模板对照 |
| 表示版本 | `health-evidence-retrieval-text-v1`；身份还含revision、维度、pooling、归一化、query/document指令、运行库 | 同维数不足以互换；本次不改旧表示/索引 |
| 本地推理环境 | Python3.11.9、torch2.7.1+cpu、transformers4.57.1、sentence-transformers5.1.2，CPU常驻进程 | 复用本机资源；不是GPU/ONNX量化后端速度对照 |
| CPU线程 | 启动默认6，允许1～12；互斥编码，两模型顺序加载 | 控制CPU/内存争用；没有线程数或并发吞吐最优实验 |

| 存储数值/距离 | float32，余弦`<=>`；距离排序后按evidence ID稳定破同分 | 可核对的精确距离基线；未测试其他距离对业务质量的收益 |

| 索引发布 | 知识/模型/文本hash绑定，向量条数必须等于证据条数，事务发布，不可变ID | 防半套索引、错版本及重复证据；真实PG有专项，未做大规模压测 |

## 4. 查询、召回、融合和最终上下文选择

| 参数/方法 | 当前实际值/规则 | 选取依据/比较情况 |
| --- | --- | --- |
| 查询边界 | 研究问题非空且≤1000字符；context≤30键、每值≤120字符；必需证据≤100条 | 输入保护，不是推荐效果调参；业务对话有自身Schema，不能把此限制套到所有入口 |
| 查询规范化 | NFKC、小写、受控别名最长重叠跨度优先；别名冲突、分型/鲜干不明需确认 | 减少表面写法差异；没有分词器/实体模型横评 |
| 否定范围 | 研究实体前最多6字符检查明确否定短语 | 局部规则，不是完整否定语义模型；有针对性回归，窗口未扫参 |
| 词面token | 中文连续片段取相邻2字，去固定停用片段；英文/数字连续词保留 | 适配中文无空格的轻量基线；不是BM25，也没有IDF/长度归一化 |
| A1实体得分 | 命中明确对象加8、命中疾病主体加4 | 提高对象针对性；手工权重，有偏题修复回归，未对照4:2/8:4/其他权重 |
| A1词面得分 | 每个命中token加`min(4,token长度)` | 限制单个长别名贡献；不是学习排序，4没有扫参证据 |
| A1内部融合 | 实体排名与词面排名等权`1/(60+r)`相加 | 融合不同量纲的手工分数；没有融合算法横评 |
| A1条数 | 独立查询默认10、允许1～50；研究外层固定请求最多50条fact | 10是单独查询显示口径，50是融合候选口径；不等于最终上下文数 |
| dense条数 | 研究默认最多30条evidence；存储接口允许limit1～1000 | 补语义候选；没有10/20/30/50的召回/延迟消融 |
| dense→fact | 根据支持/限定关系映射；同fact取最早dense evidence名次，不因证据多重复加票 | 统一ID空间并控制重复片段优势；不生成新事实 |
| 外层RRF | `2/(60+r_A1)+1/(60+r_dense)`；缺席通道贡献0，同分按fact ID稳定排序 | 2:1偏重结构化基线是工程初值；60沿用RRF平滑方法；未与分数归一化加权/专用重排做公平对照 |
| RRF参数含义 | 60是平滑常数，越大相邻头部名次差距越缓，不是召回60或top-60 | 原理有依据，具体60和2:1的本项目最优性无依据；不把融合分数当概率 |
| 相似度阈值 | 没有`cosine≥0.7`或“RRF≥某值即可回答”的准入线 | 依据有效性、实体、关系及条件判断，不猜一个未校准阈值；相关性误接纳仍待后续优化 |
| 来源权威/时效加分 | 没有按年份、机构或“置信度0.9”乘排名权重；使用已绑定来源版本/状态及对应关系类型约束 | 来源筛选与排名加分分开，不能说最新版/权威来源一定排第一；无此类权重选型 |
| 研究适用性筛选 | 排除撤回/缺证据/不适用；疾病、食品、成分、工艺按所问对象筛；所问指导必要条件未知先确认；多疾病研究组合不自动视为已评估 | 过滤优先于排名，不允许向量高分绕过；业务按多个主题分别组织指导，不是同一套组合评估 |
| 研究最终top-k | 最多8条可用fact；按融合排序逐条尝试，可能少于8 | 减少噪声并控制输入，8是工程初值；没有4/8/12/16横评 |
| 支持/限定闭包 | 每个选中fact补齐全部support/qualify，evidence去重，required evidence另保留 | 所以8条fact不等于8条证据，也不是“先截8证据再补答案” |
| 研究上下文预算 | 估算6000 token，对组装context JSON计数；该值不是模型完整输入上限，也未单独计系统消息 | 每次加入fact及其证据若超限，回退整条fact；不删限定来塞结论；未扫3000/6000/9000 |
| token估算器 | 汉字2单位、ASCII0.4、其他2，合计向上取整 | 保守的应用估算，不是真实DeepSeek tokenizer；本次测量Embedding token与该估算分开 |
| 查询向量缓存 | 工程评测的进程内MemoProvider按输入/角色缓存，dense与hybrid可复用同query；不是公共库持久存个人查询 | 防评测重复编码；模式耗时不能当独立冷启动速度；实际编码P95另报 |
| 专用重排 | 未启用cross-encoder/bge-reranker、MMR、多样性参数λ、在线HyDE或多query扩写 | 没有相应模型/λ/候选数选值；RRF本身不是语义重排或来源审核 |

代码见[A1](../../backend/src/health-knowledge-retrieval.ts)、[研究检索](../../backend/src/rag/retrieval.ts)、[预算估算](../../shared/context-budget.ts)。[RRF原论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)提供方法依据，其其他数据集结果不构成本项目增益。
