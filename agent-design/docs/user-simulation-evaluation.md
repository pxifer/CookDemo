## 运行方式

使用Node24，在当前仓库根目录：

```powershell
# 以下prepare/export不调用模型；轮次名不可复用覆盖。
node --import tsx scripts/output-evaluation-round.ts prepare <round-id>
node --import tsx scripts/output-evaluation-round.ts run <round-id> fixture 2
# 已有明确调用授权、同一持久预算及本机Key时才显式选择live。
node --import tsx scripts/output-evaluation-round.ts run <round-id> live 8
node --import tsx scripts/output-evaluation-round.ts advance <round-id> u49 <实际父run-id>
node --import tsx scripts/output-evaluation-round.ts run <round-id> live 1
node --import tsx scripts/output-evaluation-round.ts export <round-id>
node --import tsx scripts/output-evaluation-round.ts compare <old-round> <new-round>
```

prepare默认注册60个第一轮，也可在最后参数给明确ID列表；不得按是否命中知识反向筛选。advance只能使用该轮已运行的父回答，来源用户/助手历史逐字绑定，下一轮不会凭空预写助手内容。运行优先已注册的续答，之后按冻结顺序；每个case本轮只尝试一次，失败不自动再跑。需要重测时新建轮次并保留旧失败。

产物位于 `.local-data/evaluation/output-evaluation-20261113-cny5/rounds/<round-id>/`。manifest冻结身份，events追加注册/尝试/实际run记录。代码、知识/映射、目录或输入集变化后拒绝继续混跑，新建轮次；导出历史轮按历史报告，不拿新知识重算旧检索。export以事件数另建快照，不覆盖旧评分材料。

第三批9条实际输出来自`outside-in-20261113-base`冻结版本；后续轮次工具队列优先级和状态元数据已继续改进，因此不能再往该旧轮强行追加。当前持续运行的父服务未重启以保留内存Key，其旧状态接口的maximumRequests仍可能为32；真实子进程按持久的64次阶段策略及同一5元账本限额执行。源码已修复状态元数据，下次正常启动更新；此差异不影响金额账本，也不能当额外预算。

## 评分交付

export只将非fixture实际回答给评委：原话、真实历史、主答/菜品/理由/建议、opaque产品版本、输入输出哈希及原配方核验材料。原始报错代码留诊断，新错误有用户可读说明；旧记录保持原样。标签、开发分、完整知识、Prompt及认证信息不进评分包。

`not-run.json`明确标未运行/尝试失败/构造测试，不作为成功或质量分。配方返回与用户可见详情分开；运行时设置只是可核验条件，不代表用户主动声明。需要界面证据时单独观察，不用JSON代替。

逐维沿用评委judge-product-v0.1；U/N/A及事实核验状态保留，不套75分或强制补齐总分。回件按case_id/run_id/product/input/output hash逐项匹配，标准另建版本才能修改，旧分不迁移至新回答。

## 怎样用分数改进，而不是追分

1. 先由评委记录任务缺口与原句，区分事实错、支持不足、需求未满足、行动欠缺、流程/状态错误和界面缺证据；同一回答可以安全但不实用。
2. 再看对应诊断：输入抽取→条件/对话状态→实际知识版本/撤回→指导/候选→提示/输出约束→终态/展示。先排查库里是否有适用资料、是否真的装配、是否正确取回，再决定扩库还是调参。
3. 每次实验预先写因素和判据。例如“同知识/输入/目录，只改未知槽位处理”测重复追问；“同输入/代码，只换审核后的知识包”测支持覆盖。若合并导致代码也变，明确是组合变更，不声称知识独立增益。
4. 当前业务入口是结构化食材指导，不执行向量RRF或专用重排。没有命中的事实不能靠增加top-k创造；不得拿本轮得分宣传RRF/重排参数更优。只有真实走该检索路径且有独立相关性标签时，才比较召回数、RRF常数、重排TopK等。
5. 对照必须同输入、同目录、同标准，保留模型/Prompt/知识/索引/代码身份及全部失败。compare检查配对条件，未拿到独立评分时scoreDelta为空，不计算虚构提升。多轮后续回答实际依赖不同上轮时，输入不等价，应按完整场景完成度比较，不冒充相同prompt消融。
6. 开发集可以反复调；另用未参与修复的问题族复验泛化，专业临床主张另核验。把每轮未满足项和U的分布与可执行性变化一起报告，不只挑改善的题。
