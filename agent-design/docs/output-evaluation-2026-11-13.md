## 3. 执行顺序与预算

1. 冻结案例/评分规则与公开菜谱快照hash，先运行免费指导及构造供应商，验证评分器会识别坏输出。
2. 本地评测台仅绑定回环；Key由用户界面填写，仅进程内保存。每次真实调用前持久化预算预留，串行执行，无隐式重试；给出原始模型输出、程序终态和提示/证据追踪。
3. 对相同构造输入比较一般模型选择与研究RAG选择，记录差异；预期答案不进提示。保留模型/知识/目录/源码和Prompt指纹。
4. 从真实失败定位：解析/主题理解→知识缺口→适用性→映射→候选→增强→模型→程序复核→展示。先修确定缺陷，再在原失败及相邻反例复测。
5. 只在需要时改变一个因素；不能同时改清洗、top-k、RRF和Prompt后宣称某一项贡献。调过的题归开发/回归，后续由用户另提供未见问题做验收。

本轮以检索相关、回答忠实和任务相关分别检查的思路参考[RAGAS论文](https://aclanthology.org/2024.eacl-demo.16/)和[指标文档](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)。未安装框架或增加模型评委调用；结构检查不能冒充faithfulness，更不能冒充临床有效率。

本轮5元是全部阶段共用累计上限，不是每阶段5元。优先小批真实输入/输出，不为花完预算重复调用；当前最高价按输入2元/百万tokens、输出8元/百万tokens预留，来源[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。不启用搜索/Fetch付费工具，不自动部署、训练或换模型。
