核对日期：2026-11-06。本文按技术问题分类，不把流程节点当技术名；区分工具、算法、数学方法和工程约束。每项说明具体机制、解决的问题及对比边界。

范围标记：**业务**＝本地疾病/目标指导与真实菜谱选择；**研究**＝独立证据问答/向量混合检索；**离线候选**＝资料治理产物，尚未替换冻结知识及旧索引。三者不等于线上已发布。

### RRF到底解决什么，为什么选它

它解决的是**来自不同检索器的分数不可直接比较**：例如A1的实体/词面规则分与dense的余弦距离，量纲、方向、范围都不同。RRF只使用各通道的名次，把两份“排序意见”合成一份。

一般形式：`score(f)=Σ w_i/(c+rank_i(f))`；本项目外层`c=60`、`w_A1=2`、`w_dense=1`，名次从1开始，不在某榜单中则该项为0。

以下是计算示例，不是实际问题的效果数据：

| 事实 | A1名次 | dense名次 | 融合分数 | 结果含义 |
| --- | ---: | ---: | ---: | --- |
| A | 1 | 20 | `2/61+1/80≈0.04529` | 词面第一，但语义通道支持较弱 |
| B | 3 | 1 | `2/63+1/61≈0.04814` | 两个通道都靠前，融合后超过A |
| C | 未召回 | 2 | `1/62≈0.01613` | 仍可补入，但没有A1通道加分 |

`c`越大，头部相邻名次差距越缓；越小越强调榜首。原论文使用60并在其测试集与Condorcet/CombMNZ等比较；那是论文结论，不能搬成我们的业务提升。[RRF原论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)

相对直接分数加权，RRF免去当前两套异质分数的校准；相对学习排序，不需要先训练排序器；相对cross-encoder，不需逐对运行额外模型。这些是方法/工程取舍，不是本项目已测的质量胜出。代价是丢失原始分差、对候选数/通道权重敏感；两通道都偏题时仍可能把偏题事实推高。

**RRF不是语义重排器，更不是事实审核器。** 它不能判断导航问句是否支撑结论，不能识别所有缺失限定或保证菜谱适用；这些依赖来源角色、关系/适用条件检查及输出验证。专用reranker尚未接入。

| 受限动作空间/目录ID选择 | 模型只能在提供的真实catalog中选ID；过敏/忌口优先，少选不等于硬禁，无健康依据保留判断；不计算无依据营养/疗效 | 修复普通菜无依据拒选；区别于让模型自由编整套菜谱。已有少量真实调用及回归，无大规模满意度对照 |
| DeepSeek JSON模式＋应用运行时校验 | `response_format:json_object`帮助结构化输出；应用再检查结构、字段、长度、ID、类别/数量、单菜及整套条件 | JSON合法不等于字段合约或事实正确；不是已使用供应商JSON Schema约束解码。[DeepSeek JSON文档](https://api-docs.deepseek.com/guides/json_mode/) |
| 程序绑定证据与确定性健康理由 | 业务模型只交菜ID/本餐理由，程序依据实际配料与主做法生成指导绑定，不信模型自由填写引用；研究回答校验ID属于本次上下文及限定齐全 | 解决真实调用中错填证据ID；程序能验证绑定，不自动证明任意自由文本都被证据蕴含 |
| 状态机与拒绝不完整输出 | 研究区分answered/needs_confirmation/insufficient_evidence/unavailable；业务区分技术失败、部分候选比较和确实无菜。检查finish_reason=stop、非空内容与usage回执 | 防止截断JSON被当成功、模型拒选被当全库无菜；无自动重试/静默降级，不靠多次碰运气刷通过 |
| 确定函数编排与适配器接口 | TypeScript依次调用检索、组装、生成、检查；Python只负责Embedding。EmbeddingProvider/Store/Generator可替换，业务限制仍在原推荐程序 | 没有ReAct循环、自主工具规划、多Agent框架或LangChain/LlamaIndex；做过职责/依赖方案取舍，未做框架性能测试 |

## 6. 一致性、费用、记忆与质量方法

| 技术/方法 | 原理、项目实际用法与解决的问题 | 替代方案及真实比较 |
| --- | --- | --- |
| 撤回水位与生成前后复查（TOCTOU防护） | 排名时、生成前后、返回前核验资料/配方/档案身份和撤回状态；防止查时有效、生成时已撤销还返回 | 已有变化/撤回回归；不能把普通hash校验当撤回传播已完成 |
| 调用认领与预算预留 | 业务复用PG原子认领/限额，研究真实生成用专用持久化预留账本；请求前预留，回执后记录，失败不重置预算、不自动重试 | 控制重复调用/超支；两种账本范围不同，不把本地研究账本称为跨实例一致性。旧授权已结项 |
| 加密绑定游标与分页复用 | AES-256-GCM封装结果计划，绑定UID、输入/档案、Key和目录等身份及有效期；翻页读取既有选择、不重新调用模型 | 避免跨用户/旧输入结果混用和翻页额外费用；不是把推荐历史嵌入公共向量库 |
| 当前个人档案与接受记录 | 按当前账户/疾病或目标保存及撤销偏好；完整聊天仅页内内存，个人查询不入公共向量库 | 当前没有长期向量记忆、自动画像总结或Memory Agent；不能因memory设计目录存在就宣称实现 |
| 版本化回归与消融对照 | 分开保存A1、dense、hybrid及模型/知识/提示版本；保留失败，不用新代码覆盖旧调用结论 | 做过两Embedding及检索模式工程对照；尚无足够独立样本支持增益结论，参数消融并不完整 |
| 检索指标与业务硬失败 | Recall@K看相关项找全程度，MRR看首个相关项名次；工具已有二值nDCG，分级相关性gold仍待补。过敏/伪造ID/错用条件等单列失败，不由平均分抵消 | 研究调试题已有指标记录；独立gold及广覆盖业务质量未完成，不能把通过率当医学正确率 |
| 曝光登记、gold隔离和人工审核 | 已用于调试的题继续标回归；gold只送评分器，不送检索/生成；记录标注角色、争议和裁定，代理不冒充独立人审 | 用户本轮决定：独立评测集及评测流程放上线后结合输出/预期完善；现有基本回归与已知错误修复继续执行 |
