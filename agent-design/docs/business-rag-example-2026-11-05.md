时序说明：5次真实调用完成后，用户追加“填写食材忽略用量”的要求，已按 D19-13 实现并做零收费回归，见[用量策略验收](../../docs/releases/ACCEPTANCE-quantity-policy-2026-11-05.md)。以下500g输入和提示词是当时的真实记录，保留原样；不能当成新策略的付费生成验收。代理本轮调用已结项，未使用剩余预算继续测试。

## 1. 真实输入与本轮结果

用户在健康对话输入：**“我是成年人，我有高脂血症，我想减脂”**；本餐为白菜500g、豆腐500g，1人、不补买、不限口味、调料不限库存，按当前自动搭配生成。第5次调用没有设置过敏、忌口或接受记录，不能声称这一单验证了所有过敏场景；相关硬限制另有本地回归。

实际账户档案规范化为 `conditions:[成人高脂血症]`、`goals:[减脂]`、`notes:我是成年人`。疾病与目标分别处理，不诊断肥胖，不计算全天能量/蛋白需求。对话阶段由知识库产生食材建议，不调用生成模型；点击“请AI搭配”才进入以下真实生成。

最终页面返回 **白菜豆腐汤、炝拌白菜心、小葱拌豆腐**。第一道关联现有食材/做法依据；后两道没有当前映射支持，仍可按本餐条件选择，并明确“当前资料未形成这道菜的健康适宜性结论”。

## 2. 知识库里具体有什么、如何保存

| 层 | 当前实际内容 | 位置与用途 |
| --- | --- | --- |
| 来源/证据 | v2有11个来源、98条证据；新目标资料另有4条原文支持/限定证据 | 来源版本、URL、原件hash、原文、页/章节/区域定位、span hash分别保存 |
| 事实 | v2有260条关系，其中124条直接食物指导；新目标另有5条定性事实 | 疾病/目标、对象、方向、条件及支持/限定证据分开，不把原文全文当成事实 |
| 映射 | 稳定知识对象ID → 明确的目录食材成员或受控主做法规则 | [映射文件](../../datasets/health/food-guidance-mappings-v1.json)，不把普通奶当低脂奶、一般鸡肉当去皮禽肉 |
| 研究PG | 原研究事实/证据表；新增不可变 `guidance_assets` 的JSONB目标与映射快照 | 启动导入、hash/载荷回读核验，然后使用内存快照检索；取指导和返回前核验最新撤回 |
| 旧向量索引 | `evidence_embeddings`、`vector_index_manifests` 中两套各98条证据向量 | 保留Qwen/BGE研究索引；**本例业务链没有调用dense/hybrid，新增目标也未建向量** |
| 个人数据 | 当前档案与Key按既有逻辑加密，预览账户仅在本进程内 | 不进入公共知识库、不生成个人查询向量；本轮请求诊断仅在Git忽略的本地目录 |

原始资料清洗尚不完善。旧证据中存在按页取文、规范化短摘和项目目视转录，本例高脂血症证据的定位类型为 `html_visual`；新体重资料是PDF第10页短摘。不能把hash与定位核对称为通用正文识别、自动OCR或专业审核完成。

## 3. 从输入检索了什么

本例直接命中疾病和目标下的 **18条指导、7条证据**：15条高脂血症指导、3条减脂指导。它们不是按向量距离取出的top-18。

| 指导对象 | 方向 | 当前处理 |
| --- | --- | --- |
| 全谷物、杂豆、去皮禽肉、低脂/脱脂奶 | 推荐 | 保留指导；当前目录映射不足，不套用宽泛别名 |
| 新鲜蔬菜、鱼类、瘦肉 | 推荐 | 明确成员可映射，但只有与本餐候选配方相符的指导进入生成上下文 |
| 动物内脏、肝脏 | 少选 | 本例血脂分型 `lipidPattern` 未知，相关判断待确认；不阻断无内脏的菜 |
| 含糖糕点、糖果、含糖饮料、含酒精饮品 | 少选 | 当前映射不足，不能凭相似词假称已执行排除 |
| 高脂血症下的煎炸 / 蒸煮 | 少选 / 推荐 | 核对真实主做法，不混用备选方法 |
| 减脂下的白糖、煎炸 / 蒸煮 | 少选、少选 / 推荐 | 白糖提示是项目解释，不认定整菜高糖；工艺不等于能量达标 |

18条中10条在当前目录有可用映射；其余8个对象仍是缺口。取指导时保留 `applicable / needs_confirmation / not_applicable / withdrawn`，相似或未命中均不能证明安全。

## 4. 实际菜品怎样筛选、排序，top-k是多少

先复用原推荐程序检查过敏忌口、有效接受的避开、食材复用、补买、可比数量、调料设置及整套累计。只有合格目录项才供模型选择；健康“推荐/少选”不抵消硬限制。当前资料中适用的研究avoid仍先排除对应配方。

合格候选排序依次考虑：已接受少选项、研究少选匹配数、已接受推荐项、研究推荐匹配数、现有食材复用和家常属性；保留一套可行基线，再补充候选。一般最多提供48个父菜谱，并受估算24000 token输入预算限制。存在基线与轮次排序因素，因此下表的 `c1` 等仅是**本次请求内别名**，不是全库固定排名或稳定recipeId。

本次实际仅有6个候选，全部提供，`scope.complete=true`；模型按本餐数量选择3道。这例没有向量分数、专用重排模型或相似度阈值，不能虚构“召回50→重排10→top3”的过程。

| 本次ID | 菜品 | 当前配方绑定的指导 |
| --- | --- | --- |
| c1 | 炝拌白菜心 | 无；当前显式蔬菜成员映射未覆盖白菜心，不能靠模型补造绑定 |
| c2 | 豆腐烧小白菜 | 蔬菜推荐、两项煎炸少选 |
| c3 | 白菜豆腐汤 | 蔬菜推荐、高脂血症蒸煮推荐、减脂蒸煮推荐 |
| c4 | 乾隆白菜 | 蔬菜推荐、添加白糖少选 |
| c5 | 葱烧豆腐 | 两项煎炸少选 |
| c6 | 小葱拌豆腐 | 无；该实际做法未被当前受控规则认定为相应主做法指导 |

## 5. 增强后实际给了模型什么

从18条指导中保留上述候选实际绑定的 **6条指导**，支持原文去重为 **3条证据**，没有丢弃任何被选指导的必需支持/限定证据：

- 高脂血症食养指南：蔬菜/膳食纤维相关原文，定位到第6页相应区域。
- 同指南：少油蒸煮、减少油炸油煎的原文，定位到第6页烹调区域。
- 体重管理指导原则：食物选择与烹调方式原文，定位到PDF第10页。

实际user消息是JSON，包含 `task/scope/mode/count/categories/user/catalog/locked/previous/evidenceGuidance`。其中catalog每项保留本次ID、名称、类别、口味、完整配料及主做法/备选做法、复用和补买信息；每条指导保留对象、方向、人群条件、fact/evidence ID、原文及出处hash。不是只塞进一句“高脂血症少吃油”。

完整系统提示见[最终系统提示](../../artifacts/acceptance/business-rag-example-2026-11-05/final-system-prompt.txt)。便于阅读的[增强JSON导出](../../artifacts/acceptance/business-rag-example-2026-11-05/final-enhancement-redacted.json)替换了账户档案细节，未删减的请求内容与供应商原文保留在本机 `.local-data/rag-preview/call-5.json`，没有请求头或Key，不进入Git。

系统提示的实际边界包括：

- 只选catalog的实际ID，满足本次数量和荤素汤类别，不编造菜、营养、疗效或烹调反应。
- 过敏、忌口、有效避开、补买和累计库存不可放宽；调料不限库存不代表没有调料。
- 无匹配健康依据仍可按本餐条件选菜，不能给出健康适宜性结论。
- 少选不是硬禁；缺油盐克数不能默认超标，不能凭无来源营养推断拒绝唯一合格候选。
- 模型只提交ID和本餐理由；**引用归属由程序根据实际配方形成**，不采信模型自由填写的引用或自由健康陈述。
- JSON summary最多240字、reason最多100字，最多2400输出token，失败无自动重试。
